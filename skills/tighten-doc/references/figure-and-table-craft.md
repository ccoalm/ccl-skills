# 图与表的起草期契约

`deliverable-doc-genre-skeletons.md` §4 定「哪个族画哪几张图」、§5 定「画了的图怎么验收」。
本文件补的是**图与表画成什么样才合规**，以及**哪些判据能机械跑**。三者不重述：族与候选看 §4，
验收面看 §5，本文件只管形态与可判定性。

## §1 判据分三档，混档就会被反驳

落任何一条图/表规则前先归档，档位决定它能不能被"你这数字哪来的"问倒：

| 档 | 含义 | 用法 |
|---|---|---|
| `[外]` | 有权威一手源 | 可声称行业基线，引用时点名来源 |
| `[工]` | 工程约定 + 观测到的失败类 | 能防返工，**不得声称是业界最佳实践** |
| `[禁]` | 查证后确认无可靠来源 | 谁拿数字立规则，先要出处 |

**`[禁]` 档（已核，勿再立）**：加粗/高亮密度；每 N 字一图的图表密度（唯一数字是学术期刊的
**印刷页数配额**，成因是版面成本不是可读性）；"一行不超过 40 汉字"引 WCAG（该条的 CJK 40 是从
拉丁文 80 折半推导，且原文要求是「提供**机制**让用户改」不是「正文必须排这么宽」）；"句子不超过
25 词"；"留白提升理解约 20%"（错误引用链）。

**同体裁实测分布 ≠ 规范阈值**：可以说"本稿在同体裁公开样本分布的哪个位置"，不能由此推出"写得好"。
分布定位的合法输出是描述不是裁决——这条与 `tighten-doc` SKILL.md「外部基线」条同源，按那条执行。

## §2 选哪种图：按主张的形态

`[外]` 依据 UML 2.5 图种语义。**判别式是「有没有显式事件触发」**：

- 有事件触发，且关心对象的生命周期与合法/非法迁移 → **状态机图**
- 有跨参与者的消息往返，且顺序本身就是主张 → **时序图**
- 无事件触发，随动作完成自动流转（含判定分支）→ **流程图 / 活动图**
- 主张是「谁包含谁、谁依赖谁」的静态结构 → **架构图**（先定抽象层）

反向同样是规则：没有时间顺序不画时序图，没有非法迁移不画状态机。把静态包含关系画成流程图，
箭头承载不了「包含」，读者必须回正文才懂——这类图必然过不了 §5 的独立性验收。

**架构/方案族的视图三分** `[外]`：C4（Context/Container/Component、Dynamic、Deployment）、
arc42（§5 Building Block / §6 Runtime / §7 Deployment）、4+1（Logical+Development / Process /
Physical）三个来源各自独立、收敛到同一组三分：**静态结构 / 运行时行为 / 部署拓扑**。
缺哪一类视图就是缺一类受众。完整性判据用 §5 的关切覆盖（每个关切至少被一个视图回答）。

## §3 画了就必须满足的硬约束 `[外]`

通用（C4 记法与其 21 项评审清单）：

- 标题说清**图的类型与范围**（不是「架构图」，是「XX 系统的容器图」）
- **有图例**，解释形状、颜色、边框、线型、箭头
- **每条线单向且标签具体**——禁 `Uses`/`调用`/`依赖` 这类单词，要说清意图与方向
- 跨进程连线标出协议/技术；每个元素标类型 + 一句职责
- **配色一致性跨图成立**（原文：consistent within and across diagrams），且要能过黑白打印与色觉障碍

按图种补充：

- **时序图**：lifeline 是参与者不是函数；同步/异步用不同箭头并进图例；**错误分支要么画、要么在图注
  声明本图只画 happy path**——不声明即隐瞒
- **状态机**：状态穷尽（含初态、终态、异常态）；**非法迁移显式**（画禁止边或图注列出不存在的迁移）；
  每条边标**触发事件 + 守卫条件**，缺一即不可验证
- **流程图**：每个判定框**出边覆盖全部取值**；不用它表达静态包含关系

**图注写主张，不写内容** `[工]`：「图 1：系统架构」是废话；「图 1：入口层与 API 路径分离，
AI 能力跨云调用不与主云绑定」才是主张。图注承担 §5 独立性验收的一半。

## §4 调研/报告族的图与表 `[外]`

依据 ICD 203 九条分析标准中的第 9 条，原文：

> visual presentations should be used when information or concepts (e.g., spatial or temporal
> relationships) **can be conveyed better in graphic form (e.g., tables, flow charts, images) than
> in written text** … **Analytic content in visual information should also adhere to other analytic
> tradecraft standards.**

两个可执行推论：

1. **判据是「图形式是否比文字更能传达」，不是「要不要配图」。** 空间关系与时间关系优先出图；
   不满足这个条件的图是装饰。**反向也成立：量级对比与结构关系压进表格是载体错配**——表适合
   逐条查证与精确取值，看不出量级差异。
2. **图与表里的分析内容同样受其余八条约束**——图上的判断也要能追到来源、表达不确定性、
   区分信息与假设。落成可跑的判据：图上实体名在证据正文的命中数 / 在标题的命中数 /
   引用的证据编号是否存在，三项全空即**撤框**，不留「看起来合理」的框。

**档位必须拆开标，别整条挂在 `[外]` 名下。** 上面第 1 条的**载体选择原则**是 `[外]`；
但检查器用来识别「哪张表算量级对比」的**触发阈值**（行数、数值列占比、列数）是 `[工]`——
本检查器自定的保守下界，无外部依据。把两者一起标成 `[外]`，正是 §1 要防的混档，
而且本轮独立评审就是在这一条上抓到了本文件自己：一条声称按依据分档的规则自己标错了档。

同族另两条对本轮问题直接相关：**第 2 条**要求不确定性用固定七档词表
（`almost no chance / very unlikely / unlikely / roughly even chance / likely / very likely /
almost certain`）并说明什么指标会改变不确定性水平；**第 7 条**要求解释本版判断相对上版的
变化或一致性——**这把修订轮从"打磨消耗"变成必答内容，没写是缺项不是勤奋**。

报告中图表与表格的视觉记法另有国际标准 **ISO 24896:2026《Notation for business reporting》**
（2026-06-11 发布；IBCS 2.0 与之对齐）。本文件不搬其条文，只登记为该族的权威面。

## §4b 图的布局：唯一有实证的那一支 `[外]`

§1 判定「图表密度」「行宽」这类无可靠来源是对的，但**图的布局属性另有一支真正做过实验的文献**，
本仓此前完全没有覆盖——它是少数几个既有实证依据、又能在 SVG 里精确计算的属性。

**Purchase, "Which aesthetic has the greatest effect on human understanding?"（Graph Drawing 1997）**
以理解时间与错误数双指标测五项美学，原文结论：

> 减少边交叉是**迄今为止最重要**的美学特征，而最小化弯折数与最大化对称性影响较小。
> **最大化节点出边间最小夹角、以及把边与节点固定到正交网格，其效果在统计上不显著。**

**Huang, Eades, Hong, "Larger crossing angles make graphs easier to read"（JVLC 25(4), 2014）**：
更大的交叉角让图更易读，且**不必是直角**。

两条可执行推论：

1. **冲突时的取舍序**：边交叉 > 弯折 > 对称。**不要为了对齐正交网格或加大出边夹角去牺牲前三者**——
   后两项统计上不显著，为它们做取舍没有实证支持。这半句同样是 `[外]`，它是一条"别做什么"的依据。
2. **不可避免的交叉，角度越大越好**，但不必强求 90°。

**三条边界必须一起引，否则就是误引**：

- **实验对象是抽象点线图，不是带标签的架构图。** 受试回答的是图论问题（连通、最短路径），
  不是「这个系统怎么运作」。架构图的节点有名字、有语义分组、有分层——**外推需声明，不得当作已验证**。
- **它给的是排序，不是阈值。** "边交叉最重要"不等于"交叉数 ≤ N"。
  由它推出任何具体数字，就变成了 §9 删掉那四条谓词的同类。
- **只有前两项可机械计算**：边交叉数（线段求交）与弯折数（path 折点数）可精确算；
  对称性不可靠，不做。

据此 `figure-lint` 提供 `GRAPH-CROSSINGS`（**WARN，只报数不设阈**）：给出连线两两交叉数与最小交叉角，
把事实交给人判断。**没有阈值依据就不设阈**——这条谓词的存在形态本身就是 §1 分档纪律的体现。

## §4c 色觉障碍：语义只落在颜色上就会失效 `[外]` 机制 / `[工]` 判据

**机制（一手）**：protanopia 源于长波（L）视锥的视蛋白基因缺失或改变，
所以 protanope 容易把**红色与黑色**混淆——不是"红变成别的颜色"，是长波整体感光下降。
色度学上，同一条**混淆线**（confusion line）上的颜色对该类型不可分；
标准模拟法是把颜色投影到 LMS 空间的不变平面（Brettel/Viénot/Mollon 1997；Viénot/Brettel/Mollon 1999）。

**由此得出的判据不是「避开某些颜色」，而是「别让语义只落在同一条混淆线上的色对」。**

- **实算优于模式匹配。** 按"红橙/蓝黄/低饱和"这类色对模式去查，在本仓真实 token 集上
  **只能命中三分之一**——另两对（主色/静默色 protan 距 14、主色/正常态 tritan 距 19）
  不属于任何预设模式，却同样不可分。
- **参照点用实测给**：Okabe-Ito 八色两两最小二色视距离 **38**；随机八色 **10**。
  本仓原 token 集 **14**——落在随机附近。
- **色不是唯一编码**：语义还应有形状、图标或文字冗余。
- **只测契约里显式声明为语义的色，且只报数不下判定**（`CVD-DISTANCE`）。两条都是被评审打回来才改对的：
  ①早先比的是图里**全部渲染色**（含装饰、边框、底色），等于假定任意两色都编码不同语义——
  装饰色撞在一条混淆线上不构成缺陷，所以语义色必须由 `figure-contract.json` 的 `semantic_colors` **声明**，
  声明缺失就不报，而不是替作者猜；
  ②早先虽写着"只报数"，代码里却拿 25 当触发条件——**那就是阈**。
  上面那三个参照点（38 / 14 / 10）是量出来的，`25` 不是；现在无条件报出距离与参照点，可否接受由人判断；
  ③"只报数"若走 `WARN` 档，退出码就变成非零——**声明会被退出码当场推翻**。
  故本条单列 `INFO` 档：打印、但不影响退出码。没有阈值依据的测量一律走这一档。
- **`semantic_colors` 必须受契约校验**：写成数组/字符串会让下游 `.values()` 直接崩；
  写成含非法颜色的映射会被静默丢成空集，于是"没报 CVD"既可能是"距离没问题"、
  也可能是"压根没测"——两者必须可区分。现在类型、`#RRGGBB` 语法、以及
  "必须是 `color_tokens` 的子集"三项都在 `validate_contract` 里判，违者 `CONTRACT-INVALID`。

**验证锚点也可能是错的（本文件踩过）**：曾用"红色模拟后应变暗"去验实现，结果亮度上升，
差点判一个正确算法有 bug。原因是模拟把红投影到 **575nm 黄色不变轴**——
亮度上升是算法的正确行为；而"红色看起来暗"说的是**红与黑难分**，是另一个量。
**用错的尺子量对的实现，比实现出错更难发现**，因为其余锚点会通过。

`[外]` 调色板出处：Okabe & Ito，*Color Universal Design (CUD)*，J\*Fly（<https://jfly.uni-koeln.de/color/>）；
Bang Wong 2011 年在 *Nature Methods* 使其广为人知，故常被称作 "Wong palette"，但原创归 Okabe 与 Ito。

## §4d 图值不值得画，以及它退化成什么 `[工]`

- **一句话说得更快，就写那句话。** 图的价值在于让冷读者看见一个**否则要从散文里拼出来的机制**。
- **画机制，不画名字。** 一个写着「缓存」的框比散文信息还少；请求穿过它的路径、它夹在哪两个存储之间、
  移除它会消失哪条箭头——这些才是文字说不清的。
- **一组互不相连的标注框不是对比，是列表的图形版**（本仓 `FIGURE-IS-A-LIST` 查这条）。
  比较方案就画**差异**：并排两版、前后对照、每个选项各加/减的那一条边。
- **图例只在同一编码重复出现时才值得**；否则把含义直接写在标记上。
- **流向一致**：L→R 或 T→B，不混用（`FLOW-DIRECTION-MIXED`）。该判据**依赖坐标**，
  所以图里存在 transform 等解析不了的呈现时整条跳过（否则旋转/镜像后的组会被判成另一个方向）；
  两端都有箭头的双向边不计入分布，只有 `marker-start` 的边按反向计；
  **两端都没箭头的连接直接跳过**——按 `d` 的书写顺序给它定向是凭空造方向，
  三条视觉上无向的线仅因端点书写顺序不同就能触发混合流向。
- **过期的图比没有图更糟——它主动误导。** 改动了图所描述的东西，同一次提交里改图；
  评审时即使超出本次范围，也要标出发现的过期图。
- **载体按规模选**（实践者做法，非实证）：≤10 元素用 mermaid；<15 且要布局控制用 flowchart；
  >15 或有持续交叉用 plantuml（其方向提示可修交叉）。
- **边交叉的实践者目标值**：复杂图 <5、简单图 0。**本仓不设阈**——`GRAPH-CROSSINGS` 只报数，
  实证（§4b）给的是排序不是门槛，这个目标值记在这里供参考，不作判定。

**不可机械判定、故只作提示**：视觉层级（系统边界应最显眼）、Gestalt 邻近性（相关元素成组）。
二者归视觉判断，本文件不设检查器；真要判需 `product-ui-ux-design` 的渲染验收。

## §5 版式契约：起草前冻结 `[工]`

**一致性本身是 `[外]` 要求**（C4 明文：consistent within and across diagrams；ICD 203 §2：
consistency in the terms used is critical）。**但「冻结成哪几档」是团队自选**——所以规则是
**契约符合性**，不是阈值。写成魔数（"字号不超过 6 档"）是错的：6 无依据，而偏离契约有依据。

首稿动手前写死 `figure-contract.json`，与图源同目录或其上层：

```json
{
  "canvas_ratios": [1.778],
  "font_scale": [12, 13, 15, 18, 19, 36],
  "color_tokens": { "ink": "#111827", "muted": "#667085", "primary": "#356A8A",
                    "ok": "#12805C", "warn": "#B54708", "critical": "#B42318",
                    "surface": "#FFFFFF", "surface-2": "#F7F8FA" },
  "semantic_colors": { "ok": "#12805C", "warn": "#B54708", "critical": "#B42318" },
  "themes": { "light": { "surface": "#FFFFFF" }, "dark": { "surface": "#0B0F19" } },
  "_retired": { "#98A2B3": "对白底 2.58:1，不达 WCAG AA 4.5:1，已退役" }
}
```

- **契约缺失本身是缺陷**：没有冻结的版式，一致性不可判定，每轮内容变动都要重调几何
- **退役项写明理由**：下次有人想用，看到的是「为什么不能用」而不是「不在表里」
- 改契约 = 改规范，不是改一张图
- 契约还需覆盖 §4 未定的两项：**单格文本上限**（按"必须能在一行放下"定，不按字数拍）与
  **分组单元**（每个卡片 = 形状 + 其文字包一个组）
- `semantic_colors` 是 `color_tokens` 的**子集声明**：哪些 token 承载语义区分（§4c 只测这些）。
  不声明 = 不测，不是"测出来没问题"
- `themes.<名>.surface` 必须是 `#RRGGBB`。写成 `"black"` 或非字符串，早先只判真值会让它通过校验、
  随后因不是 `#` 开头被静默跳过——**声明了主题却一次都没测，报出来的是绿**。现在按语法拒绝
- **只有直接压在主题底色上的文字才按主题判**（`THEME-CONTRAST`）。压在局部卡片上的文字，
  实际底色由卡片决定：深底上一块不随主题换的白卡片 + 深色字是**可读**的，拿全局底色去判会误报。
  判据是"这块底板是不是覆盖了整幅画布"——整幅底板算页面底色，明显小于画布的才是卡片。
  另两条前提同样是被评审打回来才补的：**`fill="none"` 的描边框不是底板**
  （否则一个框住低对比文字的边框就把它豁免了）；**底色解析不可信时整条跳过并显式报
  `THEME-UNASSESSED`**——圆形/路径/渐变卡片不会进 `rects`，此时"查不到卡片"会被当成
  "文字压在主题底上"，判出来的是假红。**未判定必须说成未判定，不能沉默成绿**

## §6 可读性与渲染：两条硬事实 `[外]`

- **WCAG 2.2 SC 1.4.3**：正文对底 ≥4.5:1；大字（≥18pt 或 ≥14pt 粗）≥3:1；例外只有纯装饰与 logo。
  图里的说明小字最容易违反，因为它又小又浅——所以 §5 的 token 表要求标注对比度
- **WCAG 2.2 SC 1.3.1（Level A）**：加粗若承载信息，必须有语义标记或文字替代。管的是「加粗有没有
  意义」，不是「加粗了多少」。对表格即：**真表头，不能用加粗行冒充**
- **SVG `<text>` 默认不换行**：规范行为不是偏好。超出容器的文本不折行、直接溢出，所以
  「单格文本上限」是功能要求不是审美要求

**目标端渲染的三条** `[工]`：

1. **验收以目标端回读为准，不认本地检查器**——本地全绿而目标端丢字是已发生过的事，检查器不模拟
   目标端的写入行为
2. **卡片单元必须分组**——至少一个目标端会对未分组的「形状+文字」做 z 序重排把矩形排到文字上层
   盖字，且每次覆写受害者不同；载荷顺序正确无用，重排在写入端
3. **交互源导成静态图前全部展开再导**（可折叠节点、悬浮标签、滚动区、分页表），导出后对照交互源
   清点实体

多载体时的载体登记与同步义务归 `multi-perspective-research`，本文件不重述。

## §7 图文一致

`[工]`，但它兑现的是 §5 独立性验收与 ICD 203 §6（清晰且合乎逻辑的论证）：

- 正文引用的图号必须存在——引用悬空即缺陷
- 采用编号图注约定后，每条图注都应被正文引用；有图从不被正文提及 = 图与正文各说各的，
  读者不知道该在哪一步看图
- 单张随文插图不强制编号（否则会把正常写法误判为缺陷）

## §8 检查器自身的规则 `[工]`

这一节的存在本身是教训：本轮第一版对比度检查器把压在色块上的白字判成 1.0:1（假阳性），
后又出现过图注把自己算成正文引用（假阴性）。

1. **先证明它能报失败再信它的绿**——逐谓词 fixture + 干净控制组，控制组被误报即检查器有缺陷
2. **改判据必同步改 fixture**：本轮修完误报后，orphan 那条谓词的 fixture 当场失效却仍"通过"——
   这是最容易静默丢覆盖的一步
3. **对比度检查必须解析文本实际压着的底色**，不能假定白底
4. **谓词钉在结构与实体上**，不钉在文件名或标题词表上——改名后词表谓词要么误报，要么在检查器
   仍读旧文件时静默通过，后者更危险
5. **派生产物新鲜度要两道判据**：实体数与 canonical 一致（抓内容过期）+ 文件时间不早于 canonical
   （抓"改了名字但数量没变"）。只查数量会在纯改名的轮次里全绿
6. **派生产物不进闸，就是下一个静默过期的载体**——新增派生产物的当刻就加进闸

## §9 已删除的谓词（勿再加回）

以下四条曾经存在，**已删除**：标题过长、单元格塞整段、段落内并列枚举、列表项多句。

删除理由不是"太严"，是**判据错了**：它们都拿宽度或计数当「表达好不好」的代理，
而这类阈值经查证无可靠来源（见 §1 `[禁]` 档）——等于把 `[禁]` 档的东西改个名字重新立一遍。

代价是实测出来的：在 392 份正常文档上全量试跑，这四条产生 **318 条 ERROR、涉及 150 份文件**，
抽样中**没有一条**是其声称的那个缺陷；命中最多的是围栏代码块里的 ASCII 分隔线与示例标题。
删除后总发现从 718 条降到 23 条、ERROR 归零、涉及文件 13/392。

**一条真正的缺陷判据不会在正常仓库里命中 38% 的文件。** 命中率本身就是判据是否成立的证据，
新增谓词前先在真实语料上量一次。

顺带修的两条前提性错误（同样由全量试跑暴露）：
- **围栏代码块与其内容不参与结构分析**——代码块里的分隔线、示例标题、示例表格都不是文档结构
- **「引用悬空」的前提是文档确实在用图系统**——一张图都没有的文档里出现「图 N」是在谈论图，
  不是在引用；本文件自己就因此被误判过一次

## §9b 两条代理谓词为何是非阻断（读结果前先知道）

`C4-LEGEND` 与 `C4-EDGE-LABEL` 不是精确判据，它们的失败方向不同，报出来的数字含义也不同：

- **`C4-LEGEND` 实测为真阳性。** 在 18 张真实架构图上报 17 张缺图例；抽 3 张核对，
  确实是 0 个小色块、无图例关键字、尾部文本全是内容而非图例项。报什么就是什么。
- **`C4-EDGE-LABEL` 倾向漏报，不是误报。** 它把「连线中点 90px 内的框外自由文本」当作标签，
  而实测中框外自由文本大多是**分区标题**（「入口层」「数据层」）与**旁注**，不是边标签。
  一条真正无标签的连线，只要中点附近恰好有个分区标题，就会被判为有标签。
  **所以它报出的数量是下界，真实情况只会更差**——读结果时不要当成全部。

**两条都已降为 WARN（非阻断）。** 对抗评审实测出它们**两个方向都会错**：
`C4-LEGEND` 拒掉只有两个条目的合法图例，而注释 / `<desc>` / class 里随便出现 `legend` 字样
就能让没有图例的图通过；`C4-EDGE-LABEL` 会被中点附近的分区标题掩盖掉未标注的连线，
又会拒掉标在连线别处的合法标签。**C4 的规则本身是 `[外]`，但用邻近与色块计数去认它是 `[工]` 代理**——
代理不该阻断他人提交。要恢复阻断，需要结构化关联（契约声明的组 / `aria-labelledby` / `textPath`），
而不是把阈值调得更准。

把下界当全量会给人虚假的安心。
`est_width` 同理：它是保守估算（CJK 1em / 拉丁 0.55em），只判「明显装不下」，临界宽度不可靠。

## §10 可跑的检查

同目录 `../scripts/figure-lint.py`（SVG）与 `../scripts/doc-lint.py`（Markdown 表格与结构）实现了
上述可机械判定的部分；`../scripts/tests/` 是逐谓词 fixture 与控制组，按 §8 第 1 条先自测再信。

```
python3 skills/tighten-doc/scripts/figure-lint.py <svg 目录或文件>
python3 skills/tighten-doc/scripts/doc-lint.py   <文档.md>
```

**本仓自身的文档也进闸**（`scripts/check-doc-structure.py`，接在 `make test-repo-gates` 里，
枚举全部 tracked Markdown 交给 `doc-lint`，实测 481 篇 / 0.15s）。三条规则：

- **DOC-STRUCTURE-GATE-TIER：只有 ERROR 一档得阻断，WARN 不得设成阻断。** 这不是保守，
  是 §9b 那条自己的规矩——判不开缺陷与判断题的代理不得设闸。落地时实测 0 ERROR / 75 WARN，
  把 WARN 也设成阻断等于当天就用一堆判断题把仓库判红。ERROR 是客观的那一半：
  表格没有真表头、图引用指向不存在的图、文件读不出来。
- **DOC-STRUCTURE-GATE-SCOPE：检查器自己的 fixture 目录必须排除，且排除只能是一条字面前缀。**
  `skills/tighten-doc/scripts/tests/` 那批文档按构造就带 2 个 ERROR，扫它等于让这道闸对
  "证明检查器有效"的输入永久红。排除写成模式就会悄悄长大——它是整个扫描器里唯一能让它
  一边打印通过、一边覆盖得比声称的少的部件。
- **DOC-STRUCTURE-GATE-BIDIRECTIONAL：排除必须双向断言，且缺陷必须落在会被吞掉的那条路径上。**
  fixture 要被丢掉，长得像 fixture 的真文档要留下。后一条最初写错了：带缺陷的文档放在了不含
  `tests/` 的路径上，于是把前缀放宽成子串匹配时掉的只是一篇干净文档、判定不变、那条腿照样绿，
  而它的注释里明写着"双向"。**是突变探针发现的，不是我读出来的**——
  单向的排除测试在排除已经长到覆盖半个仓库时，一样绿。

**不可机械判定的仍归人**：图种选得对不对、图注写的是不是主张、独立性验收、
调研族图上实体能否回指证据。检查器只挡机械项，不替代 §5 的验收。
