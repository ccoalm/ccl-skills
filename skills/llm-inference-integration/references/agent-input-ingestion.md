# Agent Input And Media Ingestion

## Local scheduled prompts

Treat local scheduled prompts as future model-visible input, not a reminder convenience. Bind creation, listing, deletion, and fire events to principal/session/workspace, target agent or recipient, schedule expression, local-time interpretation, recurrence, session-only versus durable lifetime, persistence policy, scheduler generation, queue priority, privacy/policy state, and workload attribution. Durable schedules need explicit user intent, validated next-run proof, storage containment, max-job and malformed-record handling, single-owner scheduler lock or lease with stale recovery, file-watch or store-reload fencing, and cleanup on shutdown. Missed one-shot tasks must be removed or fenced before surfacing and require fresh user confirmation before execution; recurring tasks should reschedule from actual fire time, persist last-fire state, cap lifetime unless explicitly permanent, and use deterministic jitter or equivalent load spreading for herd-prone times. Session-only schedules must never be reported as durable, child-agent or recipient-owned schedules must stay owned by that recipient and be removed when the recipient is gone, and all scheduled prompt bodies are untrusted lower-precedence data until the queued turn is accepted. Diagnostics may expose bounded categories, counts, lifetime classes, and sanitized schedule classes, but not raw prompt bodies, local paths, task ids, recipient ids, credentials, or free-form scheduler errors.

## Typed prompt, paste, and media ingestion

Treat typed prompt input, pasted text, pasted images, client-supplied media blocks, and resolved file or resource attachments as a model-visible input control plane, not a text-field convenience. Bind every inserted context item to source type, principal/session/workspace scope, prompt or turn id, input generation, content digest or paste/reference id, media type/schema version, size and dimension budget, storage generation, and extraction result before it reaches the model. Before resolving a file or resource reference, require fresh read authorization, canonical path or URI containment under the current allowed scope, source ACL/trust labels, symlink/hardlink and time-of-check/time-of-use rejection, and current snapshot proof; stale references or unverifiable containment fail closed before extraction or model insertion. Command or keyword routing must use only intentional typed command tokens or explicit UI command invocations from the finalized send snapshot, plus an explicit safe-command allowlist; pasted spans, attached/resolved text, generated metadata, queued notifications, and bridge/client payload text are excluded from local command or special-mode triggering unless the surface has an explicit trusted command-intent field. Normalize and validate client media schemas, infer or reject missing media types from trusted bytes rather than filenames, resize/downsample before API submission, enforce a final API-boundary size check, and strip embedded metadata or hidden payloads before provider submission or derived transcript/cache storage by default, including geolocation metadata, document properties, thumbnails, embedded files, hidden layers, comments, and tracked changes; preserve them only with explicit consent, purpose, scope, and retention. Bind async fetch/store/resize/extract completion to the current input generation, attachment snapshot, prompt digest, session incarnation, workspace/root, privacy state, and abort signal before applying results; late results after prompt edit, send finalization, abort, session/workspace switch, attachment deletion, or compaction must be discarded or surfaced as stale. Evidence-dependent failures must not be model-only markers: block send or require explicit user confirmation with a visible degraded state, and ensure the model cannot treat missing media/file content as present evidence. Pasted/attached/OCR/extracted content is untrusted evidence: wrap, quote, escape, or otherwise label it as lower-precedence data so it cannot override policy, tools, or current user intent. Local paths, filenames, pasted text bodies, raw media, and free-form diagnostics are untrusted and sensitive: redact or replace them with bounded labels, counts, hashes only when non-reversible, and user-visible repair categories before adding metadata, transcripts, logs, telemetry, or crash reports. Prompt/context caches and pasted-media stores must be partitioned or invalidated by session incarnation, workspace/root scope, privacy state, source trust, attachment snapshot, and prompt generation; normal prompt, slash/immediate command, queued, bridge, resume, and compaction paths need parity or an explicit no-attachment policy.

## Voice and speech-to-text input

Treat speech-to-text or voice input that feeds a prompt as a model-visible input control plane, not a text-field shortcut. Separate audio-capture finality, transcription-stream finality, and transcript-insertion finality; preserve interim/final ordering, endpoint/finalize semantics, stale callback generation fences, cursor or prefix/suffix insertion anchors, and duplicate-insertion suppression. Context hints sent to a transcription service are outbound sensitive context: scope, cap, sanitize, and require product consent before sending workspace, branch, file, or private vocabulary hints. Retry or replay only with bounded copied audio under the same principal, account or organization, workspace or repository identity, privacy state, consent or context-hint policy version, language, transcription route or adapter and backend generation, capture attempt id, stream id, copied-audio artifact identity and digest, optional immutable chunk range selector, insertion target, and input generation; fail closed on any drift and never duplicate transcript, tool action, or usage/accounting events.
