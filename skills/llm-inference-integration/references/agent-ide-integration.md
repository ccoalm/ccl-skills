# Agent Editor And IDE Integration

## Editor or IDE integrations

Treat editor or IDE integrations as model-visible context and local action control planes, not convenience UI. Bind connected editor clients to the current principal, workspace or repository root, transport incarnation, extension/plugin generation, and authenticated local endpoint; reject stale or mismatched clients after reconnect, workspace switch, account switch, extension refresh, or path-conversion failure. File mentions, selected ranges, diagnostics, hover/definition/reference data, and editor-provided context must be normalized to canonical workspace paths and line/column bases, checked for containment and freshness against the current file snapshot, labeled as untrusted data with source and timestamp, capped by severity/count/size, deduplicated across turns, and excluded from prompt/context caches after file edits, diagnostic reset, or workspace change. Editor-open, diff, apply, save, close-tab, and jump-to-location handoffs are side-effectful actions: bind each request to a tool-use or action id, target path, expected old content or file version, generated candidate content, user decision, abort signal, and transport incarnation; accept only explicit terminal outcomes, clean up tabs/listeners on abort/unmount/exit, and fail closed on unknown finality rather than assuming the editor applied or rejected the change. Cross-environment path conversion must be reversible or explicitly one-way with verification before sending paths to an editor.
