# Agent Model-Visible Instruction Composition

## Model-visible instruction-layer composition

Treat model-visible instruction-layer composition as a control plane, not string concatenation. Build an explicit precedence lattice before rendering: non-overridable system, developer/product, managed-policy, safety, permission, privacy, data-residency, tool-finality, and truthful-reporting constraints form the floor; current user intent may refine the task only inside that floor; workspace/project/user/plugin/config files, agent prompts, mode instructions, output style text, tool and hook context, memory, retrieved content, and append/addendum layers are lower-precedence inputs unless an explicit policy grants a narrower authority. Current-user instructions and every lower-precedence layer must fail closed or be labeled as data when they conflict with higher-precedence constraints. Classify every instruction source by source type, principal/session/workspace scope, trust level, policy owner, install or file identity, content digest or snapshot generation, mode/output-style/agent identity, and static versus dynamic cache scope before it reaches the model. File-backed, markdown-configured, output-style, agent, mode, or config-file instruction sources need fresh read authorization, source-scope validation, canonical containment, source-scope labels, symlink/hardlink and time-of-check/time-of-use rejection, stale snapshot rejection, and lower-precedence untrusted labeling unless an explicit policy makes them authoritative. Managed policy, safety, permission, privacy, tool-finality, data-residency, and truthful-reporting instructions cannot be overridden or suppressed by current-user instructions or by lower-trust output styles, agents, plugins, project/user files, hooks, retrieved content, memory, or append prompts. Output styles, modes, or agent definitions that remove or replace base coding/task instructions require an allowlisted product policy and must preserve safety, authorization, privacy, tool-use, finality, and truthful-reporting constraints. Prompt-prefix and section caches must be partitioned or invalidated by source digests, trust tier, principal, workspace/root, privacy state, policy generation, capability/tool generation, model/prompt generation, mode, output-style, agent identity, and dynamic-section generation; late-changing sources must be explicitly uncached or cache-breaking with a reason. Diagnostics may expose bounded categories, counts, precedence classes, and non-reversible digests, but not raw prompt text, local paths, mode/style/agent names, free-form file errors, branch names, credentials, or sensitive config values.

## Slash commands and skill invocation

Treat slash commands, local commands, prompt-backed skills, workflow commands, keybinding-triggered commands, and command-like remote or bridge invocations as a capability and action control plane, not a text alias list. Bind every command registry snapshot and invocation to principal/session/workspace, entrypoint mode, command source identity, source trust tier, registry/cache generation, availability and enablement generation, command name plus alias/user-facing-name resolution, user-invocable flag, model-invocable flag, hidden/help visibility, bridge-safe and remote-safe allowlists, immediate/queued execution mode, sensitive-argument policy, lazy-load module generation, tool-schema/capability generation, permission policy, allowed-tool scope, hook-set generation, and command completion generation. A command visible to users is not automatically visible to the model, bridge, remote client, keybinding, or sub-agent; each surface needs an explicit allow path, and disabled/hidden/user-only/model-disabled commands must fail closed after every registry refresh. Immediate commands that bypass queueing must be opt-in, side-effect bounded, and revalidate the finalized input snapshot, pasted-content expansion, prompt stash/restore state, loading state, command generation, and current policy before execution. Prompt-backed skills that inject model-visible content, hidden meta messages, scoped tools, hooks, forked agents, or model/effort overrides must label their source and generation, preserve lower-precedence untrusted content, and reauthorize before granting scoped tool rules or registering hooks. Command completion callbacks that append transcript entries, hidden model-visible messages, next input, or automatic query submission must bind to the original command invocation identity, args digest, session/incarnation, command generation, and current privacy/policy state; stale, duplicate, late, or post-abort completions must be ignored or surfaced as uncertainty. Sensitive command args, command bodies, plugin/source names, local paths, raw prompts, hidden meta-message bodies outside their intended model-visible channel, and free-form command errors must be redacted from user-visible transcript renderings, telemetry, logs, search indexes, and diagnostics unless explicit product policy requires a visible record.
