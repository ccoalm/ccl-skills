# Agent Runtime Startup And Configuration Bootstrap

## Runtime startup and configuration bootstrap

Treat runtime startup and configuration bootstrap as a trust-boundary state machine, not ordinary config loading. Bind startup effects to principal/session/workspace, entrypoint mode, trust state, settings source class and generation, host-managed runtime-variable ownership, managed-policy generation, network-transport generation, cwd/project-root/worktree generation, hook snapshot generation, cleanup generation, and telemetry initialization generation. Before workspace/project trust, trusted global/user/flag/policy sources may apply according to policy, while project-local or workspace-derived settings may apply only when explicitly allowlisted as safe and unable to widen authority, redirect traffic, load code, change provider/model/routing, modify proxy/TLS material, alter hooks/tools/sandbox/telemetry behavior, affect model-visible context, or expose credentials; all other project-local or workspace-derived configuration must wait for trust and fresh authorization. Host-owned spawn variables and provider-routing variables must not be overridden by lower-trust settings when the host declares ownership. API-only tunnel or routing variables must stay scoped to the intended API client and must not leak into unrelated connector, HTTP, streaming, shell, hook, or tool transports. Early certificate, proxy, and mutual-auth setup must use only trusted sources, preserve base trust roots when adding custom trust material, respect bypass rules, and clear/rebuild cached agents or clients after post-trust environment changes. Cwd, project-root, or worktree switches must invalidate file, memory, prompt, hook, tool, permission, and source-control caches and refresh hook/config snapshots before commands, tools, hooks, skills, background jobs, or model-visible context load from the new root. Startup background jobs, prefetches, remote settings fetches, memory tasks, release notes, and telemetry must be gated by entrypoint mode and trust state, idempotent across retries, cancelable during shutdown, and unable to race noninteractive install/sync paths. Unsafe bypass modes need explicit environment checks and a fail-closed degraded state. Diagnostics may expose bounded categories, generations, mode labels, and sanitized reason codes, but not raw local paths, environment variable names or values, provider names, endpoint details, credentials, command lines, project structure, config bodies, or free-form setup errors.
