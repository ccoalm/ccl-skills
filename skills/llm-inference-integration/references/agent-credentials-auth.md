# Agent Credentials And Local Authorization

## Credential, token, and control-plane secret handling

Credential material, session tokens, and control-plane secrets must never enter model-visible context, transcripts, tool-call payloads, reconnect history, persisted session state, logs, telemetry, or crash reports. Redact at the emission boundary and route cross-service log/trace field policy to `platform-observability`.

## Browser-launched local authorization flows

Browser-launched local authorization flows are runtime credential control planes, not login UI plumbing. Bind each authorization code to the exact flow attempt: provider or authorization-server identity, client or client-registration identity, audience/resource identity, auth source, auth-policy generation, storage backend or cache namespace, verifier/challenge, CSRF state, redirect URI, callback listener identity, callback path, manual versus automatic mode, requested scope set, principal/account/tenant/organization/workspace tuple with explicit none markers, callback attempt id, callback transport generation, credential generation, policy/capability generation, abort signal, and token-exchange attempt id. Reject missing, duplicate, late, stale, canceled, timed-out, failed, wrong-state, wrong-path, wrong-host, wrong-port, wrong-mode, wrong-tuple, or post-success callbacks; close the listener and resolve any pending browser response exactly once on success, failure, manual-code fallback, timeout, abort, or process shutdown. Token, refresh-token, account, scope, subscription/entitlement, profile, remote-config, telemetry-targeting, connector-header, prompt/context, tool-schema, runtime, and model-visible capability caches must be single-flight where needed, invalidated or generation-fenced after login, logout, account switch, re-enrollment, scope drift, token-file or secure-storage drift, token revocation, refresh failure, entitlement drift, profile correction, discovery change, auth-source drift, privacy/trust change, or storage-namespace drift, and updated without clobbering a known-good account or entitlement field with transient profile-fetch failure. Every token exchange, refresh, profile fetch, entitlement fetch, config rebuild, telemetry callback, and cache write must carry the current auth/session/cache generation and drop or fail closed if the tuple changed before commit. Refresh must use re-read-after-lock and newest-token behavior where possible, re-check storage before clearing credentials on invalid grants, retry only bounded transient failures, and never elevate scope when the required scope changed. A credentialed request that receives an unauthorized response must re-read and revalidate current storage before clearing credentials, prompting login, or retrying under a stale credential generation, because another process may already have refreshed or revoked the token set. Telemetry or analytics paths must degrade or fall back without using expired, unsupported, or tuple-mismatched credentials and without changing model-visible capability state. Preserve previous profile/account/entitlement cache only for explicitly non-authoritative transient failures, never to override newer deny, opt-out, logout, account switch, revocation, or trust downgrade. Any auth fact tuple change, including scope expansion during refresh, is a policy change: revalidate the account tuple, clear or generation-fence prompt/tool/runtime/model-visible auth caches that depend on auth facts, and require fresh execution-time authorization for model-visible capabilities. Diagnostics may expose bounded outcome categories, grant class, storage class, retry/lock counts, cache outcome, and sanitized error class, but not callback URLs, codes, state, verifier/challenge values, access or refresh tokens, headers, cookies, profile or entitlement payloads, account emails, stable user or organization identifiers, local ports for live listeners, endpoint details, credentials, or free-form provider responses.

## Remote-session refresh and reconnect

Remote-session refresh and reconnect paths must be single-flight per session when a refresh changes server-side session generation, worker epoch, lease, credential, or sequence state. Treat token refresh scheduling as a session control plane: bind every scheduled, immediate, follow-up, and auth-failure refresh to session id, session incarnation, credential generation, transport incarnation, refresh attempt id, expiry or TTL source, abort/teardown generation, and sequence high-watermark. A proactive refresh and an auth-failure recovery must not both mint credentials, rotate credentials, renew leases, replace transport credentials, or advance server-side generation; claim mutual exclusion before any remote fetch that can change credentials, lease, epoch, sequence, or transport incarnation. JWT expiry decode failure or opaque-token refresh must preserve an existing valid refresh chain rather than cancel it; explicit TTL scheduling needs floors/caps that prevent tight loops and buffer-vs-delay inversion. Missing access tokens, refresh errors, and credential-fetch failures need bounded retry, terminal degraded state, and metadata-only diagnostics, not unbounded timers or model-visible credential details. Late async refresh completions after reschedule, cancel, teardown, session/workspace/account/privacy drift, or generation mismatch must not deliver credentials, rebuild transport, re-arm timers, or mutate baselines. Any refresh that changes transport credentials or server epoch must rebuild the transport under a new incarnation, carry forward only a verified sequence high-watermark, gate queued writes and history flushes during the swap, drain only into the matching rebuilt transport, and fail with visible uncertainty if final delivery is unknown. Shutdown archive, terminal-result, and final-history flushes that hit expired credentials need at most a bounded, generation-fenced credential refresh/retry within the shutdown budget; if durable archive or delivery proof is not observed before cleanup closes the transport, report unknown finality rather than delivered success.
