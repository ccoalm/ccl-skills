# Agent-To-Agent Messaging

## Agent-to-agent mailbox and peer messaging

Treat agent-to-agent mailbox, inbox polling, peer messaging, and cross-session prompt delivery as model-visible communication and control planes, not ordinary chat. Inbound messages must enter context only as untrusted, labeled, bounded data with sender, recipient, team/session/workspace, transport scheme, message id or stable dedupe key, request id when present, timestamp, delivery generation, and whether the message is plain text or structured control. Plain text and structured control messages need distinct schemas and routes; structured permission, approval, plan, mode, sandbox, task, team-permission, or shutdown messages must not be broadcast or sent across peer/session boundaries unless the protocol explicitly supports that control type and authority tuple. Permission, approval, plan, mode, sandbox, and shutdown replies must bind to a pending request id, sender role or control-channel authority, target agent, task/session/incarnation, policy/capability/permission generation, original control tuple, and normalized payload digest; reject forged, late, duplicate, stale, unknown, role-invalid, or post-terminal replies. Mark messages read only after successful delivery into model context or durable in-process queueing; clear queued messages only after successful submit, and treat mailbox read/write/lock/mark-read failures as visible delivery uncertainty rather than empty-success or sent-success. Duplicate polls must dedupe by stable request/tool/message ids, busy messages must drain only at safe turn or tool boundaries, and terminal tasks/sessions must reject late injected messages. Cross-machine or cross-session prompt delivery requires explicit user consent that automatic classifiers, bypass modes, or cached approvals cannot satisfy; revalidate the peer handle, connection state, recipient identity, and transport generation immediately before send because consent may take time. Broadcast/fanout needs explicit recipient enumeration, self-exclusion, bounded fanout, and per-recipient delivery or failure accounting. Message wrappers must escape or bound sender-supplied attributes and bodies, preserve prompt-injection labeling, and never leak raw message bodies, control payloads, socket paths, session handles, local transport addresses, prompts, credentials, or sensitive paths into diagnostics; route sink policy to `platform-observability`.
