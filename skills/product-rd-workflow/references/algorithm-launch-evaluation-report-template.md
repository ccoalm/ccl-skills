# 算法服务测评报告模板

配套 [算法能力上线门禁 SOP](algorithm-launch-sop.md)。

| 模块 | 必填内容 |
|---|---|
| 基本信息 | 项目、能力类型、新版本、老版本/基线、产品负责人、算法/研发负责人、上线决策 owner、测评时间 |
| 产品定义三问 | 给谁用、哪个任务变好；哪个业务结果改善、什么不能变差；为什么现在要自研、采购或迭代 |
| 产品定义 | 用户、场景、入口、完整链路、能力边界、失败兜底 |
| 业务目标 | 要解决的用户问题、业务目标、业务效果基线、测量窗口和数据来源 |
| 方案说明 | 算法变更、服务链路、影响范围、依赖数据 |
| 真实链路核查 | 链路图、入口、上下游模块、证据来源；未确认节点必须标为待确认，不得写成已存在链路 |
| 指标基线 | 算法指标、业务指标、工程指标的最低上线标准、阈值设置依据和审批人 |
| 指标对比 | 新版本 vs 老版本/三方/行业基线，同口径对比 |
| 数据集说明 | 来源、时间、样本量、覆盖场景、标注方式、偏差风险 |
| 版本追溯 | 模型、提示词、检索、索引、知识库、工具、后处理、三方服务和配置版本 |
| 组合链路验收 | 模块级测评、接口契约测试、端到端回归、下游业务指标是否变差 |
| 评测集治理 | 固定基准集、回归坏例集、灰度观察集的版本、负责人、防污染声明和变更记录 |
| 实验或灰度 | 分流规则、样本量、观察周期、扩量规则、停止规则、护栏指标 |
| 失败样例 | 新版本变差样例、高风险错误、长尾问题 |
| 风险控制 | 多版本实验或灰度、监控、漂移观察、告警阈值、响应时限、回滚时限、兜底、人工复核 |
| 投入产出与合规 | 自研与三方投入产出、三方对比、安全/合规确认 |
| 例外与残余风险 | 缺失项、例外范围、风险影响、owner、跟进日期；无例外则写“无” |
| 全量后运营 | 持续监控频率、重跑评测触发条件、负责人 |
| 上线建议 | 允许全量、允许实验或灰度、暂缓、禁止上线 |
