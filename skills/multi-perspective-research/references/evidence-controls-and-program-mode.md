# 证据控制、采集顺序与多轮 Program 细则

承载 `SKILL.md`「核心流程」「硬规则」「多轮 program 模式」「Closeout」及 `references/public-data-acquisition.md` 的展开判据、对照实验、可比性向量、增量管线复验与多载体同步细则。入口保留红线与状态词定义，本文承载执行步骤与判别边界。

## 一、覆盖预检与三态主张标注细则

### 覆盖预检组织边界

这四类是完整/深度标签的组织控制，不是宣称所有主题都遵循同一套系统综述标准。用户材料默认只是线索，不是研究边界；只有用户明确要求“仅基于这些材料”时才能封闭外部检索。“本轮不要执行检索/先给计划”只把检索状态留为 `pending`，不等于限定来源范围。**调研对象是一个具体组织（而非主题）时，先定 estimand 再走一遍组织披露渠道类别清单**：四类证据问的是"证据是什么种类"，只查官网与年报就能把"一手/官方"格正当关上，而强制披露制度、监管方批量数据、他国法定登记通常信息量更大却一次未被想到。`references/public-disclosure-channels.md` 是这个**组织场景**的渠道起点，只用来防"没想到"，是起点不是全集，不另立闭合状态；走完它不构成任何终局判断，走不动的类别按本节既有纪律计为未关闭格。`references/public-data-acquisition.md` 则说明公开材料怎么取回、解析与自校验，适用于组织、主题、政策、技术、市场等场景。

### 合成简报主张状态三态细则

「来源明确陈述 / 有证据支持的推论 / 作者判断」三态，与第 2 步产出的共识/争议/盲区**分区**是两个正交轴（分区说内容归哪块，状态说主张立在什么上）；「来源明确陈述」是**归因不是真实性**——写成「来源 X 声称」，可信度仍由 grounded 纪律与来源质量单独表达；作者判断句显式带「判断」类标记；证据只撑到推论级就用分级句式写（如「机制可证、参数不可证」），不让判断穿事实的句式。三态管**解释性/推断性主张**，直接观测豁免只限**原始计数/测量值**（本次工具调用真实取回的数字，走证据表 grounded 行按原样陈述）——工具生成的分类/评分/裁决（如某检查器给出的通过/风险级）仍按推论或判断标注并写明工具及其权威边界；**约束覆盖简报全部此类主张**——一段话总结、隐藏关联、可操作建议、前沿问题不得引入关键发现之外的承重新断言，新增承重断言先回填为关键发现并入证据表。

## 二、证据落地与配平、对照、可比性、消歧细则

### 源内配平与边界核对

即使 `grounded` 的全部条件都满足（来源链接、实际取回的摘录、会话内可回查的调用位置），也不能保证**取到之后的加总**是对的：法定报表常在同一行同时给出分项与行合计，整行求和即得 2 倍值；反向也会发生——看不懂来源的数被当作解析噪声丢弃，实际是子项合计。**配平只证明"我没读错这张表"，不是独立验证**——分项与合计常出自同一口径与同一生成程序，必然相等；配平之后仍须单独查单位、期间、法人与地理范围、唯一键重复、缺失分区。与另一独立口径比量级只是 sanity check：能否证不能确证。配平不上时按诊断顺序走（解析/单位/舍入/版本 → 来源修订与内部矛盾 → 仍不可解释则如实报告冲突、不以确定值进入结论）。**被禁止的是"为了配平而反复调参"**，不是禁止一切解析修正——有来源格式或模式证据支持的修正是正当的（括号负数、千分位、脚注单位），留下改前改后差异与依据即可。方法见 `references/public-disclosure-channels.md`。

### 负结果的双对照判别力检验

任何承重的负结果（两组无对应、某通道查无此人、加了变量没有差异）都有一个孪生解释：所用的匹配规则、相似度或管线本身检不出**任何**东西，坏掉的工具返回的结果与真实的"无"**逐字相同**。两种自建对照（都不需要外部真值）：

- **阳性对照（自匹配）**：把同一实体的数据按与结论无关的维度劈成两半，各自建档，问 A 半在所有 B 半档案里的最近邻是不是它自己——同一批对象、同一批特征，这是方法**必须**找到的对应。找到了，则原负结果是关于被测对象的；找不到，则方法太弱，本轮负结果降级为"未测"。**但自匹配只有在剔除标识性捷径后才算数**：两半若共享直接标识符（同一 ID、同一姓名串、同一唯一短语），或共享只有目标侧才有的特征，自匹配会靠这些捷径成功，而真实任务里两侧根本没有这种共享——于是方法"通过"了对照却仍检不出跨组关系。构档时按真实任务的可见特征建，把捷径特征剔掉再做自匹配；剔不掉的，说明这个对照对该负结果不适用，另找对照或如实记未测。
- **零假设对照（保分布打散）**：把目标集的标识与属性**在集内打散重组**，得到分布一模一样、身份已被破坏的假目标，用同一套规则去撞。命中率即**偶然碰撞率**，它同时回答"方法是不是在匹配通用特征而非身份"——对错误目标也给高分的方法，测的是词汇不是对象。
- 两个对照顺带给出一个**诊断性范围**（下侧＝精确匹配命中减去偶然碰撞率，上侧＝放宽规则后的命中），比一个孤零零的百分数诚实。**但它不是统计置信区间，不得当区间报**：它没处理抽样误差与匹配间的依赖，也不保证放宽规则只朝一个方向错，真值完全可能落在范围之外。要以区间形式进结论，须另写清识别假设并给出正当的不确定性估计；否则只作为量级诊断，并标明它是诊断而非区间。自评里已知方向性偏差（如"只归一化未消歧，会让召回偏高"）的，正好用对应侧的对照去界定方向。

这与上一条的"配平不是独立验证"是**两条正交的轴**：配平查数据有没有读错，判别力查方法有没有分辨能力。两者都过，负结果才站得住。

### 跨期可比性向量与编码迁移

同一字段跨期不可比的两个常见原因是周期性与填报口径变更，两者都会让曲线看起来像"数据坏了"。跨不同性质的期间直接比较后判定"字段不可用"是误判；反过来，有官方 bridge/映射表却拒绝 harmonize 也是错。**形式同口径不等于可比**——并购或重组导致法人范围变化时，同财季对同财季仍是假趋势，须逐项过可比性向量（期间、字段定义、单位、币种与价格基准、地理范围、法人范围、覆盖阈值、修订版本、测量方法）。一个字段塌到接近零而另一字段同期跳升，**提出编码口径迁移这个待验证假设**（而不是直接判定数据失效）；但**合并成一个语义桶必须先有语义依据**——字段定义、申报说明、版本变更记录，或正式映射表。**数值恒等式（如两列之和跨期守恒）只是 sanity check 或迁移信号，不构成依据**：两个语义不同的字段一降一升、其和恰好稳定完全可能，恒等式证明不了分类互斥完备或字段语义等价（这与本节"配平不是独立验证"是同一个道理）。缺语义依据时只能并列报告。没有依据就分别报告并标"不可比"：两个字段也可能本就是不同概念、不同统计范围，或反映了真实的结构变化，无依据合并会造出新的不 grounded 派生数据（期间长度不同时的归一化选择见 `references/public-disclosure-channels.md` §二）。**口径修复要落成后续步骤会复用的东西，而不是只写进交付物脚注**——可以是本次分析里可复算的转换、查询或版本化映射，不要求每次都去改共享规则；只写脚注时同一次调研的后半段会再犯一次。

### 第三方数据集实体消歧与召回分母

聚合型数据集会把名称相近的组织或同名个人合并成一个实体条目，用实体 ID 过滤会一次性引入整批无关记录。只报精确率是最常见的假安全：挑几条明显正确的记录能得到 100% 精确率，而目标实体可能被拆成多个 ID、旧名或子组织，召回只有一半，样本全对而总量系统性低估。两个方向都查：merge（不同对象被并成一个）与 split（同一对象被拆开），核对时带上别名与历史沿革。**召回率必须有完备性依据的分母**——有完备性论证的候选全集，或经验证的 gold set。只在该 ID 已返回的记录里抽样只能估精确率，看不到没被返回的那些。**两条"互不依赖"检索路径取并集给出的是观测到的唯一对象数——它是总体规模的下界与检索产出量度，不是真实分母，也不是召回率的下界**（召回是比例，分母未知时它可以任意接近 0）：两条入口可能共享同一上游索引，或共享语言、时间、地域、收录偏差，而"互不依赖"本身缺少可观测判据；交集 `|A∩B|` 更不是覆盖率，用 capture–recapture 之类估计时必须写明独立性假设、误差与适用边界。没有合格分母时记"召回未知"——此时**不存在可报告的召回下界**，只能报观测到的唯一对象数，并**禁止发布总体规模与比例**。消歧不可靠时，**不得用该数据估算原目标总体的比率**（流动率、归属率等）——"严格子集"救不回来，因为子集的筛选条件与被研究性质相关（筛掉属性多的实体等于筛掉目标现象）。人工逐条确认过的子集仍可支持**重新定义并明示了选择偏差的**窄结论或案例分析，但必须写清它估的已不是原总体。

### 你自己写的名字匹配

第一轮讲的是"别信数据集自带的实体消歧"。这里是另一件事：**你自己写的那个筛选条件**。

- **锚定，别子串**：按名称筛某个实体时，裸子串会把名字里含同一词的无关实体一起捞进来（一个常见词做子串，能顺带命中若干完全无关的机构）。用起始锚定 + 已知的法定后缀集合，并**把命中的不同名称变体连计数一起输出**（变体数上千时看分布与长尾，不是"逐个看"）
- **别在同一步里既归一又计数**：同一实体的多种写法要先归一（缩写、名字中段、法定后缀差异），归一表要能被人读到；归一和统计混在一行里，出错了没法判断是匹配问题还是数据问题
- **归一过度和归一不足都要查，而且两个方向的抽样框不同**：过度归一（两个不同实体被并成一个）→ **从同一个 canonical 桶内抽样**，看桶里是不是真的同一个；归一不足（同一实体被拆成两个）→ **从候选全集或 gold set 抽样**，看该实体的别名是不是都进了同一个桶。按 `SKILL.md` 的抽样契约记下**抽样方法、样本量、判定阈值**——只说"抽样看过了"不构成证据，因为挑几条正例总能自证合格

### 取到的是不是全量

分页、结果上限、`Retry-After` 退避中断，都会给你一份**语法完好的残缺数据**，而它不会报错：

- 翻页循环必须有终止断言（短页或零行），并把累计行数与数据集/报表自述的总数比对
- 命中服务端结果上限（很多接口有硬上限）时，改用更窄的切片重取，不要只拿上限那一页
- **怎么察觉自己撞上了上限：一个恰好等于文档所列每页上限的整数（100、500、1000…）是"这一页已经装满"的饱和信号，不足以当总量。**它不证明一定还有下一页（总数确实可能正好是 N），但没翻页时它往往是唯一的提示——接口返回 200、字段齐全、数值也合理，只有"恰好等于上限"这一处异常。把这类整数当规模、当分母、当比例基数之前，按顺序验：**先请求下一页**——空页是支持性证据不是证明（游标过期、权限裁剪、翻页参数写错、服务端瞬时空页都会给你一个空页），所以空页要连**同一次请求的成功状态与分页游标是否正常推进**一起看；**能比对来源自述的总数就比对**；两条都验不了，才记成下界而不是计数
- 中断重试后要能判断是否重复行——这就是分页必须给稳定排序键的原因

### 检查器自己会骗你

常见假通过/假失败形态都表现为"检查器说通过/说失败"而实际相反：

| 失效 | 表现 | 防法 |
|---|---|---|
| 子 shell 丢环境 | 循环里 `sed`/`cut` not found，输出一片失败 | 坏掉的检查器与真失败在输出上一样——**先证明检查器能正确报成功也能正确报失败** |
| 重新实现闸而不用闸 | 自写脚本判"全通过"，真闸判失败 | **闸本身才是判据**，别重写它的解析逻辑 |
| 只捕 stdout | 关键失败行走 stderr，据此做的"无新增失败"对比全是残缺的 | 采集两个流：`> file 2>&1` |
| 读错了退出码 | `cmd \| head` 之后 `$?` 是 `head` 的状态，不是 `cmd` 的 | 要判命令成败就别接管道；或读 `PIPESTATUS`/`pipestatus` |
| **检查器没坏，但只查了一部分组合** | 一个真实存在的冲突落在没被比较的那一对上，检查安静通过 | **枚举检查器覆盖了哪些组合、没覆盖哪些**；**先算规模再决定**：全配对是 N(N-1)/2 对，几十个成员时通常便宜到没理由不跑，但它是平方增长——N 上千、或每对还要解析/远程请求/模型调用时，改为按已知风险维度分层抽样，并把"只查了哪些组合"写进交付物 |

**能报失败 ≠ 查得够全。** 上表前四行是检查器**坏了**，第五行是检查器**好的但覆盖不全**——后者更难发现，因为它给出的是一个真实通过的结果。区别在于问的问题不同：前者问"它能不能报错"，后者问"它把哪些组合拿去比了"。只按预期的那种关系去查（相邻的、连续的、同类的），就查不到跨过那层预期的冲突；而**保守的实现有时会替你兜住**——按唯一键去重、而不是按文件求和，即使检验漏了也不会出错——这时候要记清楚：救回结果的是实现，不是你的检验——**而且归因到此为止还不够，仍要把检验补齐**：那层实现保护没有被谁承诺过，下一次重构把它去掉时，残缺的检验依然会亮绿灯。

同理适用于**参数**：核过"这个参数存在、能用"不等于核过"它在什么条件下不生效"。`--max-filesize` 就是这样——后缀能用是真的，对未知长度响应在旧版本上完全无效也是真的。

## 三、基线顺序：把成本花在对的地方

一次涉及公开数据采集的深度调研，时间大头常不在取数，在**返工**。下面是**默认顺序**；初始证据来自一次组织调研里"实际怎么做"与"本该怎么做"的差，组织只是来源场景而不是本文或本技能的能力边界——**这也不是普适强制序**。具体组织只是其中一个场景，可借 `references/public-disclosure-channels.md` 的组织披露清单防漏；主题、政策、技术、市场等调研必须按自己的主张另列来源类别，不能套用组织清单冒充覆盖。这个顺序是**默认序不是强制序**；“组织调研的成本大头常是返工，所以有一条基线顺序”只是最初观察到该失败的场景，不是规则的适用边界：先深挖会让最高价值的源最后才出现；先写作会让骨架反过来绑架取数范围；口径立在取数之后会让同一份数据算三遍。增量更新、用户已给定材料、限时/限窗访问源、可得性未知等情形可以换序——**换序时记下为什么**。配套两条：解析脚手架搭一次（流式读 + 按列名取 + 自校验）而不是每源重写；交付物骨架（数据源表、证据表、导航）从登记表派生而不是每轮手改——手改的那份最后一定过时。详见 `references/public-data-acquisition.md`。

| 步 | 做什么 | 跳过它的代价 |
|---|---|---|
| 1 | **定研究对象与 estimand**：对象/总体/范围是什么，依据与截至日期是什么；具体组织场景再细分单一法人、合并集团、品牌、业务单元或网络 | 后面每张表都在给错的对象取证，形式正确而总体被偷换 |
| 2 | **按载重主张走一遍适用的来源/渠道类别**，先不深挖任何一条；具体组织场景可借 `public-disclosure-channels.md`，其他场景另列 | 最高价值的源最后才出现；错套场景清单还会制造虚假覆盖 |
| 3 | **按单位投入产出排序**，不按熟悉度 | 按熟悉度先啃大体积原始明细，单位时间产出远低于结构化汇总报表 |
| 4 | **立口径**：期间、范围、单位、修订版本 | 取数后才发现不可比，同一份数据算三遍 |
| 5 | 取数 + 当场自校验（`public-data-acquisition.md` §三） | 错值进了结论才被发现 |
| 6 | 再深挖剩下的渠道 | — |
| 7 | 最后写作 | 先搭写作骨架会让骨架反过来绑架取数范围 |

**可以重排的情形**（换序时记下为什么，且遵守 `SKILL.md`「硬规则·基线顺序」条的前置冻结红线）：

- **增量更新**：estimand 与口径上轮已定且未变 → 可从第 5 步起。但上轮管线是假设级输入：复用取数脚本/解析方法前先抽验——跑一遍自校验、对一个已知值核一次只是 smoke，不等于复验完成，按风险重跑适用不变量（schema/字段、分页/完整性、配平），抽验记录写明覆盖了哪些分支（分页、地区、异常分支——已知值可能只走了主路径），并**绑定管线与输入身份**（脚本内容哈希、响应内容指纹——修改时间与逻辑版本号只作提示，不维持复验有效性：`touch`/缓存恢复不改 mtime 语义，同一版本号下内容也可被替换）——任一身份变化即该覆盖记录失效、回到未复验；**承重结论所依赖路径上的适用分支未复验时，管线复用状态是 `pending`，其产出不得进承重结论**——「诚实记录了未覆盖」不等于可以照常复用，只有不触承重结论的分支才允许带残余风险放行——源改版或文件改名会让旧脚本失效，最危险的形态是静默假绿（脚本仍读到陈旧文件，或按名匹配不到就跳过）
- **用户已给定材料**：先读给定材料，再回到第 2 步补渠道
- **限时/限窗访问源**（接口即将下线、快照窗口有限）→ 先取数保底，按 `SKILL.md` 基线顺序条在出结论前补齐口径
- **可得性未知**：先做一轮低成本可得性探针（每类只试一个入口），再回到第 3 步排序

**第 3 步排序时看两件事**，它们最容易被低估：

- **一份材料能覆盖几期**：很多定期报表**自带上一期的对照数**，所以 N 份材料最多给出 `2N` 个期次单元。但**实际覆盖的唯一期数是这些期次的集合基数**：连着取的 N 份（`2022,2021`、`2023,2022`、`2024,2023`…）互相重叠，唯一期数是 `N+1` 而不是 `2N`；只有各份的两期互不重叠时才接近 `2N`。**排序要按唯一期数算，不是按份数×2**。同时是个坑：把每份的两期都当独立数据累加，会把重叠期算两次
- **同一总体有几个正交入口**：同一批对象常能从多个维度分别枚举（按类别、按地域、按时间…）。**分别枚举再取并集**，比只走一个维度更全——单一维度总会漏掉未被该维度收录的部分。并集要按稳定标识去重（不是按内容，见上「你自己写的名字匹配」）；并集计数 `|A∪B|` 与交集 `|A∩B|` 的总体下界语义、召回分母完备性及 capture–recapture 独立性约束见上§二「第三方数据集实体消歧与召回分母」

两条配套：

- **解析脚手架搭一次**（`fetch` + 流式读 + 按名取列 + 自校验），别每个源重写一遍——重写就会漏
- **交付物的骨架从登记表派生**（数据源表、证据表、导航），不要每轮手改——手改的那份最后一定过时

## 四、把无产出也记下来

四种分开写：**在声明的检索边界内未命中**（记登记机关或数据库、用了哪些别名、时间窗、有没有翻页或结果上限——它支持的是边界内未命中，不是不存在证明）、**取到但不足以关闭**（只有标题摘要、正文删节、字段范围不足、版本冲突、真实性无法核验）、**被挡住**（记已尝试动作与下一步解封路径）、**没走**。这四种都不构成闭合判断，按 `SKILL.md` 覆盖矩阵裁决哪条主张还差什么（防将后三种混写为未命中的细则见 `references/public-disclosure-channels.md` §三）。

每个走过的渠道留一行：查了哪个机构/库、用了哪些别名、时间窗、有没有翻页或结果上限、结果按 `SKILL.md` 的状态词记。这不是流程负担——它是下一次的起点。没有它，下一次会把这次走过的路重走一遍，而「被挡住」会被误读成"查过了没有"。

## 五、多轮 Program 模式与 Closeout 展开细则

### Program 质量基础设施前置与轮起点对账

本节的统一原则是**质量基础设施前置**：charter/estimand/口径先于抓取（默认序——换序仍走上文"基线顺序"条的既有例外与记录义务，限窗源可先抓后立口径，但承重结论前必须冻结）、渲染管线始于第一张图、载体登记始于第二载体；写作基准先于初稿、读者版/工作版分离在满足适用条件且 owner 同意时同样前置（这两项的适用条件、时点与授权门归 `tighten-doc`，此处只是指针不另立规则）。这组前置针对的是一次多轮 program 复盘中实际观察到的返工类型——事后补都付过纠偏成本。初始证据来自一次多轮组织调研的复盘：该 program 最大的两类返工——发布载体不同步（跨多会话被反复纠正）与每轮由用户重述「目标是什么/做到哪了」——都不是规则缺失，而是轮节拍上缺机械检查点。

- **state note 单写者与并发/半成品恢复**：无则本轮建立；有则先对账再定本轮范围，让「今天目标完成了么」可即答；**发现多份 state note 或内容分叉时，先对账合一再开工**，不得任选一份继续。note 按**单写者假设**运作：同一时刻只有一个会话推进 program，开工时在 note 记「第 N 轮开工 + 计划动的载体」（这本身是一次写入，同样更新最后更新轮次），此后每次写回前核对最后更新轮次仍是自己上次写入的值——不一致说明有并发写入，停下对账（并行推进须显式分工与隔离，归并发执行类技能）；**重启会话看到开工记录而 covered-through 未推进 = 上轮做了一半**，先确认原会话确已终止（不能确认就问用户，不得径直接管），再盘点半成品载体继续，不得当作稳定产物。program-state note 与载体登记表、零损清单一样是**工作记录**：随工作版或访问受控的工作区存放，不进 reader-facing 发布目录，整目录发布/分享前先排除。
- **口径变更版本化**：(2) 本轮 estimand 与口径是否与既往轮一致——**口径变更不是记一句就完**：变更须版本化（新旧口径并记），列出受影响的既有结论/覆盖矩阵行/派生物并逐项重开或显式封存；covered-through 按口径分支分别记录，不得用一个全局水位横跨两个口径；不同口径的数字不得混入同一结论，加脚注不算处置（同口径纪律见上"跨期可比性向量与编码迁移"）。
- **`grounded@第N轮` 时效与降级**：**继承的是原主张原文与其口径**——任何改写、聚合、外推或口径迁移都构成新主张，按硬规则本轮重新 grounding，不得挂在旧证据行下。但**历史 grounded ≠ 当前仍 grounded**：来源内容可能已更新，时效敏感的主张（覆盖预检里标了时效类别的）在载重引用前按其时效要求复核或复取；未复核的继承行标「第 N 轮取回、未复核当前版本」。上轮证据表行缺链接或缺摘录、或来源已不可达且结论载重时，按既有规则降级或本轮重取。
- **载体登记表谓词与退役动作**：从此每轮只要动了任一 active 载体，收尾跑一次机械的载体一致性校验（脚本或逐行核对清单皆可，但要可判定）；校验器先按上面"检查器自己会骗你"的规则自测；**校验谓词钉在结构与实体上，且对承载性字段比对值/单位/口径/限定**及其宿主对应关系**（哪个值挂在哪个实体/系列/行上——值集合都在但对应关系接错同样判红；同一字段跨载体冲突判红），并核输入身份与新鲜度；不钉在文件名或标题词表上，也不满足于"实体在场"的存在性检查**——载体改名后，词表谓词要么误报（假红），要么在校验器仍读陈旧文件或按名跳过时静默通过（假绿），后者更危险。**载体退役解除同步义务，但退役是动作不是宣称**：以只读标旧或重定向实现（`superseded` 须记后继指针），之后才能改状态；**已暴露的载体不得标 `ephemeral` 逃逸同步（生成过共享链接、发给过他人、放入过共享位置即算暴露，不以"有没有人看过"判定）**；带协作评论的载体退役不删除（comment-safe 红线归 `tighten-doc`），删除须用户明确授权；仍在流通的旧载体不因"不想再同步"而退役。单载体交付无本条义务。
- **暴露面 provisional 通道与内部轮收尾**：正式传播或供决策使用：暴露面按 Closeout 章的表族收尾；**owner 索要或同意先行过目时，未闭合数字走 provisional 通道**——限具名收件人**且载体访问面同样只限这些收件人**（放进继承组织可见权限的云文档不算具名，先收权限或换载体）、醒目标「未闭合 / 不得据此决策或转发」、附当前证据状态，并把这次暴露记进 state note，不触发全表族；扩大访问面前先补齐交付收尾；一旦发生转发、决策引用或受众扩大，先补齐交付收尾再继续；provisional 不是自授的 Closeout 绕行道；纯内部的取数、管线修复轮：至少更新 program-state note、受影响的覆盖矩阵行与负结果常设节（「语料中无 / 未找到可靠来源 / 走过但无产出的渠道」跨轮累积防重挖，见上§四；抓取失败格如实留空或记状态，不得用估计值填补）。

### Closeout 过程自省与呈现结构细则

- 上面几张表是读者判断可信度所需的（覆盖矩阵、证据表、estimand、走查记录、自评）；**研究者犯了什么错、怎么发现的、下次怎么避免，不是**——读者要结论、出处、口径与限制，不要实验日志。多轮调研最易违反：每轮把本轮修订追加到同一份产物，过程叙述越积越多。两个正确去处：**修订后的结论就地改写正文**（连同口径与限制），**可迁移的方法教训沉淀进技能**；都不是在末尾加一节轮次日志。
- 当结论的**形式**本身在多说——多对多画成一对一、推断排版成结论、下界写成计数——**必须改结构**（拆开、改表头、降级措辞、整段撤回）；**不得**只在旁边补一句"这是解读不是验证"就当处置完毕——读者仍按结构去读。判据：**把免责声明删掉，剩下的还在主张什么**——仍超出证据就改它。免责声明只对"结构正确但证据不足"有效。
