# Coverage-exhaustion traps — worked failure shapes

Companion to the **`digest-masks-corpus trap`** Core Rule in `SKILL.md` (under *Evidence, RCA, charter & attribution*). That Core Rule carries the **gates + triggers** (when an "exhausted / complete / no-gap / fully-extracted" claim is unsupported, and what closes it). This file carries two things: the **relocated gate detail for variants (a0) and (4)** — the executable obligation text moved here from the Core Rule so the entrypoint stays at gate altitude (the Core Rule keeps the variant names and a pointer) — and the **recurrence-memory** for the core form and variants (a)/(b)/(c): the concrete historical failure shapes that justify each gate, plus the fuller worked examples. Read it when you are about to make such a claim and want the concrete shape of how each variant goes wrong, or when you need the (a0)/(4) obligation text.

The trap has one core form and variants (a)/(b)/(c) as failure shapes; the Core Rule's walked enumeration adds (a0) and standing gate (4) to the same fix family, and this file carries their relocated gate detail. The core form and variants (a)/(b) share one fix — **enumerate the real underlying artifact and mark each unit `read`/`skipped`, rather than trusting the digest**. Variant (c) is the case where *no artifact masked anything*: the **source-class universe itself was never enumerated**, so its fix is to enumerate the class taxonomy instead.

## Core — digest exhaustion ≠ repo exhaustion

The digest (a high-quality maintainer `AGENTS.md`/`CLAUDE.md`, README, CONTRIBUTING, or architecture/design doc) and the underlying code are distinct source classes; a strong digest masks how much code went unread.

**Failure shape:** deep-read a 50KB `AGENTS.md`, land its lessons, write "extraction exhausted" while ~hundreds of KLOC are unread, and a user has to ask "你没看代码么 / did you read the code".

Note on depth: the code-corpus sweep is usually inventory + owner-mapping + novelty-spot depth, not line-by-line — but it must be a **closed register row**, and is commonly low-yield because the digest already distilled the reusable layer. Record that outcome honestly rather than skipping the row.

## Variant (a) — self-retrospective form (the digest is your OWN output)

In a task / session / multi-batch retrospective the same trap fires with the agent's own artifacts as the digest: prior retro summaries, MR / commit *descriptions*, and project-memory notes *about* the work are a lossy digest of the actual change set, not the change set. Reading your own summaries back and finding nothing new is NOT evidence the diffs hold nothing — and a fact recorded only at the project-memory layer is not the same as a lesson promoted to the owning shared skill.

**Failure shape:** declare a multi-repo program "fully summarized" from MR descriptions and self-notes while the real diffs still carry reusable lessons (a locale-stable manifest-sort fix, a per-surface-redaction refinement) that were noted at the project layer but never promoted, and a user has to ask "根据实际变更核查 / 不要只看 comment".

## Variant (b) — benchmark / no-gap form (the conclusion is "we already cover this")

When the source is an external artifact you are benchmarking to decide whether WE must extract, a "no gap / already covered / it converges with what we already have" conclusion is ALSO a coverage claim under this trap. The digest here is the source's **overview / README / feature-docs / commit-messages — prose written to *advertise* a feature** — which systematically omits the very safety mechanics worth borrowing. Concluding "no new lesson" requires reading the source's **load-bearing decision surface**: the actual decision rules, the claim-vs-ground-truth checks, the data-loss guards. Where that surface is code separate from the docs, read the code; where the load-bearing artifact is *itself* executable prose (a skill's own `SKILL.md`, a standards/spec doc with no code), read THAT rule surface in full — not the overview of it — and scope the no-gap claim to the artifact actually read.

**Failure shape:** "this external self-maintenance design is already covered, nothing to extract" claimed twice from its feature-docs + commit messages, until a user said "真实看对方实现逻辑 / read the actual implementation" and the code revealed two real gaps (a claim-vs-ground-truth reconciliation and a package-integrity guard) the docs never surfaced.

## Variant (c) — channel-taxonomy form (nothing masked it; the class set was never listed)

The three shapes above all have a **digest standing in front of a corpus you could already reach**. This variant has no digest and no corpus-in-hand: the claim is that an *acquisition channel set* is exhausted, and it fails because the **taxonomy of channel classes was never enumerated** — so the agent kept searching harder *inside* the two or three classes it had thought of. The tell that separates it from the core form: each round surfaces a **class the agent had never considered**, not another artifact within a known class.

Its fix is therefore not "read the real artifact" but **walk a seed list of channel classes to catch the ones never considered, and then scope the claim to what was actually walked** — the seed list is not a universe, so it licenses no exhaustion claim; what makes the output falsifiable is recording each class's search boundary and which classes were not walked, because otherwise "I could not find more" and "there is no more" are indistinguishable. Closure and downgrade belong to the owning skill's existing coverage gate, not to a status vocabulary invented here.

**Failure shape:** an agent researching one organization from public sources declares "the public channels are mined out" five separate times; each time the user pushes back, a **previously unconsidered channel class** lands major evidence (an archive route around a bot-block, a regulator's bulk dataset, a mandatory-disclosure regime, another jurisdiction's statutory filings, a filing the organization voluntarily publishes on its own site). No artifact was hiding these — they were never on a list. The domain-side channel taxonomy lives with the research owner (`skills/multi-perspective-research/references/public-disclosure-channels.md`, repo-root relative); what belongs here is the recurrence memory that an exhaustion claim over a *channel set* needs a walked class list, not more effort inside the known classes.

## Variant (a0) — produced-artifact + next-run-delta (relocated gate detail)

**Firing point: for a task/session retrospective, this variant fires at CHARTER time — the produced-artifact row (i) enters the charter's evidence plan as its FIRST source class (see the Evidence plan field in `source-to-skill-extraction.md`), while the next-run-delta row (ii) is a separate required charter/closeout record, not a source class — not only when an exhausted/complete claim is about to be made** (the original anchor, kept as backstop). Observed failure shape of the late anchor: a 7-session program retro that never claimed "exhausted" walked past this gate entirely, took only correction turns as evidence, and landed zero method/craft lessons while r-series reports and a benchmark corpus sat unread in the project.

When the source is a task/session that PRODUCED runnable artifacts (scripts, commands, queries, configs, fixtures), two rows are required and neither substitutes for the other: **(i)** the produced artifacts are enumerated as their own source class in the **source register** (existing status vocabulary — `read`/`deep-read`/`excluded`/`routed`, with "project-specific only" recorded as the *reason* on an `excluded` row, never as a new status), and each reusable technique found in them gets a row in the **provenance-to-target diff** under its existing vocabulary (`landed`/`routed`/`downgraded`/`pending`) — **attaching the artifacts to a deliverable, or archiving them in the project, is NOT `landed`**, because a bundle hanging off one document is unreachable from the next project; and **(ii)** a **next-run delta** row in the source register whose fields are: what this run's cost was actually spent on, what the next run of this task shape must do IN WHAT ORDER, and which prerequisites must hold regardless of order — a sequencing lesson is a counterfactual about ordering, not an artifact, so the per-artifact sweep structurally cannot surface it. The framing trap this closes: extraction defaults to asking "what rules did we learn" (declarative) and never asks "what would we do differently, in what order" (procedural), so a session whose most reusable assets were working code and a better sequence lands only prose rules and passes every gate.

## Gate (4) — the per-item verdict-disposition obligation (relocated gate detail)

The verdict owes a **per-item disposition row EVEN WHEN THE ROUND LANDS NOTHING** (no commit fires to catch an advertising-level verdict): each row records the load-bearing surface actually read (section/line/rule — NOT headers/`When to invoke` blurb/feature-list), the owning organization artifact (`file:rule`) OR `route-to-tool` / `out-of-scope: <reason>`, and for `covered` the mechanical firing path. A `quick`/`light`/`sweep`/`triage` framing does **NOT** waive the load-bearing read. Record the row on a **concrete surface** — the triage turn's final response OR persistent scratch / `source-register`, never chat-ephemeral. (Honesty: absent a host/review hook checking that surface, this stays recognition-dependent — salience, not mechanical enforcement.) A repeated user "深度分析了么 / did you deep-read" across rounds is the recurrence signal that an advertising-level verdict shipped; treat it as a validation-gate defect.
