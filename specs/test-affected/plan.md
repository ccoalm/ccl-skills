## Role

`make test-affected` (`scripts/select-affected-tests.py`, previewed via `make test-affected-plan`) picks the preflight checks and test suites most likely to catch a regression in the files you changed, and runs them in seconds to a few minutes. It is **advisory feedback during local iteration**, not a gate:

- **Repository and directory gates remain required before push or PR:**
  - `make test` for changes to `AGENTS.md`, `README.md`, `docs/`, `skills/`, `hooks/`, `scripts/`, or plugin manifests (`AGENTS.md`).
  - Focused suites for touched scripts and packages (`npm --prefix packages/ccl-skills-npm test` and `npm --prefix packages/ccl-skills-npm run test:pack`).
  - `python3 scripts/check-public-sanitization.py .` and `bash skills/skill-extraction-workflow/scripts/test_check_ccl_regressions.sh --heavy-only` when touching shared skill text, plus `python3 skills/skill-extraction-workflow/scripts/check_review_evidence_present.py` before opening or updating a PR that touches `skills/` or `hooks/`.
  - `make test-verify-sandbox` when touching `scripts/verify-sandbox/` (local Docker check; neither `make test` nor CI runs it).
- **CI runs every required lane independently and never calls `select-affected-tests.py`.**
- **Output states the boundary explicitly.** `--run` ends with `advisory: run make test before push` after `select_affected_tests_done` or `select_affected_tests_failed: exit=<code>` (never `ok`). `--dry-run` ends with `# advisory: run make test before push`. `--json` writes UTF-8/ASCII JSON bytes carrying `"advisory": "advisory: run make test before push"`.

## Why not a sound selector

Two gate-grade designs failed adversarial review:

- **Suite-level claiming "never under-selects" (`specs/test-affected/evidence/review-R1.json`):** 33 findings, 15 of them suites reading inputs not linked in the path map.
- **Lane-level (`specs/test-affected/evidence/design-review-D1.json`):** 21 findings, including cross-directory inputs (`skills/claude-code-review/` checked by `test_code_review_identity.sh`, root `AGENTS.md` read by `test_update_review_plan_intent.sh`), focused tests outside Makefile lanes (`test_kimi_packet_mcp.py`), and checks invoked outside `make test`.

Maintaining a sound whole-repository dependency graph duplicates `make test` and CI at higher maintenance cost. Dropping the soundness claim preserves fast inner-loop signal without weakening any repository gate.

**Mechanism-operability check (claim withdrawal):** Nothing in `.github/workflows/`, `hooks/`, `.githooks/`, `Makefile` `test`, or `AGENTS.md` invokes `select-affected-tests.py` as an enforcement or completion gate. `scripts/test_select_affected_tests.py` stays registered in `make test-repo-gates` to test the tool itself. No downstream control rested on the withdrawn soundness claim.

## Behavior

- **Makefile & CLI boundary:** `Makefile` defines `test-affected` (`python3 scripts/select-affected-tests.py --repo . --run`) and `test-affected-plan` (`python3 scripts/select-affected-tests.py --repo . --dry-run`) as literal zero-interpolation commands. When either target is in `MAKECMDGOALS`, `Makefile` unexports all command-line variables before child execution and fails closed with `$(error ...)` on any command-line override other than literal `FULL=1` (inspected via `$(value FULL)` without Make expansion). Callers pass flags directly to `scripts/select-affected-tests.py`, or supply environment prefixes (`FULL=1`, `SUITE_JOBS`, `CCL_SKILL_BASE_REF`, `CCL_SKILL_DEFAULT_BASE_REF`) before `make` through POSIX `envp`.
- **Selection and runner dispatch:**
  - Unmapped `hooks/` changes run every `hooks/` suite parsed from executable `Makefile` recipes, plus installer and npm checks. Core `skills/code-review/scripts/` changes derive shard membership from `Makefile`.
  - Input paths collapse redundant `/` and `.` segments before dedicated-runner and path-map lookups so aliases such as `skills/code-review/scripts/./test_review_gate_abort_leak.sh` cannot bypass slow-suite exclusions.
  - A changed suite (`.py` or `.sh` only) runs itself, and a changed `<stem>.{py,sh}` runs existing sibling `test_<stem>.{py,sh}` (`-` mapped to `_`), except dedicated suites (`test_review_gate_abort_leak.sh`, `test_check_ccl_regressions.sh`, individual `heavy_tests` parsed comment-safely from `test_check_ccl_regressions.sh`, `test_gen_report.py`, `scripts/verify-sandbox/test.sh`, and `eval/test_*.py`), which stay on their serial/slow/unittest paths. Changing `eval/<mod>.py` or `eval/test_<mod>.py` appends `eval.test_<mod>` to `python3 -m unittest`.
  - Selected `.py` suites are read via `_read_contained_regular_bytes` and parsed with `ast.parse`; a module runs directly via `python3` only when a top-level runner/exit call (`unittest.main`, `pytest.main`, `sys.exit`, `os._exit`, `SystemExit`) or an `if __name__ == "__main__":` guard containing executable statements beyond `pass`, constants, or `print`/`stdout.write`/`stderr.write` stubs is present — preserving custom `__main__` harnesses (`verify_cases()`) while routing pytest modules (even those with top-level `subprocess.run()` setup or print-only `__main__`) serially via `python3 -m pytest -q <suite>`.
- **Containment and drift:**
  - `_open_contained_regular_fd` walks every relative directory segment inside `repo_root.resolve(strict=True)` via `O_RDONLY | O_DIRECTORY | O_NOFOLLOW` `dir_fd`s and opens the leaf via `O_RDONLY | O_NOFOLLOW | O_NONBLOCK` + `fstat` `S_ISREG`, refusing symlinked parent directories, leaf symlinks, FIFOs, and directories without blocking.
  - `build_test_plan` validates all generated `preflight_commands`, `parallel_suites` (`scripts/run-parallel-suites.sh`), `serial_commands`, `Makefile`/`GNUmakefile`/`makefile`, and `makefile_recipe_paths()` (which parses executable `Makefile` recipe command segments, flags unresolved `$` script/module operands as unsafe, extracts script operands regardless of top-level directory, and rejects scripts replaced by directories). Any `unsafe` path sets `unsafe_blocked`: fallback escalation is refused, `--json` and `--dry-run` exit `2` (emitting `(exit 2)` instead of runnable commands), and `execute_plan` exits `2` before running anything.
  - At execution time, `execute_plan` re-verifies every preflight and serial command via `_verify_command_containment`, and executes `parallel_suites` in a bounded in-process worker pool (`--jobs` or `SUITE_JOBS`, rejecting `< 1` with exit `2`) that prepares each worker's temp directory, private `gitconfig`, and log descriptor first, verifies `_verify_contained_regular_file` immediately before `subprocess.Popen([runner_bin, "--", suite], ...)`, and terminates `--` option parsing for dash-prefixed paths (userspace verification before `execve`; simultaneous kernel-level swaps by a local same-UID writer remain outside userspace scope, and suites rely on `__file__`/`BASH_SOURCE[0]` path resolution rather than `/dev/fd/N`).
  - `makefile_suites()` records both path-form suites and dotted `eval.test_*` modules (`eval/test_*.py`) from executable `Makefile` recipes. Deleted registered suites populate `missing_suites`, emit a `selector-drift` note, and escalate to `make -f Makefile test-repo-gates`, `test-regressions-fast`, `test-code-review-1`, and `test-code-review-2`.
- **Change discovery, Git isolation, and snapshot pinning:**
  - `verify_repo_root()` runs unconditionally in all modes (including `--files`), requiring `.git` at `--repo` and `git rev-parse --show-toplevel == root` (preserving `\r`-suffixed directory names) and converting missing-`git` `OSError` failures into exit `2`.
  - Discovery runs `git -c core.fsmonitor=false -c core.hooksPath=/dev/null -C <repo>` with scrubbed `GIT_REPOSITORY_ROUTING_ENV`, `GIT_CONFIG*`, and `GIT_TRACE*`, preserving `~/.gitconfig` `safe.directory` trust while preventing `core.fsmonitor` execution and `GIT_TRACE` stderr false positives. It unions `git diff <merge_base_sha> <head_sha> --`, `git diff --cached <head_sha> --`, `git diff --`, and `git ls-files --others --exclude-standard` via `-z` and `os.fsdecode` (`--no-renames`, `--no-ext-diff`).
  - Child execution (`_clean_child_env`) and `--dry-run` strip Make (`MAKEFLAGS`, `MAKEFILES`, `MAKEOVERRIDES`, etc.) and Git overrides, set `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_SYSTEM=/dev/null`, `GIT_TERMINAL_PROMPT=0`, point `GIT_TEMPLATE_DIR` at an isolated `template/` directory containing only `info/` (no `hooks/` and no `gitconfig`), and give each serial command and parallel worker its own private `GIT_CONFIG_GLOBAL` file populated only with `safe.directory = <repo_root.resolve()>`.
  - Explicit `--base-ref` and `CCL_SKILL_BASE_REF` apply in both discovery and `--files` modes. Automatic resolution canonicalizes `<remote>/<branch>` to `refs/remotes/<remote>/<branch>`, checks exact `%(refname)` matches via `git for-each-ref` while failing closed (`exit 2`) on `for-each-ref` `stderr` warnings, `rev-parse --git-path` failures, or broken loose ref files, picks the candidate with the smallest `rev-list --count <mb>..<head_sha>`, and forwards pinned `resolved_base_sha` and `head_sha` to `shared_git_surface_gate.py --base-ref <base_sha> --head-ref <head_sha>` and child `CCL_SKILL_BASE_REF`.
- **Execution, cancellation, and output:**
  - `_run_cmd` and `_run_parallel_suites_bounded` install `SIGINT`/`SIGTERM`/`SIGHUP` handlers before `subprocess.Popen(..., start_new_session=True)`, re-check `received_sig` after restoring handlers, prune retired process-group IDs once `_pgid_has_live_members(pgid)` is false, reap live groups across signal cancellation (`128 + sig`), `Popen` launch failure (`126`/`127`), and `containment_abort` (`2`), and escalate to `SIGKILL` after `1.5s` when any leader or descendant ignores `SIGTERM`.
  - Parallel workers stream captured logs for both passing and failing suites in 64 KiB binary chunks to `sys.stdout.buffer` (avoiding full-file memory buffering and `PYTHONIOENCODING=ascii` decode crashes) and emit `regression_test_timing: test=<suite> seconds=<sec> status=<rc>` lines.
  - `--dry-run` emits `set -euo pipefail`, standalone `_affected_tpl="$(mktemp -d)"` (so `mktemp` failure aborts immediately), `cd -- <repo>`, and `--` before parallel suite paths; `--json` writes UTF-8 bytes directly to `sys.stdout.buffer` (`ensure_ascii=True`, `\x00hex:<hex>` for raw non-UTF-8 bytes, safe under `PYTHONIOENCODING=ascii` and `PYTHONIOENCODING=utf-16`); `_terminal_safe` scrubs surrogates and C0/DEL/C1 controls; `BrokenPipeError` flushes inside the handler and exits `141`.

## Security four questions

1. **Caller-controllable inputs:** Environment variables and CLI flags (`FULL`, `SUITE_JOBS`, `CCL_SKILL_DEFAULT_BASE_REF`, `CCL_SKILL_BASE_REF`, `--repo`, `--base-ref`, `--default-base-ref`, `--files`, `--jobs`), inherited environment variables (`GIT_*`, `MAKEFLAGS`, `MAKEFILES`), and worktree paths/symlinks/FIFOs/filenames.
2. **Blast radius if malformed or forged:** Make command-line overrides could evaluate `$(...)` or truncate `$` tokens; inherited `MAKEFILES`, `GIT_INDEX_FILE`/`GIT_DIR`/`GIT_NO_REPLACE_OBJECTS`/`GIT_TEMPLATE_DIR`, `~/.gitconfig` `core.hooksPath`, or `core.fsmonitor` could execute injected recipes/hooks or corrupt caller Git state; sharing one `GIT_CONFIG_GLOBAL` inside `GIT_TEMPLATE_DIR` leaks `git config --global` across suites; prefix ref matches, broken loose refs, or `rev-parse --git-path` failures could misselect bases; a FIFO, symlinked parent directory, `GNUmakefile` symlink, unresolved `$` or directory fallback script operand, or queued parallel symlink swap could hang planning or execute external files; raw ANSI/newline bytes in filenames could spoof terminal lines or inject commands into `--dry-run`.
3. **Trust roots:** `Makefile` `unexport` + `$(error ...)` blocking Make command-line overrides besides literal `FULL=1`; `--repo` verified unconditionally via `.git` + `git rev-parse --show-toplevel`; discovery run with `-c core.fsmonitor=false -c core.hooksPath=/dev/null` and `GIT_TRACE*` scrubbed; per-suite `GIT_CONFIG_GLOBAL` outside `GIT_TEMPLATE_DIR` carrying only `safe.directory`; exact ref matching + SHA-pinned `resolved_base_sha` and `head_sha`; `O_NOFOLLOW` `dir_fd` regular-file verification across planning, `--dry-run`, per-slot parallel launch, and `make -f Makefile` / serial dispatch.
4. **Negative cases:** Retired `AFFECTED_ARGS='$(warning ...)'` and command-line `CCL_SKILL_BASE_REF` are rejected without Make expansion while env `$5` refs survive (`test_makefile_literal_recipes_preserve_dollar_and_avoid_make_arg_expansion`); `MAKEFILES`, `core.fsmonitor`, `GIT_INDEX_FILE`, `GIT_TEMPLATE_DIR`, and per-suite `GIT_CONFIG_GLOBAL` are isolated (`test_git_isolation_disables_fsmonitor_and_isolates_child_templates_and_global_hooks`, `test_resolved_base_snapshot_reaches_child_subprocess_and_strips_overrides`); FIFO `Makefile`, symlinked parent dir, `GNUmakefile` symlink, directory/`tools/`/`$(SCRIPTS_DIR)` fallback operands, queued `--jobs 1` swap + descendant cleanup, `-dash/` suite, parallel `Popen` failure reaping, and `tests/test_widget.py` pytest swap are handled safely (`test_containment_fifo_gnumakefile_recipe_scripts_queued_parallel_pytest_and_dry_run`); `GIT_TRACE=1`, `rev-parse --git-path` failure, descendant refs, broken loose refs, and `--base-ref=--independent` behave deterministically (`test_base_resolution_exact_ref_broken_loose_ref_shadow_unrelated_and_files_env`); serial/launch/restore/parallel `SIGTERM` and PGID retirement pass (`test_sigterm_cancellation_escalates_on_term_ignoring_child_and_descendant`).
