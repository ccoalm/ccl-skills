# 039 — 设计先行的收缩轮（三批次）

Status: **design**（开轮计划；无技能变更落地）。写操作准入枚举与退役状态属共享闸语义变更，本文件被评审前不落地实现。

**成功判据：本 program 不自判通过。** 它产出 30 份处置及其 diff，由用户裁决这一轮值不值。

这是第三版判据，前两版都被外部对抗击穿。换法依据见下方「判据为何不再自判」——不是放弃判据，是把评判权从作者手里拿走，因为作者自判正是那 16 条 findings 共同的攻击面。

判据既不是字节也不是能力。取 **N = 30** 条既有规则，在看任何一条之前冻结抽样（自台账中两个主导 owner 的 126 行按固定种子随机抽取，种子与名单写入本文件）。每条必须产出：

| 要素 | 要求 |
| --- | --- |
| 终态 | `keep` / `superseded` / `休眠` / `收窄` 四选一，无「待定」 |
| 证据 | `keep` 须给触发路径（哪个决策点机械触达它）；其余三态须给零损失义务表 |
| owner | 裁定落在哪个技能/引用的哪一节 |
| 执行 | 判「要动」的，本 program 内动完，不留 follow-up |

终态分布连同各自的证据与 diff 一并交付，**本文件不解释它意味着什么**——不说哪种分布"有信息量"，也不说它证实或证伪了任何假设。全 `keep`、全 `superseded`、或任何中间分布，都只是被记录的事实；它值不值、说明什么，由用户判断。

### 判据为何不再自判

前两版判据分别是「仓库净字节下降」与「30 条处置完毕即通过」。五轮外部对抗共 **16 条 P1，全部属同一类**：找到一条「不真处置任何东西也能报通过」的路径。逐条堵完之后，第五轮仍能找出新的。

按本仓自有的规则，同类发现跨轮复现是**设计信号而非补丁信号**——该问这个能力该不该存在，而不是再补一个洞。这里该删的能力就是**自判通过**：攻击面全部来自「作者既处置又宣布结果」，只要这个状态存在，就总有下一条路径。

删掉之后：

- 交付物是 **30 份处置记录 + 实际产生的 diff**，都可直接读，不需要相信任何声明。
- 没有可伪造的通过态，因此不必再为它加签署、加阈值、加阻断条款；一整套围绕「通过」的判定机器随之不必存在。
- 独立通道回到它真正能做的事：复核单条处置的归类与证据是否成立，而不是给整个 program 发绿灯。

保留的硬约束仍然有效，因为它们约束的是**产出什么**而非**宣布什么**：抽样冻结、判据冻结、分母恒 30、终态绑定动作、`证据不足` 为非终态、零损失义务表。

三条被这个判据替换掉的旧候选，及其不可用的原因：

- 「`skills/` 净字节下降」——代理指标，可被位移与压缩措辞绕过（本仓已证实在闸下会位移），且会把诚实的空手结论判为失败。
- 「建立双向可判的能力」——用「造出一套判定机制」度量一个反元层增肥的 program，自我拆台。
- 两者并列——保留前者的全部缺陷。

仓库是否变小**降为观测量**：达标后照报全仓与 `skills/` 净字节，变小就报变小，没变小就报「冗余比假设的少」，两者都不影响判据。

**这条判据的最重要性质：它让机制变成可选的。** 若 30 条能手工处置完，则 `write_op` 字段、行为探针、台账回放**一个都不必造**。机制只有在手工处置被证明不可扩展时才获得正当性。

## 背景：仓库事实与外部机制交叉着看

不是「仓库出诊断、外部出机制」两条平行车道。承重的结论都出在交叉处：一条仓库事实只有配上外部机制才知道它意味着什么，一条外部机制只有配上仓库事实才知道它在这儿成不成立。先列各自的量，再列交叉结论（第五节），本轮设计由交叉结论决定。

**单一钉点：`5146b3b`（开轮时的 `origin/dev`）。**本文件的全部事实——增删比、体量分层、台账计数、specs 分类、抽样框——都由该 SHA 的 git 对象计算，**不读工作树、不算到 HEAD、也不随 `dev` 前进而追平**。

> **钉点与当前 dev 已分叉，如实标注。**本轮进行期间 037 落地，`dev` 前进到 `e139424`。在新 base 下：增删比 12.9 → 12.3（added 9157→9295、deleted 708→754），台账 183 → 186 行，两 owner 池 126 → 129，`specs/` 29 → 30 轮。**本文件不追平这些数**：诊断是在开轮态做出的，抽样冻结的意义就是钉住不可变 blob——每次 `dev` 前进就重算会让「冻结」失去意义，也违反本文件自己的「不得重抽」。读者应把下列数字读作**开轮时的仓库状态**，不是当前状态；方向性结论（增长单向、元层偏重）在两个钉点下都成立。

**所有 base 指标一律由 `5146b3b` 的 git 对象计算**；候选态指标在取证文件中单列标注（本候选只动 `specs/`，两者数值相同）。下列指标均可直接复跑复核，未编辑输出见取证文件。

### 二、增长单向，但此前的量级数是错的

仓库做过一次 `git init` 重建，`chore: init ccl-skills` 一个 commit 把 79990 行整树快照记成新增。因此按全量 git 历史算出的增删比是**快照伪影**，必须剔除首个 commit：

| 口径 | added | deleted | 增删比 | 删除占新增 |
| --- | --- | --- | --- | --- |
| 含 re-init 快照（**不可用**） | 89147 | 708 | 125.9 : 1 | 0.79% |
| 剔除首个 commit（真实可观测增长） | **9157** | **708** | **12.9 : 1** | **7.7%** |

方向不变——每删 1 行加 13 行——但量级比先前记录的 139:1 / 0.7% 小一个数量级。本计划一律用 12.9:1，并且承认 re-init 之前的历史不可见，该口径只覆盖重建之后。

最大 entrypoint 为 `skills/skill-extraction-workflow/SKILL.md` = **122101 B**（119.2 KB），不受 re-init 影响，可直接核。

### 三、体量分层：元层与 domain 大致相当，增长偏向元层

「元层占多少」按不同分层给不同的数，所以给区间。分层按**交付物**：交付物是过程本身如何运转的记 meta，是产品制品的记 domain。

| 分层 | 静态体积 | 历史新增（含快照，仅作相对比较） |
| --- | --- | --- |
| 提炼 + 评审两包（不依赖分类判断） | **40.5%** | **51.1%** |
| meta 窄口径（+ 交付路由、风险分级、编辑隔离、并行分发、发布协调、契约覆盖） | 47.8% | 57.3% |
| meta + 四个边界包（测试策略、缺陷诊断、拷问、多视角调研） | 55.6% | 62.8% |
| domain 侧合计 | 44.4% | 37.2% |
静态体积一律按 **base 的 git 对象字节**计（`git ls-tree -r -l`），不用 `du`——早前报的 38.6% 是 `du -sk` 的文件系统块数，口径不同，已作废。两个流程包自己就占全仓 40.5%、并吃掉历史新增的一半。
区间宽度来自四个边界包的归属争议，其中只有测试策略量级显著（静态 5.7%）。**本计划不取单一数字**，承重的结论是三种口径下都成立的那条：元层与 domain 侧体量大致相当，而增长明显偏向元层。此表的新增列含 re-init 快照，只用于层间**相对**比较，不作绝对增长依据。

### 四、结论：缺的是目标模型

失败只会说「少了什么」，永远不说「这条多余」。判冗余需要一个「应该有什么」的目标模型，而仓库对自己的技能集没有目标模型——所以既有的「规则集不得单调增长」这条规则没有任何机制能执行它。

设计先行**不违反** evidence-first：设计产出目标与假设（该去为什么找证据），evidence-first 决定什么能变成可执行规则。仓库把两者混同，连带禁掉了设计那一半。

反向教训同时成立，不得因此把设计先行推过头：028 退役的那道闸是「设计得漂亮但判分器是正则」的假闸；而 self-sealing 信号、owner 被还原成 base、台账行绑不到 owner、merge 制造新轮这几类规避形态，书桌上推不出来，只能靠撞。**设计负责产出目标与删除依据，撞出来的仍归失败驱动。**

| 仓库事实 | 外部机制 | 交叉出的结论 |

| base 上 29 轮里 22 轮的交付物是流程或工具自身 | 元层投入自身也要有停止线：预注册投产窗口，窗口内无可测增益即暂停新建 | 仓库对元层投入没有任何速率约束。停止线是这套机制里**唯一约束速率**的部件，也是本 program 自身必须先接受的约束（见风险与停止线节）。 |

| 外部机制 | 本仓状态 | 结论 |
| --- | --- | --- |
| 影子回放 / 规则是否真被执行 | **已有正确形状，覆盖极窄**：`eval/body-compliance-eval.rb` 自述即「skill 已激活后，agent 是否真的应用了它的硬规则」，且支持 `--arm` 双臂对照。但覆盖是 12 probes / 仅 4 个 `requirement-*` 技能，元层 28 个技能一条没有；advisory，不阻断合并，需本机 claude CLI | **未建成，不是不可移植**。后续若要做可观测性，把探针扩到元层技能比等台账可回放更直接，且不依赖 038 |

## 诊断修正：不是无闸，是闸只管一面且没有对侧出口

「仓库只能加不能删是因为没有防膨胀的闸」——这个诊断是错的，实证如下：

- `scripts/check-size-budget.sh` **已经**对 entrypoint 与 always-on 注入层做净增长阻断（新建或跨过 severe 线即拒；已 severe 的只准平或缩）。
- 该闸**确实在运行**，有 applied-mutation 实证（见取证文件末节）：给已 severe 的入口追加约 3KB，`entrypoint_size_block` 与 `entrypoint_word_budget_block` 同时转红并点名该文件与具体字节数（122101 → 125103，见取证文件），复原后转绿，未突变的控制组始终绿。这是差分归因，不是文件头自述。
- 位移形态另有一条一手实例：038 的实现记录里，一条新规则原本写进 `SKILL.md`，被 `entrypoint_word_budget_block` 拦下，改落 `references/` 下的相邻小节，入口零字节增长。该记录判定为「闸提了个真意见，不是绕行」——就那一轮而言成立。此条依据的是 038 的记录文本，**未独立复核**。
- 但把这类事件放在 program 尺度看：`references/` 无闸，于是被拦下的增长**位移**而非消失。总量继续涨，入口读数却是干净的。

所以真因是四条缺失，不是缺一个字节闸：

1. **写操作没有枚举**——提炼轮唯一被建模的动作实质是 ADD；REINFORCE（同义、只增一次证据）与 NOOP（重复/无信息量/作用域不明）没有合法书写形态，agent 无处可去。
2. **规则没有状态**——全部隐式 active，缺可逆的休眠与 superseded 中间态，于是「留」与「删」成了仅有的两个选项，而删不可逆，所以永远选留。
3. **没有退役触发清单**——没有任何入口问「哪条现存规则该退役」。提炼的触发全是纠正驱动，而纠正驱动的枚举结构上到不了「本来就做对、可以合并复用」这条轴。
4. **没有判「这条规则还有没有用」的对照判据**——现有判据是「有这条 vs 没这条」，属空白对照，会把通用纪律的功劳算到专用规则头上。

**推论：不给 `references/` 加字节闸。** 那只会再位移一次（下一站是脚本注释、模板、示例）。杠杆在于给增长提供合法替代出口（REINFORCE / NOOP），并给存量规则开一个可逆的退出口（休眠 / superseded）。

## 交付

骨架是**先处置，再决定造不造机制**。本 program 只有一批：抽样处置。可能的后续工作列在其后，但不预设触发条件、不在本 program 内。

### 抽样处置（本 program 的全部交付）

1. **抽样：框现在钉死，种子由用户一次性提供**

   三版方法均在**任何槽位被处置之前**作废，理由都是**方法本身可被作者选择**，非对结果不满：`seed = 39` 是裸自由参数；`seed = int(base_sha[:8],16)` 里「哪个 SHA 是 base」由我宣布开轮时点决定；`seed = merge commit SHA` 看似不可预知，但**不可预知不等于不可重试**——本地可构造候选 merge 预览结果，再 rebase 或重开 PR 试到满意，且 ff / squash 可能根本不产生 merge commit。承重的性质是**不可重试**，不是不可预知。

   | 项 | 定义（现在即冻结） |
   | --- | --- |
   | 抽样框 | **不可变 blob**：git object `1fc647e2113db1a827611f2152d5de5a25847f33`（sha256 `b654f5ab…d09618`），即 `5146b3b` 上的 `references/source-register.md`。抽样只读这个 blob，**不读任何分支、merge tree 或工作树**，故 `dev` 前进、分支编辑、行增删或重排都影响不到成员与序号 |
   | 池 | 该 blob 中 `behavioral-evidence` 行且 owner ∈ {`skill-extraction-workflow`, `code-review`}，按文件出现顺序编号，共 **126** |
   | seed | `int(nonce[:8], 16)`，`nonce` = **由用户在处置开始时提供的一次性随机十六进制串**（≥8 位） |
   | 规模 | 30 |

   **为什么是用户提供的 nonce**：作者不生成、不预览、不能重试。**本 program 只索取一次 nonce**；若因任何理由出现第二次索取，本 program 即记为 `未完成` 并记录事由——「再来一个」正是重试的形态，必须可见。nonce 与其提供时刻一并逐字记入处置 commit。

   名单在拿到 nonce 后的第一个 commit 落盘，与 nonce、frame blob id、抽样器哈希、复算命令一并记录；在此之前处置不得开始。本文件与取证**均不含名单**——含即意味着我已算过。

2. **单元定义与分母（冻结）**：样本单元不是台账行，是台账行**指向的规则目标**——owner 包内可 `grep` 到的具体锚点（文件 + 小节标题或行首句）。解析在处置之前完成并记录：30 个序号 → 目标锚点。

   **分母恒为 30，不可缩。** 事后改变「什么算数」与事后裁剪判据是同一种规避，一并堵死：

   - 两行解析到同一目标 → 两个槽位**各自保留独立终态**，可以共用同一处置动作，但**不合并、不减分母**。
   - 解析不到唯一目标 → 该槽位记 `不可解析`；它不是一种终态，而是一个**未完成项**，使交付记为 `未完成`。
   - **不补抽、不重抽。** 若冻结判据在处置中被发现有缺陷，本 program 记为 **`未完成`** 并记录缺陷（是否就此收手由用户裁决，不由本文件自判）；修正后的判据须另行预注册为**新的**实验，**不得用来满足本 program**。

3. **终态判定条件（冻结，本节即冻结物，不是「将来写定」的承诺）**：按下列顺序逐条测试，**第一个成立者即为终态**，不得挑选：

   | 序 | 终态 | 成立条件（全部满足） |
   | --- | --- | --- |
   | 1 | `superseded` | 存在另一条现存规则或机械闸，其义务逐条覆盖本单元——即零损失义务表可填满且无 `intentionally-dropped` 行 |
   | 2 | `收窄` | 能举出至少一个具体情形：按当前措辞会触发，但触发是错的；该情形须写成一句可判定的断言 |
   | 3 | `keep` | 两项**同时**成立：(a) firing point 位于**目标文本之外**——某个会去取用它的决策点（closeout 走查行、validator、闸脚本、trigger 面），**引用自身文本不算**；(b) 有**可核验的因果制品**，三种形态之一，**判准是第三方无需相信起草方的叙述即可复核** |
   | 4 | `休眠` | 已按下方检索协议查过并留存检索记录，确认**不存在**落地后的触发证据 |
   | — | `证据不足`（**非终态**） | 检索协议无法执行、或结果不确定。触发补证——按同一协议补查后**重新套用同一冻结判据**。收口时仍停在本项的槽位使交付记为 **`未完成`**（机械状态，非评价）|

   **检索协议（冻结）**：三项检索一律**排除规则自身的定义文本与其引入 commit**——否则规则必然含有自己的行首句、`git log -S` 也必然命中它的引入，于是没有任何规则可判 `休眠`，全部非 keep 槽位都卡在非终态，这一轮永远走不完。排除后各项只数**引入之后、定义文本之外**的命中：

   1. `git log -S <锚点串> <引入commit>..HEAD`，排除引入 commit 本身：此后有无轮次引用或修改它。
   2. 全仓 grep 该锚点行首句与其失败类关键词，**排除定义文件的该处本身**：别处有无引用。
   3. 其 owner 包内及 `scripts/` 下有无以它为断言的测试或闸（定义文本本身不算断言）。

   **排除范围与检索词逐槽位先冻结，再检索**——否则一个执行者只排除定义那一行、另一个把整份文件都当定义排掉，同一条规则可得相反终态；而误判休眠的后果是**把一条仍在生效的规则挤出取用路径**，比误判 keep 更贵：

   - **定义跨度**：写死为「**blob object id** + 起止行号」，钉在不可变对象上（行号在可变分支上会漂移）。仅此区间算定义；**同一文件内该区间之外的出现照数为命中**。
   - **检索词按固定规则导出，不由作者挑**：必选串 = 定义跨度内**第一个句子的前 12 个词**，加上该跨度所属小节的标题串。二者机械可得，无裁量。
   - **附加检索词须先经独立通道同意**：作者可提议额外的同义/别名串，但须在**检索之前**由独立通道逐条同意；**未获同意的不得使用，双方对某个串是否该纳入有分歧的，该槽位直接判 `证据不足`**。这挡住「只挑定义里独有的措辞、从而保证零命中」——那是把裁量从检索时挪到选词时。
   - **改写与转述**：除 `git log -S` 的精确串外，另跑 `git log --follow -p` 查该跨度历史。**判定规则机械化**：该跨度的历史 diff 中出现过**除引入 commit 外的任何内容变更**，即算「曾被改写」→ 判 `证据不足`，不判 `休眠`。至于"是否语义等价"这类需要判断的转述，**一律不由作者裁定**：存疑即 `证据不足`。

   三项都执行完毕、且连同改写检查都无命中 → `休眠`；任一项无法执行 → `证据不足`。

   台账行的 `observed-failure` 字段**不参与**上述任一判定：它记录的是「当初有个失败促成了这条规则」，与「这条规则后来是否触发」无关。

   **`keep` 的落地后触发证据是本判据的承重条款。** 说不出「它落地之后真的改变过一个决定」的规则不得判 `keep`——但**不因此自动落到 `休眠`**：它退回有序判据重走。`休眠` 只在检索协议三项**全部执行完毕且均无命中**时成立，任一项跑不动即 `证据不足`（非终态、阻断通过）。取消这个自动转换，是因为它让作者可以绕过冻结的检索条件直接把槽位终态化。这堵死了「把 keep 定义成泛化的机械可达性、于是全判 keep、零工作量通过」这条路——全 keep 要求每一条都拿得出落地后的实际生效证据，那本身就是个强结论而非默认值。

   **(b) 的三种合格形态**（等价可证伪，任选其一）：

   | 形态 | 内容 | 第三方如何复核 |
   | --- | --- | --- |
   | 突变 | applied-removal **行为 oracle**：以该规则为唯一变量的双臂对照，观察**产出或决定本身**出现了规则所述的差异（如 `eval/body-compliance-eval.rb --arm` 两臂输出之别），未突变控制组绿。**被观察对象为随机性系统时另加统计控制**（见下） | 两臂输出直接读出「若无这条规则，那个产出不会是这样」，且该差异不能由随机性解释 |
   | 机器制品 | 当时由机器产出的输出，且必须显示**因果**而非仅**点名**：该制品指出一个**经由所述 firing point 而产生的具体决定**（闸因该规则拒绝了某次落地、CI 因它失败、评审通道因它给出 finding 并改变了处置）。**仅"提到了这条规则"不合格**；由**把该规则本身喂进提示词**而产出的制品也不合格——那是自证换了个外壳 | 读该制品能看出「若无这条规则，那个决定不会发生」 |
   | 他方改动 | 一处 diff，其改动可归因于该规则，且**作者不是该规则的作者** | 读 diff 与提交归属 |

   三者的共同判准是**不必相信起草方的叙述**。凡只能靠起草方自己的记述成立的，一律不合格。

   **随机性系统的统计控制（不加即不合格）**：被观察方若是采样式模型，单臂各跑一次、留下差异合意的那一对，形式上完全满足"唯一变量 + 观察行为"，但差异可能纯由随机生成造成。故优先用可确定性复放的观察点；做不到时按下列**四条全部满足**，缺一即 `证据不足`：

   1. **预注册清单先于任何一次运行落盘并留哈希**（提示词、解码参数、每臂运行次数、判定函数）。跑完再补写的清单不算。
   2. **判定函数唯一且写死**——不得用「以下任一成立即判有差异」这类可事后择取的形式。
   3. **假阳上限是有意义的具体数值**并按整族比较控制；设成 1.0 或任何排除不掉东西的值等同于没设。
   4. **安慰剂臂改在与规则同一个模型可见注入点上**（改动量相当、与规则语义无关），且须另行证明该 oracle **对安慰剂是敏感的**——一个天生不可能影响输出的安慰剂，不构成对照。安慰剂臂也显示差异即判 `证据不足`。

   **突变形态的排除项——这道门最容易被假货满足**：转红的检查必须观察**行为**，不得是对规则本身的**存在性、哈希、锚点或 schema** 检查。删掉规则文本使「该文本存在」的断言转红，是同义反复，什么也没证明。同样排除**专为给该规则背书而新建**的检查或制品；机器制品形态若只声称因果而无配套的无规则臂观察，一并不合格。

   该证据**明确排除**两类自证材料：台账行的 `observed-failure: yes` 标记（全仓 101 行带该标记，见取证文件——它记录规则的成因而非其触发），以及任何仅以叙述声称"当时起了作用"的轮次记录——包括本计划自身、台账行正文、以及任何由起草方撰写的轮次记述。

   **零损失义务表字段（冻结）**，每条判 `superseded` / `休眠` / `收窄` 的单元附一张，每行一条 before 义务：

   | 字段 | 取值 |
   | --- | --- |
   | before 义务 | 逐字引用原文 |
   | 去向 | `survives-verbatim` / `subsumed-by <锚点>` / `intentionally-dropped` |
   | 承接锚点 | 文件 + 小节，须 grep 得到 |
   | 验证 | 能证明该义务仍被强制的命令 |

   **`survives-verbatim` 必须落在**经验证仍在生效的 firing path 上——否则它只是"文本还在存档里躺着"，义务实际已经消失，而零损失表却显示无损。**验证不出来的、或承接位置已不在取用路径上的，一律转 `intentionally-dropped`**，按该行规则须给理由与风险接受人，且由用户裁决。**不存在 `unverified` 这一挡**：无法验证即等同于已丢弃，只是尚未被承认。

   `intentionally-dropped` 行须给理由与风险接受人；**本 program 内 agent 不得自行接受，留给用户裁决**。

   **判据一经冻结，对本样本不得修改，也不得作废重抽。** 若处置中发现判据本身有缺陷，本 program 记为 **`未完成`** 并记录缺陷（是否就此收手由用户裁决）；修正后的判据与样本属于**另一个单独标识的预注册实验**，不得用来满足本 program。就地打补丁与"作废重抽再报同一 program"是同一种事后裁剪，一并禁止。

4. **逐条处置**：每槽位给终态 + 证据 + owner，并**执行该终态所绑定的动作**。

   **终态 ⇄ 动作是冻结的对应关系，不由起草方判断「要不要动」**（否则可以把四个标签连同证据表全部记下来、一行不改、再声称"该动的都动了"，于是整个 program 零改动通过）：

   | 终态 | 必须执行的动作 | 通过所需证据 |
   | --- | --- | --- |
   | `keep` | 不改动——**唯一允许不动的终态** | 判定表第 3 行的两项证据（独立 firing point + 因果制品） |
   | `superseded` | 规则文本**离开取用路径**，或就地打上被强制识别的失效标记 | diff + 零损失义务表 |
   | `休眠` | 同上：离开取用路径，保留可查与可恢复 | diff + 零损失义务表 + 检索记录 |
   | `收窄` | **实施**所述的作用域编辑 | diff 中可见的措辞变更 + 零损失义务表 |

   「离开取用路径」的可验证含义：agent 在正常读取该 owner 包时不再触达该文本（移入归档小节、或移出被引用的 reference 文件），且该判定可由一条 grep 或既有闸复核。

   记录每槽位耗时，按下方计时协议——它是判断「手工处置能否扩展到全量」的读数，不预先绑定任何阈值。
5. **归类顺带产出**：处置过程中记录每单元「若按四操作模型重来一次，它当初该是 ADD / REINFORCE / NOOP」。这是给后续判断用的读数，不是独立工作，也不预先绑定阈值。

**不得自证**：判据与处置同出一方则终态分布可任意调节，这正是本计划自己引用的「不能同一方既蒸馏又评判」。故处置结果交跨模型族独立通道（`code-review` 技能持有的 Kimi / OpenCode / Codex 路由）复核，复核方拿到的材料按下方「签署必须建立在可核验的材料上」一节的固定清单（锚点、拟定终态与动作、因果制品或零损失表、diff、检索三项日志、起止时戳与扣除原因）；**唯一扣留聚合层信息**——各终态的计数，避免结论牵引。不一致不由起草方裁决。

**交付完成态**（非评价性，本 program 不自判通过）：全部单元有裁定，且各终态所绑定的动作已执行完毕。终态分布本身不是成败——全 `keep` 与全 `superseded` 都是有信息量的结论。但 `keep` 须逐条满足判定表第 3 行的两项；**拿不出落地后生效证据的槽位不自动落到 `休眠`**，而是退回有序判据重走，`休眠` 仅在检索协议三项全部执行完毕且均无命中时成立，否则为 `证据不足`（非终态，使交付记为 `未完成`）。

### 后续轮次（不预设触发条件）

处置完 30 个槽位后，可能需要两类后续工作。它们**不在本 program 内**，也**不预先规定触发阈值**：

- **写操作枚举与退役触发表** —— 若处置显示「只能加」是结构性的（大量槽位在四操作模型下本该是 REINFORCE 或 NOOP），值得把 `ADD / REINFORCE / SUPERSEDE / NOOP` 落成台账必填字段，并配可逆的休眠中间态与退役触发表。设计要点已在本轮理清（各取值的 invoke bar 采用「写清排除项」形态；退役默认动作多数不是删除；防抖用进入/退出阈值不同 + 冷却期；「新模型已默认会做」是一条现成未开采的退役来源）。
- **规则触发的可观测性** —— 若处置中大量槽位卡在 `证据不足`，值得把 `eval/body-compliance-eval.rb` 的探针从现有的 4 个 `requirement-*` 技能扩到元层技能（该 harness 已支持 `--arm` 双臂），或推进台账全量可回放（后者依赖 038 落地，前者不依赖）。

**为什么不预先规定触发条件。** 本轮曾为这两批写过数值阈值、取数时点、分母口径、依赖顺序与不触发时的签署要求。外部对抗在其中连续找出矛盾：分母写着恒 30 而触发式除以「实际单元数」；依赖节写着批次三须等 038 而批次三自身另有不依赖 038 的路径；风险节写着影子回放在本仓无对应物而能力表已更正为「有但覆盖窄」。这些矛盾不是疏忽——**它们出自为一个尚未证明存在的需求预先搭建机器**，而那正是本 program 要治的元层膨胀本身。

所以：处置先做完，需要什么由处置结果说话，届时各自开轮、各自立 charter 与证据。这也让本文件缩短约 70 行，是本轮唯一一次「设计产生删除」的实例。

## 风险与停止线

- **假闸风险（首要）**：`write_op` 是一个可以被填而不做的字段——这正是本仓已命名的 record-field 伪造面。对策是每个取值都带 invoke bar（见抽样处置），且对抗评审须专门以「不做也能填」为透镜审一遍。同类教训已有一次（028 轮）：判分器实为正则、换模型救不了，证据冻结但闸作废。
- **照搬风险**：外部源中依赖**真实用户行为与线上暴露**的机制（随机分臂、exposure 归因、命中率统计）在本仓没有对应物，照搬即造假闸。**但「规则是否真被应用」有对应物且覆盖窄**——`eval/body-compliance-eval.rb` 就是该形态（12 probes / 仅 4 个 `requirement-*` 技能，advisory），所以那条路是**未建成**而非不可移植（见交叉分析节）。本 program 只借不依赖用户行为数据的机制。
- **过度收缩风险**：零损失义务表是硬红线；删掉一个有用的窄闸比多留一条冗余规则更贵。
- **本 program 自造的机制同样受退役管辖（递归但必要）**：`write_op` 字段、退役触发表、净字节 advisory 一旦落地，各自登记进退役表并带复验窗口（默认与停止线同窗）。复验时若某机制只被填而未改变任何决定，按「持续无净增益」触发收窄或退回候选。台账 append-only 使 schema 无法回退，因此复验的可执行形态是**停止索要该字段并标注自哪一轮起不再承重**，而非删列。不给自己开豁免，是这套机制可信的前提。
- **停止线（预注册窗口，不绑里程碑）**：外部源的原意是**投产窗口**——时间与轮次预算，不是「几个批次做完」。绑里程碑两头都能绕：说「还没完」可以无限拖，跳过环节又能迅速「跑完」。故预注册为：**自开轮起 6 个自然轮次或 4 周，以先到者为准**；窗口内 30 个槽位未全部拿到终态、或判「要动」而未动完，交付即记为 `未完成`，本 program 停止投入、不再新增机制（「值不值得继续」仍由用户裁决）。重启需要新证据、新失败形态或用户重新限定投入。窗口值在开轮时冻结，中途看到结果后不改。
- **上线门与价值门分开记**：某一批通过它自己的落地闸（可以合并）不等于 program 该继续投下一批（价值门）。用一个通过掩盖另一个，是这里最容易犯的错。

## 验收

- **抽样处置（承重）**：抽样与判据在看任何一行之前已冻结并写入本文件；30 条各有终态、证据、owner；判「要动」的已动完，无 follow-up 遗留；跨模型族独立通道复核已跑且不一致项已处置。终态分布本身不是成败。
- **后续轮次**：不在本 program 的验收范围内。是否需要、需要哪一类，由 30 个槽位的处置结果与耗时读数说话；届时各自开轮、各自立 charter 与证据。
- **program**：不自判通过。交付 30 份处置记录与实际 diff，附报观测量（全仓与 `skills/` 净字节变化、各终态分布、被触发批次的终态），交用户裁决这一轮值不值。窗口内未产出完整交付物即记为 `未完成` 并如实记录。
- 本 program 的交付边界就是这 30 个槽位。**不得把尚未开轮的后续工作算进本轮的完成度**，也不得因为后续工作没做而说本轮未完成。
