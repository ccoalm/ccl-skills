# 039 — 设计先行的收缩轮（三批次）

Status: **design**（开轮计划；无技能变更落地）。写操作准入枚举与退役状态属共享闸语义变更，本文件被评审前不落地实现。

**成功判据：预注册的既有规则样本，每条拿到终态裁定并在本 program 内被执行。**

判据既不是字节也不是能力。取 **N = 30** 条既有规则，在看任何一条之前冻结抽样（自台账中两个主导 owner 的 126 行按固定种子随机抽取，种子与名单写入本文件）。每条必须产出：

| 要素 | 要求 |
| --- | --- |
| 终态 | `keep` / `superseded` / `休眠` / `收窄` 四选一，无「待定」 |
| 证据 | `keep` 须给触发路径（哪个决策点机械触达它）；其余三态须给零损失义务表 |
| owner | 裁定落在哪个技能/引用的哪一节 |
| 执行 | 判「要动」的，本 program 内动完，不留 follow-up |

**全部 30 条判 `keep` 且各自附上触发证据 = 通过**——那是用证据证伪了「冗余很多」这个假设，属有效结论。**判「要动」却没动 = 失败。**

三条被这个判据替换掉的旧候选，及其不可用的原因：

- 「`skills/` 净字节下降」——代理指标，可被位移与压缩措辞绕过（本仓已证实在闸下会位移），且会把诚实的空手结论判为失败。
- 「建立双向可判的能力」——用「造出一套判定机制」度量一个反元层增肥的 program，自我拆台。
- 两者并列——保留前者的全部缺陷。

仓库是否变小**降为观测量**：达标后照报全仓与 `skills/` 净字节，变小就报变小，没变小就报「冗余比假设的少」，两者都不影响判据。

**这条判据的最重要性质：它让机制变成可选的。** 若 30 条能手工处置完，则 `write_op` 字段、行为探针、台账回放**一个都不必造**。机制只有在手工处置被证明不可扩展时才获得正当性。

## 背景：仓库事实与外部机制交叉着看

不是「仓库出诊断、外部出机制」两条平行车道。承重的结论都出在交叉处：一条仓库事实只有配上外部机制才知道它意味着什么，一条外部机制只有配上仓库事实才知道它在这儿成不成立。先列各自的量，再列交叉结论（第五节），本轮设计由交叉结论决定。

Base `origin/dev`@5146b3b，下列指标均可直接复跑复核，命令记在本轮 charter（per-host scratch）。

### 一、规则沉淀高度集中在元层

| 指标 | 实测 |
| --- | --- |
| 台账 behavioral-evidence 行总数 | 183 |
| 属 `skill-extraction-workflow`(86) + `code-review`(40) | **126 行 = 68.9%** |
| 客户端 / 设计面五个包合计（UI/UX、跨端 App、小程序、React Web、终端 CLI） | **3 行** |
| `specs/` 轮次中交付物是流程或工具自身 | **21 / 30 = 70%** |

余下 9 轮也基本是元层（评审索引默认值、计划项处置、CI 泳道、调研 broker、模型账、理论欠账）；真正面向产品交付面的轮次接近于零。**规则在为「怎么做规则」而生，不是为「怎么做产品」。**

台账证据来源同向：按关键词粗扫，提及机器评审/对抗的行 ≥38%，提及真实用户纠正或线上事故的行仅 3%。此项口径敏感（早前一次用不同正则得 66% / 17%），精确比例不作承重结论；**方向在两种口径下一致——沉淀主要由机器评审自循环产生，不由真实使用产生。**

### 二、增长单向，但此前的量级数是错的

仓库做过一次 `git init` 重建，`chore: init ccl-skills` 一个 commit 把 79990 行整树快照记成新增。因此按全量 git 历史算出的增删比是**快照伪影**，必须剔除首个 commit：

| 口径 | added | deleted | 增删比 | 删除占新增 |
| --- | --- | --- | --- | --- |
| 含 re-init 快照（**不可用**） | 89147 | 708 | 125.9 : 1 | 0.79% |
| 剔除首个 commit（真实可观测增长） | **9157** | **708** | **12.9 : 1** | **7.7%** |

方向不变——每删 1 行加 13 行——但量级比先前记录的 139:1 / 0.7% 小一个数量级。本计划一律用 12.9:1，并且承认 re-init 之前的历史不可见，该口径只覆盖重建之后。

最大 entrypoint 为 `skills/skill-extraction-workflow/SKILL.md` = **122101 B**（119.2 KB），不受 re-init 影响，可直接核。

### 三、体量分层：元层与 domain 大致相当，增长偏向元层

「元层占多少」按不同分层给不同的数，所以给区间。分层按**交付物**：交付物是过程本身如何运转的记 meta，是产品制品的记 domain。

| 分层 | 静态体积 | 历史新增（含快照，仅作相对比较） |
| --- | --- | --- |
| 提炼 + 评审两包（不依赖分类判断） | 38.6% | 51.1% |
| meta 窄口径（+ 交付路由、风险分级、编辑隔离、并行分发、发布协调、契约覆盖） | 46.7% | 57.3% |
| meta + 四个边界包（测试策略、缺陷诊断、拷问、多视角调研） | 54.6% | 62.8% |
| domain 侧合计 | 45.4% | 37.2% |

区间宽度来自四个边界包的归属争议，其中只有测试策略量级显著（静态 5.7%）。**本计划不取单一数字**，承重的结论是三种口径下都成立的那条：元层与 domain 侧体量大致相当，而增长明显偏向元层。此表的新增列含 re-init 快照，只用于层间**相对**比较，不作绝对增长依据。

### 四、结论：缺的是目标模型

失败只会说「少了什么」，永远不说「这条多余」。判冗余需要一个「应该有什么」的目标模型，而仓库对自己的技能集没有目标模型——所以既有的「规则集不得单调增长」这条规则没有任何机制能执行它。

设计先行**不违反** evidence-first：设计产出目标与假设（该去为什么找证据），evidence-first 决定什么能变成可执行规则。仓库把两者混同，连带禁掉了设计那一半。

反向教训同时成立，不得因此把设计先行推过头：028 退役的那道闸是「设计得漂亮但判分器是正则」的假闸；而 self-sealing 信号、owner 被还原成 base、台账行绑不到 owner、merge 制造新轮这几类规避形态，书桌上推不出来，只能靠撞。**设计负责产出目标与删除依据，撞出来的仍归失败驱动。**

### 五、交叉：仓库事实 × 外部机制

| 仓库事实 | 外部机制 | 交叉出的结论 |
| --- | --- | --- |
| 台账 86 行的 owner 是提炼工作流自己 | 四种写操作（ADD / REINFORCE / SUPERSEDE / NOOP） | **这 86 行里有多少本该是 REINFORCE 或 NOOP，是可测的。** 若多数是同一失败类的再实例化，四操作模型价值大；若确为互异失败类，价值有限。这决定批次一值不值得做，因此**前置为批次一的第一步**，不预设结论。 |
| 客户端 / 设计面只有 3 行——不是覆盖好，是那里根本不产生证据 | 冷启动用**通用指导臂**，由公开方法论蒸馏，「做一次用两处」 | 零证据面的正确形态不是专用规则（没有证据支撑），而是**通用基线**——它同时就是后续判专用规则的对照臂。所以「客户端面」不是与提炼工作流并列的另一个起点，它是**对照臂的供给侧**，排在批次二。原先的起点二选一因此消解。 |
| 台账每行等权：183 行里机器评审 ≥38%、真实用户纠正 3% | 证据按**预测误差**分级加权，不按条数 | 等权累计等于把最贵的信号摊薄。这解释了增长为何由机器驱动——**最便宜产出的证据主导了沉淀**。退役判据因此不能只看「命中次数」，要看该行当初的证据等级。 |
| 入口尺寸闸能拦增长，但仓库所有规则都被当作永久有效 | 退役触发：更强的基座能力持续不劣于该手工规则 → 标 superseded；「手工规则是过渡表征」 | 仓库从未用过这条退役来源。183 行里必然有一部分编码的是新模型已经默认会做的事——这是一条**现成、未开采的删除依据**，且不依赖任何运行时数据。 |
| 30 轮里 21 轮的交付物是流程或工具自身 | 元层投入自身也要有停止线：预注册投产窗口，窗口内无可测增益即暂停新建 | 仓库对元层投入没有任何速率约束。停止线是这套机制里**唯一约束速率**的部件，也是本 program 自身必须先接受的约束（见风险与停止线节）。 |
| 028 退役的假闸：判分器实为正则 | 裁判信息隔离**要写清排除项**；承诺哈希记录的是声明、不构成独立性证明 | 仓库把这条学成了一则战例，外部把它写成了可核的条款形态。批次一的 invoke bar 直接采用后者的形态：不写「要独立」，写「哪些东西裁判看不到」。 |

反过来也有不成立的，但边界比初稿判定的**窄**——初稿写「影子回放在本仓没有对应物」，这是错的，实测更正如下：

| 外部机制 | 本仓状态 | 结论 |
| --- | --- | --- |
| 影子回放 / 规则是否真被执行 | **已有正确形状，覆盖极窄**：`eval/body-compliance-eval.rb` 自述即「skill 已激活后，agent 是否真的应用了它的硬规则」，且支持 `--arm` 双臂对照。但覆盖是 12 probes / 仅 4 个 `requirement-*` 技能，元层 28 个技能一条没有；advisory，不阻断合并，需本机 claude CLI | **未建成，不是不可移植**。批次二/三的路径因此改变：把探针扩到元层技能，比等台账可回放更直接 |
| 通用指导臂 / 对照臂 | harness 已支持 `--arm LABEL`；跨模型族独立通道由 `code-review` 技能持有 | 可行，但计划须点名由谁写通用臂 |
| 随机分臂 / exposure 归因 / 命中率统计 | 无运行时、无用户行为数据，无对应物 | 真不可移植，照搬即 028 式假闸 |

`body-compliance-eval.rb` 自带的纪律一并采用：**能失败的探针才算证据**（它自己的 oracle 之所以成立，是因为某一臂 36 个探针失败了 14 个）。本 program 任何用探针做的退役判定，都先证明该探针在无规则臂上会红。

## 诊断修正：不是无闸，是闸只管一面且没有对侧出口

「仓库只能加不能删是因为没有防膨胀的闸」——这个诊断是错的，实证如下：

- `scripts/check-size-budget.sh` **已经**对 entrypoint 与 always-on 注入层做净增长阻断（新建或跨过 severe 线即拒；已 severe 的只准平或缩）。
- 该闸**确实在生效**：038 的实现记录里有一条一手位移实例——一条新规则原本写进 `SKILL.md`，被 `entrypoint_word_budget_block` 拦下，改落 `references/` 下的相邻小节，**入口零字节增长**。该轮记录判定为「闸提了个真意见，不是绕行」——就那一轮而言成立。
- 但把这类事件放在 program 尺度看：`references/` 无闸，于是被拦下的增长**位移**而非消失。总量继续涨，入口读数却是干净的。

所以真因是四条缺失，不是缺一个字节闸：

1. **写操作没有枚举**——提炼轮唯一被建模的动作实质是 ADD；REINFORCE（同义、只增一次证据）与 NOOP（重复/无信息量/作用域不明）没有合法书写形态，agent 无处可去。
2. **规则没有状态**——全部隐式 active，缺可逆的休眠与 superseded 中间态，于是「留」与「删」成了仅有的两个选项，而删不可逆，所以永远选留。
3. **没有退役触发清单**——没有任何入口问「哪条现存规则该退役」。提炼的触发全是纠正驱动，而纠正驱动的枚举结构上到不了「本来就做对、可以合并复用」这条轴。
4. **没有判「这条规则还有没有用」的对照判据**——现有判据是「有这条 vs 没这条」，属空白对照，会把通用纪律的功劳算到专用规则头上。

**推论：不给 `references/` 加字节闸。** 那只会再位移一次（下一站是脚本注释、模板、示例）。杠杆在于给增长提供合法替代出口（REINFORCE / NOOP），并给存量规则开一个可逆的退出口（休眠 / superseded）。

## 分批

骨架是**先处置，再决定造不造机制**。批次一是承重的，批次二、三是条件触发的——不满足触发条件就不做，且不做是正常终态。

### 批次一（承重）：抽样处置

1. **冻结抽样（已完成，2026-08-23，先于任何行内容的阅读）**：

   - 抽样框：`references/source-register.md` 中 `behavioral-evidence` 行且 owner ∈ {`skill-extraction-workflow`, `code-review`} 者，共 **126** 条，按文件出现顺序编号。
   - 方法：`random.Random(39).sample(frame, 30)`，**seed = 39**，可复跑。
   - 抽中的台账序号：`3, 4, 6, 12, 15, 16, 42, 45, 48, 50, 54, 55, 66, 80, 81, 82, 85, 86, 90, 108, 118, 124, 131, 134, 137, 142, 144, 146, 154, 178`
   - owner 分布：`skill-extraction-workflow` 20 条，`code-review` 10 条。
   - 名单一经写入不得更换。中途发现某条不适用（例如该行指向的规则已在他轮被删）时，记为该条的终态并说明，**不补抽**——补抽会让样本偏向"好处置的"。
2. **冻结判据**：四个终态各自的判定条件、以及零损失义务表的字段，在看到任何一行之前写定。
3. **逐条处置**：每条给终态 + 证据 + owner；判「要动」的当轮动完。
4. **归类顺带产出**（原批次一的测量）：处置过程中记录每条「若按四操作模型重来一次，它当初该是 ADD / REINFORCE / NOOP」。这是批次二的触发条件读数，不是独立工作。

**不得自证**：判据与处置同出一方则终态分布可任意调节，这正是本计划自己引用的「不能同一方既蒸馏又评判」。故处置结果交跨模型族独立通道（`code-review` 技能持有的 Kimi / OpenCode / Codex 路由）复核，复核提示词只给冻结判据与原始行，不给「各终态占比意味着什么」；不一致不由起草方裁决。

**终态**：30 条全部有裁定且「要动」的已动完。占比本身不是成败——全 `keep` 是通过，全 `superseded` 也是通过。

### 批次二（条件触发）：写操作枚举与退役触发表

**触发条件**：批次一显示手工处置不可扩展——具体为二者之一：① 30 条中 REINFORCE/NOOP 同类占比高，说明「只能加」是结构性的而非个案；② 手工处置单条成本高到全量（183 行）不可行。**两条都不满足则本批次不做**，如实记录「手工处置足够，机制无正当性」，这是有效终态。

触发后的交付物：

- **`write_op` 落成台账必填列** ∈ `ADD` | `REINFORCE` | `SUPERSEDE` | `NOOP`，每个取值带 **invoke bar**（防字段被填而不做，本仓已命名的 record-field 伪造面）。写法采用「写清排除项」而非「要求独立」的形态——不写「NOOP 需有依据」，写「NOOP 行必须点名文件 + 小节，缺任一即拒」；`SUPERSEDE` 行须点名被取代行并附零损失义务表；`REINFORCE` 行不得改写已发布规则文本，证据另存、计数派生（与台账既有的 append-only + supersede-by-pointer 契约同向）。
- **退役触发表**，默认动作多数不是删除：

  | 触发 | 默认动作 | 恢复 |
  | --- | --- | --- |
  | 长期未命中 | 转休眠——移出取用路径（agent 读不到），保留可查 | 可逆，随时恢复 |
  | 时效窗口到期 | 转休眠复验；续期需新证据，不因仍在命中自动延续 | 可逆 |
  | 被当场覆盖 / 反复例外 | 降置信；连续多次触发 `SUPERSEDE` 候选 | — |
  | 持续无净增益 | 收窄作用域，不是自动删除 | 冷却期后可凭新证据重进候选 |
  | 被更强的既有规则吸收 | 标 superseded，旧文本保留可查 | 可回滚 |
  | 新模型已默认会做（手工规则是过渡表征） | 双臂探针：有规则臂与无规则臂**都过** → 不再承重 → superseded 候选。单次通过不算，须先证明该探针在无规则臂上能红 | 可回滚 |

- **防抖**：进入阈值与退出阈值不同 + 冷却期 + 最小证据窗口；同一轮看到结果后不改阈值。
- **对照臂供给**：客户端 / 设计面只有 3 行台账，不是覆盖好而是那里不产生证据。零证据面的正确形态是从公开方法论蒸馏的**通用基线**，该基线同时就是判其它专用规则的对照臂——做一次用两处。本批产出基线，不产出该面的专用规则。
- **退役判据带证据等级权重**：台账每行等权，而机器评审行 ≥38%、真实用户纠正行 3%，等权即把最贵的信号摊薄。「持续无净增益」的判定须带该行当初的证据来源等级，机器自循环产出的行退役门槛更低。
- **落点纪律**：不新增顶层 bullet，`write_op` merge 进 `rule-consolidation.md` 已拥有的失败类；入口零字节增长。**firing path**：Step 6 closeout 逐行走查 + `check-ccl-skills.sh` 校验。附带 advisory：轮 closeout 打印本轮净字节 delta，不阻断。
- **零损失红线**：收缩不得删掉有用的窄闸。任何改写 / 退役都携带零损失义务表——每条 before 义务映射到存活文本或真正被包含的文本，逐条可验，对抗评审专审这张表。
- **验收**：缺 `write_op` 的新增台账行使闸转红并点名本 owner（RED-baseline，applied 突变、差分归因、控制组绿）。

### 批次三（条件触发）：规则触发可观测性

**触发条件**：批次二的退役触发表里出现了**手工判不了**的行（典型是「长期未命中」——判它需要知道某规则历史上是否被触达）。没有这种行则不做。

触发后有两条路，取成本低者：

| 路径 | 直接性 | 确定性 | 依赖 |
| --- | --- | --- | --- |
| 扩 `eval/body-compliance-eval.rb` 探针到元层技能 | 直接回答「规则是否被应用」 | advisory，需 claude CLI，每次跑烧 token | 无（harness 已在，支持 `--arm` 双臂） |
| 台账全量可回放 | 间接推断 | 确定性、免费 | 依赖 038 落地 |

**两种非终态要分开**：「技术上不可行 + 成本高于收益」是本批的技术结论；「038 未落地」是依赖阻塞，不构成技术结论。038 当前 gate 记录中「独立对抗评审：未跑」，另有一项 scope-cut 待风险 owner 裁决——若走台账路径且它在窗口内未落地，降级为人工抽样回放（随机 20 行人工判定），并如实标注为抽样而非全量。

## 每批硬性 gate（不因分批减免）

1. 每批次新一轮 invoke `skill-extraction-workflow`，round 自建 charter（per-round re-invocation）。
2. worktree 先行，绝不在 main/dev 检出上编辑。
3. R0 零命中。本 program 的外部源是**私有产品设计文档**，provenance（真实标题、URL、租户、产品名、业务域名词）只入 per-host private alias，共享树只写机制形态——shape 入、content 不入。审计不豁免。
4. dual-track：独立评审 + 对抗 challenge；非 wording 变更配 behavioral-evidence 行；触碰 `description`/frontmatter 即按 routing-surface 走 `make eval-routing`。
5. 台账 schema 变更属共享闸语义变更，走 `feature-risk-router` 的 `shared-gate` 分类；改动前本文件须已存在并被评审。
6. 既有回归全绿，尤其 `check-ccl-skills.sh`、`check-size-budget.sh`、台账 firing-path 与 impact-chain 相关套件；真仓改前/改后跑同一命令，verdict 不得意外翻转。
7. **自指处理**：本 program 改的是提炼工作流自身，改后的规则会作用于本轮自己的台账行——实现时须处理 bootstrap 顺序，且不得自我豁免。

## 风险与停止线

- **假闸风险（首要）**：`write_op` 是一个可以被填而不做的字段——这正是本仓已命名的 record-field 伪造面。对策是每个取值都带 invoke bar（见批次一），且对抗评审须专门以「不做也能填」为透镜审一遍。同类教训已有一次（028 轮）：判分器实为正则、换模型救不了，证据冻结但闸作废。
- **照搬风险**：外部源中依赖真实任务流与用户行为数据的机制（影子回放、随机分臂、exposure 归因、命中率统计）在本仓**没有对应物**。照搬即造假闸。本 program 明确只借「写操作枚举 / 状态与退役 / 对照臂 / 停止线」这四类不依赖运行时数据的机制。
- **过度收缩风险**：零损失义务表是硬红线；删掉一个有用的窄闸比多留一条冗余规则更贵。
- **本 program 自造的机制同样受退役管辖（递归但必要）**：`write_op` 字段、退役触发表、净字节 advisory 一旦落地，各自登记进退役表并带复验窗口（默认与停止线同窗）。复验时若某机制只被填而未改变任何决定，按「持续无净增益」触发收窄或退回候选。台账 append-only 使 schema 无法回退，因此复验的可执行形态是**停止索要该字段并标注自哪一轮起不再承重**，而非删列。不给自己开豁免，是这套机制可信的前提。
- **停止线（预注册窗口，不绑里程碑）**：外部源的原意是**投产窗口**——时间与轮次预算，不是「几个批次做完」。绑里程碑两头都能绕：说「批次二还没完」可以无限拖，跳过批次又能迅速「跑完」。故预注册为：**自开轮起 6 个自然轮次或 4 周，以先到者为准**；窗口内 30 条样本未全部拿到终态裁定、或判「要动」而未动完，即暂停本 program，不开新批次、不再新增机制。重启需要新证据、新失败形态或用户重新限定投入。窗口值在开轮时冻结，中途看到结果后不改。
- **上线门与价值门分开记**：某一批通过它自己的落地闸（可以合并）不等于 program 该继续投下一批（价值门）。用一个通过掩盖另一个，是这里最容易犯的错。

## 验收

- **批次一（承重）**：抽样与判据在看任何一行之前已冻结并写入本文件；30 条各有终态、证据、owner；判「要动」的已动完，无 follow-up 遗留；跨模型族独立通道复核已跑且不一致项已处置。终态分布本身不是成败。
- **批次二**：触发条件成立与否有读数支撑。不成立则记录「手工处置足够，机制无正当性」即完成。成立则：触发表每行有可执行判据（不是形容词）；休眠可逆且有恢复路径；通用基线可被没读过本轮的人执行；每条退役附零损失义务表；缺字段的 RED-baseline 实跑转红并差分归因。
- **批次三**：触发条件成立与否有读数支撑。不成立即完成。成立则产出「探针扩展」或「台账回放」或「技术不可行 + 成本判定」三者之一的终态；依赖阻塞不得记作技术结论。
- **program**：30 条样本全部拿到终态并执行完毕。附报观测量：全仓与 `skills/` 净字节变化——变小报变小，未变小报「冗余比假设的少」，两者都不影响判据。窗口内未达成即按停止线暂停并如实记录。
