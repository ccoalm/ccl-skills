# 评审控制器对技能包单文件的大小上限

## 现象

评审控制器给被选中的技能包算哈希时，对包里每个文件套用 1,048,576 字节的上限。`skills/skill-extraction-workflow/references/source-register.md` 是只增不减的台账，在 `main` 上已是 1,048,226 字节。任何再加一行登记的改动都会让评审以 `selected skill file exceeds 1048576 bytes` 结束，而改动上游技能必须加登记行，所以下一轮技能改动都过不了评审。

复现：在一个加了两行登记的候选上运行 `extraction_review_gate.sh --mode review`，返回 `inconclusive`，原因即上面那句。

## 原因

这个上限只用来限制算哈希时的读取，文件内容不进评审包。包级别另有 8,388,608 字节的总上限。单文件上限比台账的自然增长小，包上限才是真正需要的界。

## 改动

被选中技能包里的每个文件，读取上限改为包上限减去已读的字节数；超出时按包超限拒绝。这样一个包被接受的内容不超过包上限，读取的字节总数最多比它多 1 字节：读取函数为了发现文件在检查之后变大，会多读 1 字节再拒绝。改之前是先按单文件上限读完再累加判断，最多会比包上限多读一个文件。控制器运行时文件、wording-only 证明等其它输入的 1,048,576 字节上限不变。

没有选的做法：给台账开豁免（多一条按路径的特例）；把旧登记行归档（台账行按路径被引用，不能移动）。

## 验证

候选是本分支相对 `origin/main` 0feefb0 的改动。

| 检查 | 命令 | 结果 |
| --- | --- | --- |
| 改前：1,048,577 字节的技能文件 | 在未改的 `review_gate.py` 上调用 `_hash_skill_package` | 抛出 `selected skill file exceeds 1048576 bytes` |
| 改后：同一个文件，再改动第一个 MiB 之后的一个字节（长度不变） | `bash skills/code-review/scripts/test_review_gate.sh` 里的新增用例 | 两次哈希不同 |
| 改后：单个文件超过包上限；九个文件合计超过包上限 | 同一套件里的两个既有用例 | 都被拒绝，原因码 `local_tool_failure` |
| 改后：合计恰好等于包上限的包，其后再跟一个空文件；再把空文件改成 1 字节 | 同一套件里的新增用例，同时记录每次读取的上限 | 前者通过，三次读取的上限依次为包上限、包上限减入口文件大小、0；后者被拒绝 |
| 控制器套件 | `bash skills/code-review/scripts/test_review_gate.sh`，macOS | 310 条通过 |
| 结构闸 | `CCL_SKILL_BASE_REF=origin/main bash skills/skill-extraction-workflow/scripts/check-ccl-skills.sh .` | 通过 |
| 整条 lane | `make test`，Linux | 见 `evidence/validation.md` |

质量检查：不涉及领域模型、可观测性、用户体验。性能上，一个包的读取总量上限从「包上限加一个文件」降到包上限加 1 字节。安全上，读取仍然先按文件描述符判断类型和大小，没有放宽链接与类型检查。

| 独立评审，`evidence/review.json` | 3 条 P2 | 全部修复：读取上限改为包的剩余额度；新增用例改为同长度改字节；本节补上命令和结果 |
