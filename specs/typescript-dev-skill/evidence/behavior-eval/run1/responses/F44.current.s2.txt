## 一、为什么改一个包就要整仓重新检查

一般是下面三种原因之一：

1. **没用 project references**：每个包各跑 `tsc --noEmit`，或者只有一个根 tsconfig 把所有源码都包进去。
2. **包之间直接引用对方源码**：`paths` 把 `@scope/lib` 指到 `../lib/src`，或者 `package.json` 的 `exports`/`types` 指向 `src/*.ts`。这样下游的检查范围里包含了上游的全部源码，就算加了 references 也没有用。
3. **没有 `.tsbuildinfo`**：没开 `incremental`/`composite`，每次都从零开始。

## 二、tsconfig 结构

```
tsconfig.base.json          # 共享编译选项，不含 include/references
tsconfig.json               # 只做入口：files: []，引用全部 5 个包
packages/
  core/   tsconfig.json  tsconfig.test.json
  utils/  ...            (references → core)
  api/    ...            (references → core, utils)
  ...
```

**tsconfig.base.json**
```jsonc
{
  "compilerOptions": {
    "target": "es2022",
    "module": "nodenext",            // 前端/打包器包用 "preserve" + "moduleResolution": "bundler"
    "moduleResolution": "nodenext",
    "strict": true,
    "composite": true,               // 隐含 incremental + declaration
    "declarationMap": true,          // IDE 跳转定义时能跳到上游源码
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "skipLibCheck": true,
    "types": ["node"]                // 6.0 起 types 默认为 []，要显式写出
  }
}
```

**packages/api/tsconfig.json**
```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "dist",
    "tsBuildInfoFile": "dist/.tsbuildinfo"
    // JS 由 tsup/esbuild 产出时加 "emitDeclarationOnly": true
  },
  "include": ["src"],
  "references": [{ "path": "../core" }, { "path": "../utils" }]
}
```

**packages/api/tsconfig.test.json**：测试代码单独放一个项目，避免 `.d.ts` 混进发布产物。
```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": { "emitDeclarationOnly": true, "outDir": ".tsbuild/test", "rootDir": "." },
  "include": ["test"],
  "references": [{ "path": "./tsconfig.json" }]
}
```

**根 tsconfig.json**
```jsonc
{
  "files": [],
  "references": [
    { "path": "packages/core" }, { "path": "packages/core/tsconfig.test.json" },
    { "path": "packages/utils" }, { "path": "packages/api" }
    // ……每个包和它的 test 项目都要列上
  ]
}
```

**package.json（每个包）**
```jsonc
{
  "exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } },
  "dependencies": { "@scope/core": "workspace:*" }
}
```

必须遵守的几条：
- **删掉指向兄弟包源码的 `paths`**。包之间只通过 `workspace:*` 加 `exports` 指向的 `dist/*.d.ts` 互相引用。
- `references` 要和 `package.json` 依赖保持一致，少一条就会读到过期的 `.d.ts`。可以用 `@monorepo-utils/workspaces-to-typescript-project-references` 这类工具自动同步，或者在 CI 里校验。
- 包比较多、检查较慢时，可以开启 `isolatedDeclarations`，让 `.d.ts` 生成不依赖完整的类型检查。这是可选项。

## 三、日常命令

```bash
# 只检查一个包（会顺带检查它的上游，上游没变就跳过）
pnpm exec tsc -b packages/api

# 全仓增量检查：只重新检查输入变了的项目；
# 上游 .d.ts 没变时，下游不会重新检查
pnpm exec tsc -b

# 排查为什么某个项目被重新检查了
pnpm exec tsc -b --verbose
```
CI 可以缓存各包的 `dist/.tsbuildinfo` 和 `dist`，缓存 key 用 lockfile 哈希加 tsconfig 哈希。

## 四、升级步骤

建议分两步升：5.x → 6.0 → 7.0。不要从 5.x 直接跳到 7。

**第 0 步：在当前 5.x 上留基线**
- 先把上面的 references 结构落地，确认 `tsc -b` 干净通过。
- 记录 `tsc -b --extendedDiagnostics` 的耗时。
- 把各包的 `dist/**/*.d.ts` 复制一份，当作公开 API 快照。

**第 1 步：先升到最新的 5.x 小版本**，把新出现的报错修掉。

**第 2 步：升到 6.0**
- 用 pnpm catalog 统一全仓的 TypeScript 版本：
  ```yaml
  # pnpm-workspace.yaml
  catalog:
    typescript: ^6.0.0
  ```
  各包写 `"typescript": "catalog:"`，然后运行 `pnpm install`。
- 处理 6.0 的弃用项和默认值变化（具体以官方 release notes 为准）。常见的有：
  - 弃用：`moduleResolution: node/node10/classic`、`baseUrl`、`outFile`、`target: es5`、`module: amd/umd/system`、`esModuleInterop: false`、`downlevelIteration`。
  - 默认值变化：`strict` 默认为 true，`types` 默认为 `[]`，`rootDir` 默认为 tsconfig 所在目录。
- `"ignoreDeprecations": "6.0"` 只能临时用。升 7 之前必须把对应问题清理掉，因为 7.0 会直接删除这些选项。
- 同步升级周边工具的 peer 范围：typescript-eslint、ts-jest/vitest 的类型检查、tsup/`rollup-plugin-dts`、api-extractor、`@types/node`。IDE 要切换到 workspace 里的 TypeScript 版本。

**第 3 步：升到 7.0（Go 原生版）**
- 如果 7.0 还没出正式版，先加一个不阻塞合并的 CI 任务：`pnpm dlx @typescript/native-preview tsgo -b`，和 6.x 的检查结果对比。
- 主要风险是工具链兼容性。依赖 TS 编译器 JS API 的工具（如 typescript-eslint 的类型感知规则、api-extractor、ts-morph、vue-tsc），在 7.x 上可能暂时不可用。如果遇到，可以用 pnpm 别名保留一份 6.x 给这些工具用（`"typescript6": "npm:typescript@^6"`），类型检查本身交给 `tsgo -b`。
- 7.x 和 6.x 的检查结果一致后，再把 7.x 设为阻塞合并的检查项。

| 增量生效 | 只改 `core` 内部一个不导出的函数，再运行 `tsc -b --verbose` | 只有 `core` 重新检查，其他包显示 up to date |
