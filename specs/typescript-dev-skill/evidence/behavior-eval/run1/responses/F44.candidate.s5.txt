## 一、tsconfig 结构（Project References + `tsc -b`）

整仓重新检查，是因为 `tsc` 每次都把所有文件当成一个整体来编译。改成项目引用后，每个包独立编译，生成 `.d.ts` 和 `.tsbuildinfo`。`tsc -b` 只重建过期的包。如果上游改动没有改变它的 `.d.ts`，下游包也不会重新检查。

```
tsconfig.base.json          # 共享选项
tsconfig.json               # 根 solution，只做引用
packages/a/tsconfig.json    # 源码项目
packages/a/tsconfig.test.json
...
```

**tsconfig.base.json**：把所有选项都显式写出来，不依赖默认值，因为 6.0 改了一批默认值。

```jsonc
{
  "compilerOptions": {
    "strict": true,
    "target": "es2022",              // 按最老的运行时定，不按开发机
    "lib": ["es2022"],
    "module": "nodenext",            // 由 Node 直接加载 / 要发布的包
    "moduleResolution": "nodenext",  // 由打包器解析的前端包在包内改成 esnext + bundler
    "types": [],                     // 6.0 起默认就是 []；每个包按需声明
    "composite": true,
    "declaration": true,
    "declarationMap": true,          // 编辑器跳转能直接到源码
    "sourceMap": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "noUncheckedIndexedAccess": true,
    "noUncheckedSideEffectImports": true,
    "skipLibCheck": true             // 不能用来掩盖自己写的 .d.ts 里的错误，见第三节
  }
}
```

**根目录 tsconfig.json**：它自己不编译任何文件，只列出所有项目。

```jsonc
{
  "files": [],
  "references": [
    { "path": "packages/a" }, { "path": "packages/b" }, { "path": "packages/c" },
    { "path": "packages/d" }, { "path": "packages/e" },
    { "path": "packages/a/tsconfig.test.json" } // 每个包的 test 项目都要列上
  ]
}
```

**packages/b/tsconfig.json**：

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "dist",
    "tsBuildInfoFile": "dist/.tsbuildinfo",
    "types": ["node"]
  },
  "include": ["src"],
  "references": [{ "path": "../a" }]   // 必须和 package.json 里的 workspace 依赖一致
}
```

**packages/b/tsconfig.test.json**：测试单独成一个项目，否则 `rootDir` 和测试全局类型会混进源码。

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": ".",
    "outDir": "../../.tsbuild/b-test",
    "emitDeclarationOnly": true,
    "types": ["node", "vitest/globals"]
  },
  "include": ["test", "scripts"],
  "references": [{ "path": "." }]
}
```

**包之间怎么引用**：建议先构建再引用。`package.json` 里写 `"@scope/a": "workspace:*"`，`exports` 指向 `dist`，并且 `types` 必须写在第一位：

```json
"exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } }
```

另一种做法是源码优先（`customConditions`），但这样打包器和测试运行器也要认同一个 condition，不然编辑器、CI 和运行时看到的类型会不一样。两种方式只选一种，不要混用。

`paths` 别名只在编译期有效，运行时并不认。如果要用，必须同时配上 `package.json#imports` 或打包器的 alias。6.0 起不再支持把 `baseUrl` 当作查找根目录，要把前缀直接写进每条 `paths`。

**常用命令**：

```bash
pnpm exec tsc -b                    # 全仓，只重建过期的项目
pnpm exec tsc -b packages/c         # 只检查 c 及其上游
pnpm exec tsc -b --verbose          # 显示每个项目为什么重建 / 为什么跳过
```

如果 JS 由打包器（tsup、vite 等）生成，就在包里设 `emitDeclarationOnly: true`，让 `tsc -b` 只负责类型检查和生成 `.d.ts`。打包器构建成功不代表类型检查通过。

包之间的依赖方向属于架构决策。如果出现循环引用，要先拆包，靠调配置解决不了。

## 二、升级步骤（5.x → 6.0 → 7.0）

按我知识截止时的信息：6.0 修改了默认值、废弃了一些旧选项；7.0 是用 Go 重写的原生编译器，把 6.0 的废弃项变成硬错误，**而且不提供编译器 API**。请先运行 `npm view typescript dist-tags` 确认当前最新版本，再对照官方 release notes。

不要一步从 5.x 跳到 7，要分开发布：

0. **记录基线**
   - `pnpm ls -r typescript` 和 `tsc -v`
   - 记下当前检查耗时（`tsc -b --extendedDiagnostics`）
   - 保存一份 `dist/**/*.d.ts` 快照，后面用来对比
   - 列出所有调用编译器 API 的工具：typescript-eslint、vue-tsc、ts-jest、ts-node、tsup/rollup 的 dts 插件、api-extractor、ts-morph、vitest typecheck。逐个查它们支持的 TS 版本范围。
1. **先完成第一节的项目引用改造**，并且在当前 5.x 上保持零错误。不要和编译器升级混在一个 PR 里。
2. **升到最新的 5.x**，确认零错误。
3. **升到 6.0**
   - 在根目录 `package.json` 用 pnpm `catalog:` 统一版本，保证整仓只解析出一个 `typescript`。
   - 把默认值有变化的选项都写进 base：`strict`、`module`、`target`、`types`、`rootDir`、`noUncheckedSideEffectImports`。
   - 把 `moduleResolution: node`/`node10` 迁移到 `nodenext` 或 `bundler`。
   - 去掉 `baseUrl`。
   - 对新出现的错误：能修就修；修不了的用 `// @ts-expect-error <原因>`，不要用 `@ts-ignore`，也不要放宽 `strict`。
   - **最终必须零错误，并且不使用 `ignoreDeprecations`。**
4. **升到 7.0**
   - 命令行的 `tsc -b` 换成 7.0。
   - 需要 API 的工具，逐个决定是否留在 6.0 API 上。官方提供了并存方案（发布了 `@typescript/typescript6`，带 `tsc6` 和 6.0 API），具体包名和别名写法以官方文档为准。
   - 这个“新旧两个版本并存”的决定要写进仓库文档，不能让 pnpm 意外装出两个版本。
   - typescript-eslint 的类型感知规则依赖编译器 API，要确认它目前用的是哪个 API。
5. **后续单独提 PR**，逐条清理第 3、4 步加的 `@ts-expect-error`。

- 根目录运行 `tsc -b` 作为必过的检查（加 `--verbose` 方便排查）。
