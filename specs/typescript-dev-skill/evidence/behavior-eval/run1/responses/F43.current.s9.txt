## 思路

`JSON.parse`、`localStorage.getItem`、`catch (err)` 拿到的都是运行时数据，TypeScript 只能在编译期检查类型。`as User` 只是告诉编译器"相信我"，运行时并不会检查。所以统一改成三步：

1. **入口先当 `unknown`**：所有外部数据一律从 `unknown` 开始。
2. **用 schema 在运行时校验，再收窄类型**：用 zod 定义 schema，类型由 schema 推导（`z.infer`），两者只维护一份。
3. **失败有明确处理**：请求体不合法返回 400；配置不合法回退默认值；异常先统一转成 `Error` 再读 `message`。

## 代码（zod v4）

```ts
// src/safe-json.ts
import { z } from 'zod';
import { getErrorMessage } from './errors';

export type Result<T, E = string> = { ok: true; value: T } | { ok: false; error: E };

export function parseJson(text: string): Result<unknown> {
  try {
    return { ok: true, value: JSON.parse(text) as unknown }; // any → unknown 是放宽，安全
  } catch (e) {
    return { ok: false, error: `invalid JSON: ${getErrorMessage(e)}` };
  }
}

export function parseWith<T>(schema: z.ZodType<T>, text: string): Result<T> {
  const json = parseJson(text);
  if (!json.ok) return json;
  const r = schema.safeParse(json.value);
  return r.success ? { ok: true, value: r.data } : { ok: false, error: z.prettifyError(r.error) };
}
```

```ts
// src/config.ts
import { z } from 'zod';
import { parseWith } from './safe-json';

export const ConfigSchema = z.object({
  theme: z.enum(['light', 'dark']).default('light'),
  pageSize: z.number().int().min(1).max(100).default(20),
});
export type Config = z.infer<typeof ConfigSchema>;

const KEY = 'cfg';
type ReadableStorage = Pick<Storage, 'getItem'>;

function readRaw(storage?: ReadableStorage): string | null {
  try {
    // 隐私模式或沙箱 iframe 里，访问 localStorage 本身就可能抛 SecurityError
    return (storage ?? globalThis.localStorage)?.getItem(KEY) ?? null;
  } catch {
    return null;
  }
}

export function loadConfig(storage?: ReadableStorage): Config {
  const raw = readRaw(storage);
  if (raw === null) return ConfigSchema.parse({});
  const r = parseWith(ConfigSchema, raw);
  if (r.ok) return r.value; // 旧版本存的数据缺字段时，会自动补默认值
  console.warn(`[config] ignored invalid "${KEY}": ${r.error}`);
  return ConfigSchema.parse({}); // 每次返回新对象；不删坏数据，下次保存时会覆盖
}
```

```ts
// src/errors.ts
export function toError(e: unknown): Error {
  if (e instanceof Error) return e;
  if (typeof e === 'string') return new Error(e);
  if (typeof e === 'object' && e !== null && 'message' in e && typeof e.message === 'string') {
    return new Error(e.message, { cause: e });
  }
  let text: string;
  try {
    text = JSON.stringify(e) ?? String(e);
  } catch {
    text = Object.prototype.toString.call(e); // 循环引用、BigInt 等无法序列化时
  }
  return new Error(text, { cause: e });
}

export const getErrorMessage = (e: unknown): string => toError(e).message;
```

## 用编译器和 lint 防止再写回去

- **tsconfig**：开启 `"strict": true`，它包含 `useUnknownInCatchVariables`，`catch (err)` 里直接写 `err.message` 会编译报错。`lib` 至少设为 `es2022`，否则 `Error` 的 `cause` 选项不可用。
- **typescript-eslint 的 `recommendedTypeChecked`** 包含两类规则：
  - `no-unsafe-assignment` 和 `no-unsafe-member-access`，拦截 `any` 继续往下传。
  - `use-unknown-in-catch-callback-variable`。`.catch(err => ...)` 回调里的 `err` 即使开了 strict 仍然是 `any`，这一点容易漏，需要这条规则来管。
- **禁止 `JSON.parse(...) as X` 写法**：
  ```js
  'no-restricted-syntax': ['error', {
    selector: "TSAsExpression > CallExpression[callee.object.name='JSON'][callee.property.name='parse']",
    message: '用 parseWith(schema, text)，不要断言 JSON.parse 的结果',
  }]
  ```
- **可选**：引入 `@total-typescript/ts-reset`，它会把 `JSON.parse` 和 `Response.json()` 的返回类型改成 `unknown`。改完后漏改的调用点都会以编译错误的形式出现，可以当作待改清单。
- **迁移时用这些命令找出所有调用点**：
  ```
  rg 'JSON\.parse\(.*\)\s+as '
  rg '\.json\(\)\s*as '
  rg 'getItem\('
  rg 'catch \(\w+: any\)'
  rg '\.catch\(\(?\w+'
  ```

```ts
// src/user.test.ts
import { describe, it, expect } from 'vitest';
import { parseUser } from './user';

const valid = { id: 'u1', name: 'Ann', email: 'ann@example.com' };

describe('parseUser', () => {
  it('accepts a valid user', () => {
    expect(parseUser(JSON.stringify(valid))).toEqual({ ok: true, value: valid });
  });

  it('strips unknown fields such as isAdmin', () => {
    expect(parseUser(JSON.stringify({ ...valid, isAdmin: true }))).toEqual({ ok: true, value: valid });
  });

  it('does not carry __proto__ payload into the result', () => {
    const r = parseUser('{"id":"u1","name":"Ann","email":"ann@example.com","__proto__":{"isAdmin":true}}');
    expect(r.ok).toBe(true);
    if (r.ok) expect((r.value as Record<string, unknown>).isAdmin).toBeUndefined();
  });

  it.each([
    ['broken JSON', '{"id":'],
    ['empty body', ''],
    ['null', 'null'],
    ['array', '[]'],
    ['missing email', JSON.stringify({ id: 'u1', name: 'Ann' })],
    ['wrong type', JSON.stringify({ ...valid, id: 1 })],
    ['bad email', JSON.stringify({ ...valid, email: 'x' })],
    ['negative age', JSON.stringify({ ...valid, age: -1 })],
  ])('rejects %s', (_, body) => {
    const r = parseUser(body);
    expect(r.ok).toBe(false);
    if (!r.ok) expect(r.error).not.toBe('');
  });
```

## 安全提示

- **校验通过不等于身份可信**：schema 只证明请求体的格式正确，不证明内容属实。`id`、`role`、租户之类的值，在服务端要从登录凭证或服务端数据推导，不能用请求体里的值。
- **多余字段会被丢掉**：zod 默认去掉 schema 以外的字段，所以请求体里多出的 `isAdmin` 不会进入 `user`。上面有测试覆盖这一点。如果改用 `.passthrough()` 或 `z.looseObject()`，这层保护就没了。
- **原始错误信息不要直接给用户看**：可能泄露内部细节，可以记日志，界面上换成通用提示。

如果不想引入 zod，可以把 `parseWith` 换成手写的类型守卫（`(v: unknown): v is User`）。测试用例不用改，只是字段多了以后，守卫和类型要分别手动维护。
