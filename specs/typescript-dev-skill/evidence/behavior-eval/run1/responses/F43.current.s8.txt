## 做法

三处问题其实是同一件事：**外部数据的类型要在运行时检查，不能靠 `as` 声明出来。**

| 现在的写法 | 问题 | 改成 |
|---|---|---|
| `JSON.parse(body) as User` | `JSON.parse` 返回 `any`，`as` 不做任何检查 | 先拿到 `unknown`，再用 schema 校验，返回 `Result` |
| `localStorage.getItem('cfg')` 直接断言 | 数据可能是旧版本、被篡改、JSON 损坏，读 storage 本身也可能抛错（隐私模式、SSR） | schema 校验；单个字段坏了只回退这个字段的默认值；不会抛错 |
| `catch (err) { err.message }` | `err` 实际是 `unknown`，别人可以 `throw "str"` 或 `throw null` | 用 `toError(e)` 统一转成 `Error` |

我推荐用 **zod**（v4）做运行时校验，类型从 schema 推出来，只维护一份定义。

### 1. `src/lib/errors.ts`

```ts
export function toError(e: unknown): Error {
  if (e instanceof Error) return e;
  if (typeof e === 'string') return new Error(e);
  if (typeof e === 'object' && e !== null && 'message' in e && typeof e.message === 'string') {
    return new Error(e.message, { cause: e }); // 跨 iframe 的 Error、{ message } 形状的对象
  }
  let msg: string;
  try {
    msg = JSON.stringify(e) ?? String(e); // undefined → "undefined"
  } catch {
    msg = String(e); // BigInt、循环引用
  }
  return new Error(msg, { cause: e });
}

export const errorMessage = (e: unknown): string => toError(e).message;
```

### 2. `src/lib/json.ts`

```ts
import { z } from 'zod';
import { toError } from './errors';

export type Result<T, E = Error> = { ok: true; value: T } | { ok: false; error: E };

export function parseJson(text: string): Result<unknown> {
  try {
    const value: unknown = JSON.parse(text); // 这里只是把类型放宽成 unknown，是安全的
    return { ok: true, value };
  } catch (e) {
    return { ok: false, error: toError(e) };
  }
}

export function parseWith<S extends z.ZodType>(schema: S, text: string): Result<z.infer<S>> {
  const json = parseJson(text);
  if (!json.ok) return json;
  const r = schema.safeParse(json.value);
  return r.success
    ? { ok: true, value: r.data }
    : { ok: false, error: new Error(z.prettifyError(r.error), { cause: r.error }) };
}
```

### 3. `src/user.ts`

```ts
import { z } from 'zod';
import { parseWith, type Result } from './lib/json';

export const UserSchema = z.object({
  id: z.string().min(1),
  name: z.string().min(1),
  email: z.email(),
  age: z.number().int().nonnegative().optional(),
});
export type User = z.infer<typeof UserSchema>;
// 如果项目里已经有手写的 interface User，就保留它，并在上面的 schema 后面加
// `satisfies z.ZodType<User>`，两者不一致时编译会报错。

export const parseUser = (body: string): Result<User> => parseWith(UserSchema, body);
```

调用方：

```ts
const r = parseUser(body);
if (!r.ok) return res.status(400).json({ error: 'invalid_body', detail: r.error.message });
const user = r.value; // 类型是 User，而且已经校验过
```

zod 的 object 默认会去掉未声明的字段，所以 `__proto__`、`isAdmin` 这类多余的键不会传到后面。

### 4. `src/config.ts`

```ts
import { z } from 'zod';
import { parseWith } from './lib/json';

const CFG_KEY = 'cfg';

// 每个字段都用 .catch：这个字段缺失或类型不对时，只回退这一个字段
export const ConfigSchema = z.object({
  theme: z.enum(['light', 'dark']).catch('light'),
  pageSize: z.number().int().min(1).max(200).catch(20),
  locale: z.string().min(2).catch('zh-CN'),
});
export type Config = z.infer<typeof ConfigSchema>;

type StorageLike = Pick<Storage, 'getItem' | 'setItem'>;

export const defaultConfig = (): Config => ConfigSchema.parse({});

function defaultStorage(): StorageLike | undefined {
  try {
    return globalThis.localStorage ?? undefined; // SSR 环境里没有；禁用 cookie 时访问会抛 SecurityError
  } catch {
    return undefined;
  }
}

export function loadConfig(storage: StorageLike | undefined = defaultStorage()): Config {
  let raw: string | null;
  try {
    raw = storage?.getItem(CFG_KEY) ?? null;
  } catch {
    return defaultConfig();
  }
  if (raw === null) return defaultConfig();
  const r = parseWith(ConfigSchema, raw); // 只有 JSON 损坏或顶层不是对象时才会失败
  return r.ok ? r.value : defaultConfig(); // 不删除坏数据，下次 saveConfig 时会被覆盖
}

export function saveConfig(cfg: Config, storage: StorageLike | undefined = defaultStorage()): void {
  storage?.setItem(CFG_KEY, JSON.stringify(ConfigSchema.parse(cfg)));
}
```

### 5. 防止再写回去（关键）

只改现有代码不够，下次还会有人写 `as User`。下面这些配置会让编译和 lint 直接拦住：

`tsconfig.json`：
```jsonc
{ "compilerOptions": { "strict": true, "noUncheckedIndexedAccess": true } }
// strict 已经包含 useUnknownInCatchVariables，catch (e) 里的 e 是 unknown
```

`eslint.config.js`（typescript-eslint v8，需要开启 type-aware lint）：
```js
rules: {
  '@typescript-eslint/no-unsafe-type-assertion': 'error',   // 禁止 unknown/any → User 这种收窄断言
  '@typescript-eslint/no-unsafe-assignment': 'error',
  '@typescript-eslint/no-unsafe-member-access': 'error',
  '@typescript-eslint/no-explicit-any': 'error',
  '@typescript-eslint/use-unknown-in-catch-callback-variable': 'error', // 见下方说明
}
```

关于最后一条：`useUnknownInCatchVariables` 只管 `try/catch`。`promise.catch(err => err.message)` 里的 `err` 仍然是 `any`，必须靠这条规则来拦。

可选：安装 `@total-typescript/ts-reset`，让 `JSON.parse` 和 `res.json()` 返回 `unknown`。不过它拦不住 `as User`，所以 lint 规则仍然要加。

找出所有要改的地方：
```bash
rg -n 'JSON\.parse\([^)]*\)\s*as\s'
rg -n 'localStorage\.getItem\('
rg -n -U 'catch\s*\(\s*(\w+)[^)]*\)\s*\{[^}]*\1\.message'
rg -n '\.catch\(\s*\(?\w+\)?\s*=>'
```
最可靠的办法是先打开上面的 lint 规则，让 `eslint` 把剩下的地方全部报出来。

### 安全提醒
- `body` 和 `localStorage` 的内容都由调用方控制。即使校验通过，也只说明格式对，不说明内容可信。
- `User` 里如果有 `id`、`role` 这类身份或权限字段，必须从登录会话或服务端状态取，不能用请求体里的值。
- `cfg` 只能用于界面偏好，不能决定权限或功能开关。
- 第一个测试文件里有一条用例专门检查越权字段会被去掉。

```ts
import { parseUser, type User } from './user';

const valid = { id: 'u1', name: 'Ann', email: 'ann@example.com' };

describe('parseUser', () => {
```

`src/config.test.ts`
```ts
import { describe, it, expect } from 'vitest';
import { loadConfig, saveConfig, defaultConfig } from './config';

const mem = (init: Record<string, string> = {}) => {
  const m = new Map(Object.entries(init));
  return { getItem: (k: string) => m.get(k) ?? null, setItem: (k: string, v: string) => void m.set(k, v), m };
};

describe('loadConfig', () => {
  it('没有 cfg 键 → 默认值', () => expect(loadConfig(mem())).toEqual(defaultConfig()));
  it('JSON 损坏 → 默认值', () => expect(loadConfig(mem({ cfg: '{oops' }))).toEqual(defaultConfig()));
  it('顶层不是对象 → 默认值', () => expect(loadConfig(mem({ cfg: '"str"' }))).toEqual(defaultConfig()));
  it('部分字段非法 → 只回退这些字段', () => {
    const s = mem({ cfg: JSON.stringify({ theme: 'dark', pageSize: 'lots', locale: 1 }) });
    expect(loadConfig(s)).toEqual({ ...defaultConfig(), theme: 'dark' });
  });
  it('旧版本缺少新字段 → 补上默认值', () => {
    expect(loadConfig(mem({ cfg: '{"theme":"dark"}' }))).toEqual({ ...defaultConfig(), theme: 'dark' });
  });
  it('getItem 抛错（隐私模式）→ 默认值', () => {
    const s = { getItem: () => { throw new DOMException('denied', 'SecurityError'); }, setItem: () => {} };
    expect(loadConfig(s)).toEqual(defaultConfig());
  });
  it('没有 storage（SSR）→ 默认值', () => expect(loadConfig(undefined)).toEqual(defaultConfig()));
  it('save 后 load 结果一致', () => {
    const s = mem();
    const cfg = { theme: 'dark', pageSize: 50, locale: 'en-US' } as const;
    saveConfig(cfg, s);
    expect(loadConfig(s)).toEqual(cfg);
  });
  it('每次返回新对象，修改返回值不会影响默认值', () => {
    const a = loadConfig(mem());
    a.pageSize = 999;
    expect(loadConfig(mem()).pageSize).toBe(20);
  });
});
```
