## 1. tsconfig 结构：用 project references 实现增量检查

```
tsconfig.base.json          # 公共编译选项，只放一份
tsconfig.json               # 根配置：不编译文件，只引用每个包
packages/
  pkg-a/tsconfig.json       # composite，引用它依赖的包
  pkg-a/tsconfig.test.json  # 测试单独一个项目，引用 ./tsconfig.json
  pkg-b/...
```

**tsconfig.base.json**：把会受版本默认值影响的选项都写明，升级时就不会悄悄变化。

```jsonc
{
  "compilerOptions": {
    "strict": true,
    "target": "es2022",            // 按最老的运行时定
    "lib": ["es2022"],             // 浏览器包在自己的配置里加 "dom"
    "module": "nodenext",          // 由打包器解析的前端包改成 esnext + "moduleResolution": "bundler"
    "moduleResolution": "nodenext",
    "types": [],                   // 每个包在自己的配置里明确写要用的全局类型
    "composite": true,
    "declaration": true,
    "declarationMap": true,
    "incremental": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "noUncheckedSideEffectImports": true,
    "skipLibCheck": true           // 如有手写的 .d.ts，另加一条 skipLibCheck:false 的检查
  }
}
```

**packages/pkg-b/tsconfig.json**（假设 pkg-b 依赖 pkg-a）：

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "dist",
    "tsBuildInfoFile": "dist/.tsbuildinfo",
    "types": ["node"]
  },
  "include": ["src"],
  "references": [{ "path": "../pkg-a" }]
}
```

**packages/pkg-b/tsconfig.test.json**：

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": { "noEmit": false, "emitDeclarationOnly": true, "outDir": "dist-test", "rootDir": ".", "types": ["node", "vitest/globals"] },
  "include": ["test", "scripts"],
  "references": [{ "path": "./tsconfig.json" }]
}
```

**根目录 tsconfig.json**：

```jsonc
{
  "files": [],
  "references": [
    { "path": "packages/pkg-a" }, { "path": "packages/pkg-a/tsconfig.test.json" },
    { "path": "packages/pkg-b" }, { "path": "packages/pkg-b/tsconfig.test.json" }
    // …五个包都列上
  ]
}
```

规则：
- **references 必须和 `package.json` 里的 `workspace:*` 依赖一一对应。** 引用关系不能成环，出现环说明包的划分有问题，需要拆包，而不是在配置里绕过去。建议在 CI 加一个小脚本比对这两者，少了或多了都报错。
- **包之间按"先构建再引用"解析。** 每个包的 `exports` 指向 `dist`，并且 `types` 写在每个条件的第一位：

  ```json
  "exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } }
  ```

  这样 `tsc -b` 检查下游包时读的是上游的 `.d.ts`，不会重新检查上游源码。不要再用 `paths` 把包名映射到别的包的 `src`，否则编辑器、CI 和运行时看到的类型会不一致，增量检查也会失效。
- **增量效果：** 改了 pkg-a 的内部实现、但没改它的 `.d.ts`，只会重新检查 pkg-a。只有公开类型变了，才会继续检查依赖它的包。
- 想让公开类型更稳定，给导出函数写明返回类型。
- 把 `*.tsbuildinfo` 和 `dist` 加入 CI 缓存。

## 2. 升级步骤：分三次提交，不要和结构改造混在一起

先用 `pnpm view typescript dist-tags` 和官方发布说明确认当前最新大版本，下面按 6.0 和 7.0 来写。

**第 0 步：在现在的 5.x 上完成 references 改造。** 改完后的报错应和改造前完全一致，作为下面对比的基线。

**第 1 步：升到 6.0。**
1. 用 pnpm catalog 或 `pnpm.overrides` 让整个仓库只解析出一个 `typescript` 版本，然后用 `pnpm why typescript` 确认。
2. 6.0 改了几个默认值：`strict`、`module`、`target`、`types: []`、`rootDir`、`noUncheckedSideEffectImports`。上面的 base 已经把这些都写明了。
3. 处理 6.0 废弃的选项：
   - 删掉 `baseUrl`，把前缀直接写进每条 `paths`。更好的做法是改用 `package.json#imports`。
   - `moduleResolution: node` 或 `node10`：Node 直接加载的代码改成 `nodenext`，经打包器的代码改成 `bundler`。
4. 目标是**不加 `ignoreDeprecations` 也能零报错**。确实修不了的报错，用 `// @ts-expect-error <原因>` 局部压住，并记下后续要去掉。

**第 2 步：升到 7.0（原生编译器）。**
1. 先列出所有调用编译器 API 的工具：typescript-eslint、vue-tsc、ts-jest/ts-node、生成或打包 `.d.ts` 的工具（api-extractor、rollup-plugin-dts、tsup 的 dts）、编辑器插件。
2. 7.0 没有编程 API。这些工具改为依赖官方的 `@typescript/typescript6`（提供 6.0 的 API 和 `tsc6` 命令），然后把对应关系写进仓库文档。
3. 主检查改为 7.0 的 `tsc -b`。先确认你装的 7.x 支持 build 模式，以及你用到的每个选项。
4. 6.0 时废弃的选项在 7.0 直接报错，所以第 1 步必须彻底清干净。
