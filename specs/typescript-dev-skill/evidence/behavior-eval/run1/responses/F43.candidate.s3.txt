## 核心做法

`JSON.parse` 的返回值、`localStorage` 里读出的内容、`catch` 捕到的值，都来自程序外部，编译期没法保证它们的形状。处理方式：

1. 读进来先当 `unknown`。
2. 在入口处用运行时 schema 校验一次，得到准确的类型。
3. 后面的业务代码只拿校验过的值。
4. 校验失败时返回带类型的错误或默认值，不再用 `as` 强转。

示例用 zod。项目里如果已经有别的 schema 库（valibot、arktype 等），就用现有的，不要再加一个。

```ts
// src/boundary/errors.ts
function safeString(v: unknown): string {
  try { return String(v); } catch { return Object.prototype.toString.call(v); } // 没有原型的对象调 String 会抛错
}

export function getErrorMessage(e: unknown): string {
  if (e instanceof Error) return e.message;
  if (typeof e === 'string') return e;
  // 跨 iframe/realm 的 Error，或第三方库抛出的 { message } 对象
  if (typeof e === 'object' && e !== null && 'message' in e && typeof e.message === 'string') {
    return e.message;
  }
  try { return JSON.stringify(e) ?? safeString(e); } catch { return safeString(e); } // 处理循环引用、BigInt
}

export function toError(e: unknown): Error {
  return e instanceof Error ? e : new Error(getErrorMessage(e), { cause: e });
}
```

```ts
// src/boundary/json.ts
import type { Result } from './result';
import { getErrorMessage } from './errors';

export function parseJson(text: string): Result<unknown, SyntaxError> {
  try {
    const value: unknown = JSON.parse(text); // 把 any 收进 unknown，不做断言
    return { ok: true, value };
  } catch (e) {
    return { ok: false, error: e instanceof SyntaxError ? e : new SyntaxError(getErrorMessage(e)) };
  }
}
```

## 2. 替换 `JSON.parse(body) as User`

```ts
// src/user/user.ts
import { z } from 'zod';
import type { Result } from '../boundary/result';
import { parseJson } from '../boundary/json';

export const UserSchema = z.object({
  id: z.string().min(1),
  name: z.string(),
  email: z.string().email(),
}).strict(); // 多出来的字段直接拒绝，比如 role、isAdmin

export type User = z.infer<typeof UserSchema>; // 类型从 schema 推导，避免两份定义对不上

export type UserParseError =
  | { kind: 'invalid_json'; message: string }
  | { kind: 'invalid_shape'; issues: { path: string; message: string }[] };

export function parseUser(body: string): Result<User, UserParseError> {
  const json = parseJson(body);
  if (!json.ok) return { ok: false, error: { kind: 'invalid_json', message: json.error.message } };
  const r = UserSchema.safeParse(json.value);
  if (r.success) return { ok: true, value: r.data };
  return {
    ok: false,
    error: {
      kind: 'invalid_shape',
      issues: r.error.issues.map(i => ({ path: i.path.map(String).join('.'), message: i.message })),
    },
  };
}
```

调用处：
```ts
const parsed = parseUser(body);
if (!parsed.ok) return reply.status(400).send({ error: parsed.error });
const user = parsed.value; // 类型是 User，而且运行时已经校验过
```

**安全提醒：** 如果这个 body 是请求体，`id` 和角色、租户等权限相关的值应该从认证会话里取，不要相信 body 里的值。`.strict()` 就是用来拒绝伪造的 `role` 等字段的，下面有对应的反向测试。

## 3. 替换 `localStorage.getItem('cfg')` 后直接断言

```ts
// src/config/config.ts
import { z } from 'zod';
import { parseJson } from '../boundary/json';

export const ConfigSchema = z.object({
  theme: z.enum(['light', 'dark']),
  pageSize: z.number().int().min(1).max(200),
});
export type Config = z.infer<typeof ConfigSchema>;
export const DEFAULT_CONFIG: Config = { theme: 'light', pageSize: 20 };

export type LoadedConfig =
  | { source: 'stored'; config: Config }
  | { source: 'default'; config: Config }                 // 没存过，或存储不可用
  | { source: 'default_after_corrupt'; config: Config };  // 存了但内容损坏或格式过时

export function loadConfig(storage: Pick<Storage, 'getItem'>, key = 'cfg'): LoadedConfig {
  let raw: string | null;
  try { raw = storage.getItem(key); } catch { return { source: 'default', config: DEFAULT_CONFIG }; } // Safari 隐私模式、沙箱 iframe 下会抛错
  if (raw === null) return { source: 'default', config: DEFAULT_CONFIG };
  const json = parseJson(raw);
  const r = json.ok ? ConfigSchema.safeParse(json.value) : null;
  return r?.success
    ? { source: 'stored', config: r.data }
    : { source: 'default_after_corrupt', config: DEFAULT_CONFIG };
}
```

调用方式：`loadConfig(window.localStorage)`。

现在只要有一个字段不对，整份配置都会回退到默认值。如果希望升级后旧配置能保留还有效的字段，可以给每个字段加 `.catch(默认值)`，按字段单独回退。

## 5. 让编译器和 lint 防止再犯

- **tsconfig：** 打开 `"strict": true`，它包含 `useUnknownInCatchVariables`。打开后所有 `err.message` 都会编译报错，正好可以用来找出全部位置。显式写成 `catch (err: any)` 的地方编译器不会报，要靠下面的 grep 找。`Error` 的 `cause` 选项需要 `lib` 至少到 `es2022`。
- **typescript-eslint：** 使用 `recommendedTypeChecked`，其中的 `no-unsafe-assignment` 和 `no-unsafe-member-access` 会拦住 `any` 的使用。另外开启 `use-unknown-in-catch-callback-variable`，覆盖 `.catch(e => …)` 的写法。再加一条规则，专门禁止对 `JSON.parse` 的结果做断言：
  ```js
  'no-restricted-syntax': ['error', {
    selector: "TSAsExpression > CallExpression[callee.object.name='JSON'][callee.property.name='parse']",
    message: '外部 JSON 用 parseJson + schema 校验，不要用 as 断言',
  }],
  ```
- **可选：** `@total-typescript/ts-reset` 能把 `JSON.parse` 的返回类型全局改成 `unknown`，影响整个项目。
- **找出现有代码：**
  ```
  rg -n 'JSON\.parse\(.*\)\s+as\s'
  rg -n 'getItem\('
  rg -n 'catch\s*\(\w+\s*:\s*any\)'
  ```

const store = (v: string | null) => ({ getItem: () => v });
