## 原则

`JSON.parse` 的结果、`localStorage` 读到的值、`catch` 捕获的错误，都来自程序外部或运行时，编译期的类型管不到它们。三者统一这样处理：**先当作 `unknown`，在读入的那一处用运行时代码检查一次，检查通过才变成精确类型**。

- `as User` 只是让编译器相信你，运行时什么都不检查。数据格式不对时，错误会在更后面的业务代码里冒出来，很难定位。
- 类型从 schema 推导出来（`z.infer`），不要另写一份 `interface User`，否则两边迟早不一致。
- 仓库里已经有 schema 库（zod、valibot 等）就用现有的，不要再加第二个。下面以 zod v4 为例；v3 的写法差别在注释里标出。

## 1. 公共工具：Result 类型和安全解析

```ts
// src/boundary/parse.ts
import { z } from 'zod';

export type Result<T, E = string> =
  | { ok: true; value: T }
  | { ok: false; error: E };

/** 把 JSON.parse 和 schema 校验合成一步，失败时返回错误而不是抛异常 */
export function parseJson<S extends z.ZodType>(
  text: string,
  schema: S,
): Result<z.infer<S>> {
  let raw: unknown;
  try {
    raw = JSON.parse(text);
  } catch (e) {
    return { ok: false, error: `invalid JSON: ${errorMessage(e)}` };
  }
  const r = schema.safeParse(raw);
  return r.success
    ? { ok: true, value: r.data }
    : { ok: false, error: z.prettifyError(r.error) }; // v3: r.error.message
}
```

## 2. User：替换 `JSON.parse(body) as User`

```ts
// src/user/user.ts
import { z } from 'zod';
import { parseJson, type Result } from '../boundary/parse';

export const UserSchema = z.object({
  id: z.string().min(1).brand<'UserId'>(), // 品牌类型：普通字符串不能冒充 UserId
  name: z.string().min(1),
  email: z.email(),                          // v3: z.string().email()
  role: z.enum(['admin', 'member']),
});
// z.object 默认会删掉多余字段；涉及权限的输入改用 z.strictObject，直接拒绝多余字段

export type User = z.infer<typeof UserSchema>;

export function parseUser(body: string): Result<User> {
  return parseJson(body, UserSchema);
}
```

调用方改成：

```ts
const r = parseUser(body);
if (!r.ok) return reply.status(400).send({ error: r.error }); // 在边界处转成 400，不让坏数据往下走
const user = r.value; // 类型是 User，而且运行时已经检查过
```

## 3. 配置：替换 `localStorage.getItem('cfg') as Config`

```ts
// src/config/config.ts
import { z } from 'zod';
import { parseJson } from '../boundary/parse';

export const ConfigSchema = z.object({
  theme: z.enum(['light', 'dark']),
  pageSize: z.number().int().min(1).max(200),
});
export type Config = z.infer<typeof ConfigSchema>;

export const DEFAULT_CONFIG = { theme: 'light', pageSize: 20 } as const satisfies Config;

type ReadableStorage = Pick<Storage, 'getItem'>;

export function loadConfig(storage: ReadableStorage = globalThis.localStorage): Config {
  let raw: string | null;
  try {
    raw = storage.getItem('cfg'); // 浏览器禁用存储或隐私模式下可能抛异常
  } catch {
    return { ...DEFAULT_CONFIG };
  }
  if (raw === null) return { ...DEFAULT_CONFIG };
  const r = parseJson(raw, ConfigSchema);
  return r.ok ? r.value : { ...DEFAULT_CONFIG }; // 返回副本，调用方改了也不会污染默认值
}
```

- 存储通过参数传入，测试时不需要模拟浏览器环境。
- 如果希望某个字段坏了只回退这一个字段，而不是整个配置回到默认值，可以给每个字段加 `.catch(默认值)`。

## 4. catch：替换直接用 `err.message`

```ts
// src/boundary/error.ts
export function errorMessage(err: unknown): string {
  if (err instanceof Error) return err.message;
  if (typeof err === 'string') return err;
  try {
    return JSON.stringify(err) ?? String(err);
  } catch {
    return 'Unknown error'; // 循环引用，或没有原型的对象让 String() 抛异常
  }
}

/** 需要重新抛出时：保证抛出的是 Error，并把原始值放进 cause */
export function toError(err: unknown): Error {
  return err instanceof Error ? err : new Error(errorMessage(err), { cause: err });
}
```

try { await save(); }
catch (err) {            // 开启 strict 后 err 的类型是 unknown，直接写 err.message 编译不过
  log.warn(errorMessage(err));

## 5. 让编译器和 lint 防止回退

tsconfig：

```jsonc
{
  "compilerOptions": {
    "strict": true,                      // 包含 useUnknownInCatchVariables
    "noUncheckedIndexedAccess": true
  }
}
```

如果现在写 `err.message` 能编译通过，原因只可能是：没开 `strict`，或者写成了 `catch (err: any)`。两种都要改掉。

typescript-eslint（需要类型信息的规则）：

```js
rules: {
  '@typescript-eslint/no-unsafe-type-assertion': 'error', // 拦截 `JSON.parse(x) as User` 这类从 any 出发的断言
  '@typescript-eslint/no-unsafe-assignment': 'error',
  '@typescript-eslint/no-unsafe-member-access': 'error',
  '@typescript-eslint/no-unsafe-argument': 'error',
  '@typescript-eslint/no-explicit-any': 'error',
  '@typescript-eslint/use-unknown-in-catch-callback-variable': 'error', // Promise .catch(e => …) 回调也按 unknown 处理
}
```

不要指望 `ts-reset` 解决问题。它会让 `JSON.parse` 返回 `unknown`，但 `unknown as User` 照样能编译，最终还是要靠上面的 lint 规则拦住。

找出所有要改的地方：

```bash
rg -n 'JSON\.parse\([^)]*\)\s*as\s' src
rg -n 'getItem\([^)]*\)[^;]*\bas\s' src
rg -n 'catch\s*\(\s*\w+\s*:\s*any' src
rg -n '\bas unknown as\b' src
```

// src/user/user.test.ts
import { describe, it, expect } from 'vitest';
import { parseUser } from './user';

const valid = { id: 'u1', name: 'Ann', email: 'a@example.com', role: 'member' };

describe('parseUser', () => {
  it('accepts a valid body', () => {
    const r = parseUser(JSON.stringify(valid));

  });
  it('rejects malformed JSON without throwing', () => {
    const r = parseUser('{bad');

  });
  it.each([
    ['missing field', { ...valid, email: undefined }],
    ['wrong type', { ...valid, name: 42 }],
    ['bad enum', { ...valid, role: 'root' }],
    ['empty id', { ...valid, id: '' }],
    ['not an object', [valid]],
    ['null', null],
  ])('rejects %s', (_, input) => {
    expect(parseUser(JSON.stringify(input)).ok).toBe(false);
  });
  it('drops unknown keys (incl. privilege fields)', () => {
    const r = parseUser(JSON.stringify({ ...valid, isAdmin: true }));
    expect(r.ok && 'isAdmin' in r.value).toBe(false);
  });
});
