## 思路

- **为什么要改 `moduleResolution`**：`bundler` 适合"所有 import 都由打包器解析"的场景。发布到 npm 的库会被 Node 直接加载，`bundler` 模式会放过一些在 Node 里运行会失败的写法，比如不带扩展名的相对 import。所以类型检查和 ESM 构建都改用 `nodenext`。
- **为什么不能共用一份 `.d.ts`**：同一个 `.d.ts` 不能同时正确描述 ESM 和 CJS 两种格式。共用的话，`attw` 会报"Masquerading as CJS/ESM"（声明文件的格式和实际 JS 不一致）。所以 ESM 和 CJS 各编译一次，各自产出 JS 和 `.d.ts`。
- **TS 怎么区分两份声明**：TS 按离文件最近的 `package.json#type` 判断 `.d.ts` 是哪种格式。根目录设 `"type": "module"`，再在 `dist/cjs/` 里放一个 `{"type":"commonjs"}`，两份声明就分别按 ESM 和 CJS 解读。

## 1. `package.json`

```jsonc
{
  "type": "module",
  "main": "./dist/cjs/index.js",          // 给不认 exports 的老工具
  "types": "./dist/cjs/index.d.ts",       // 给 node10 解析的老 TS 用户
  "exports": {
    ".": {
      "import":  { "types": "./dist/esm/index.d.ts", "default": "./dist/esm/index.js" },
      "require": { "types": "./dist/cjs/index.d.ts", "default": "./dist/cjs/index.js" }
    },
    "./package.json": "./package.json"
  },
  "files": ["dist"],
  "scripts": {
    "clean": "node -e \"require('node:fs').rmSync('dist',{recursive:true,force:true})\"",
    "typecheck": "tsc -p tsconfig.json --noEmit",
    "build:esm": "tsc -p tsconfig.esm.json",
    "build:cjs": "tsc -p tsconfig.cjs.json && node -e \"require('node:fs').writeFileSync('dist/cjs/package.json','{\\\"type\\\":\\\"commonjs\\\"}')\"",
    "build": "npm run clean && npm run build:esm && npm run build:cjs",
    "check:pack": "attw --pack . && publint",
    "prepublishOnly": "npm run typecheck && npm run build && npm run check:pack"
  },
  "devDependencies": {
    "@arethetypeswrong/cli": "^0.18.0",
    "publint": "^0.3.0"
  }
}
```

要点：

- 在 `import` 和 `require` 里面，`types` 都必须排在第一位。TS 取第一个匹配的条件，排在后面的 `types` 永远不会被读到。
- 如果库的公开类型引用了别的包，那些包要放在 `dependencies` 或 `peerDependencies` 里，不能只放在 `devDependencies`。

## 2. tsconfig 拆成三份

`tsconfig.json`：负责类型检查，也给编辑器用，覆盖源码和测试。

```jsonc
{
  "compilerOptions": {
    "target": "es2022",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "strict": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "rootDir": "src",
    "noEmit": true
    // 不要开 verbatimModuleSyntax：CJS 那次构建会因为源码是 ESM 语法而报错
  },
  "include": ["src"]   // 测试如果在 src 外，单独建一个 tsconfig.test.json 也纳入 typecheck
}
```

`tsconfig.esm.json`：

```jsonc
{
  "extends": "./tsconfig.json",
  "compilerOptions": { "noEmit": false, "outDir": "dist/esm" },
  "include": ["src"],
  "exclude": ["src/**/*.test.ts"]
}
```

`tsconfig.cjs.json`：

```jsonc
{
  "extends": "./tsconfig.esm.json",
  "compilerOptions": {
    "module": "commonjs",
    "moduleResolution": "bundler",   // TS ≥ 6.0；TS 5.x 改成 "node10"
    "outDir": "dist/cjs"
  }
}
```

`moduleResolution` 按 TS 版本选：

- **TS 5.x**：这里用 `node10`。
- **TS 6.0**：`node10` 已经弃用，换成 `bundler`。6.0 起允许 `bundler` 搭配 `module: commonjs`。如果你的版本不接受这个组合，构建会直接报错，第一步就能发现。

## 3. 源码需要改的地方

- **相对 import 补 `.js` 扩展名**：`nodenext` 强制要求。比如 `./utils` 要写成 `./utils.js`，目录导入 `./lib` 要写成 `./lib/index.js`。CJS 构建输出的 `require("./utils.js")` 照样能运行。
- **不要用 `import.meta` 和顶层 `await`**：CJS 构建会失败。
- **公开 API 建议只用具名导出**：如果用 `export default`，CJS 用户拿到的是 `require('pkg').default`，`attw` 也会提示这个问题。
- **双包风险**：如果库里有模块级状态，比如单例、缓存，或者依赖 `instanceof` 判断的类，那么同一个进程里 ESM 和 CJS 会各加载一份实例。没有这类状态就可以忽略。

## 4. 验证（都需要你本地执行）

```bash
# 1) 类型检查（这是唯一的类型证据，构建成功不算）
npm run typecheck

# 2) 构建，并抽查产物格式
npm run build
head -3 dist/esm/index.js     # 应为 export ...
head -3 dist/cjs/index.js     # 应含 "use strict" / exports.
cat dist/cjs/package.json     # {"type":"commonjs"}

# 3) 检查打包内容和类型解析
npm pack --dry-run            # 文件列表只有 dist/** 与 package.json/README/LICENSE
npx attw --pack .             # node10 / node16-CJS / node16-ESM / bundler 四列都应为 🟢
npx publint
```

```bash
# 4) 用 tarball 搭一个临时消费者，验证运行时和三种类型环境
TGZ=$(npm pack | tail -1); D=$(mktemp -d); cp "$TGZ" "$D"; cd "$D"
npm init -y >/dev/null && npm i ./"$TGZ" typescript
PKG=<你的包名>

node -e "console.log(Object.keys(require('$PKG')))"                                  # CJS 运行时
node --input-type=module -e "import * as m from '$PKG'; console.log(Object.keys(m))" # ESM 运行时

printf "import * as m from '%s'; export const k = Object.keys(m);\n" $PKG > esm.mts
printf "import m = require('%s'); export const k = Object.keys(m);\n"  $PKG > cjs.cts
printf "import * as m from '%s'; export const k = Object.keys(m);\n"  $PKG > bnd.ts
npx tsc --noEmit --strict --module nodenext --moduleResolution nodenext esm.mts cjs.cts
npx tsc --noEmit --strict --module esnext   --moduleResolution bundler  bnd.ts
```

判定标准：

- `attw` 四列都是绿色。
- 两条运行时命令都能打印出导出名。
- 两条 `tsc` 命令都没有报错。
- 在编辑器里，`esm.mts` 里的符号应该跳转到 `dist/esm/*.d.ts`，`cjs.cts` 里的应该跳转到 `dist/cjs/*.d.ts`。

只对 `src` 跑检查不算数，必须对打包出来的 tarball 验证，因为用户装到的是 tarball。
