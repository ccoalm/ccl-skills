## 思路

还是用 tsc 编译两次，一次出 ESM、一次出 CJS，不引入打包工具。要让两边都拿到正确的类型，关键是**两份产物各带各的 `.d.ts`**，并且 TS 和 Node 都能判断出每份 `.d.ts` 是 ESM 还是 CJS。如果两边共用 `dist/index.d.ts`，ESM 和 CJS 里总有一边类型是错的。工具里把这种情况报成 "Masquerading as ESM/CJS"。

现在的配置有两个问题要先处理：

1. `moduleResolution: bundler` 允许写 `import './foo'` 不带扩展名。这样编出来的 ESM 在 Node 里会报 `ERR_MODULE_NOT_FOUND`。所以 ESM 构建要改成 `nodenext`，让编译器强制检查扩展名。
2. 只有 `main` 和 `types` 没有 `exports`，Node 和 TS 就没法按 `import` / `require` 分别给出不同的文件。

## 改动

### 1. 源码：相对导入补 `.js`

```ts
// 之前
import { foo } from './foo';
import { bar } from './utils';
// 之后
import { foo } from './foo.js';
import { bar } from './utils/index.js';
```

还有几点：
- 只用命名导出。如果用 `export default`，CJS 用户就得写 `require('pkg').default`。
- 源码里不要用 `import.meta` 和顶层 `await`，CJS 产物不支持。

### 2. tsconfig 拆成三份

`tsconfig.base.json`：
```json
{
  "compilerOptions": {
    "target": "es2022",
    "strict": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "rootDir": "src",
    "esModuleInterop": true,
    "skipLibCheck": true,
    "isolatedModules": true
  },
  "include": ["src"],
  "exclude": ["src/**/*.test.ts", "src/**/__tests__/**"]
}
```

`tsconfig.json`（编辑器和类型检查用，规则和 ESM 构建一致）：
```json
{
  "extends": "./tsconfig.base.json",
  "compilerOptions": { "module": "nodenext", "moduleResolution": "nodenext", "noEmit": true }
}
```

`tsconfig.esm.json`：
```json
{
  "extends": "./tsconfig.base.json",
  "compilerOptions": { "module": "nodenext", "moduleResolution": "nodenext", "outDir": "dist/esm" }
}
```

`tsconfig.cjs.json`：
```json
{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "module": "commonjs",
    "moduleResolution": "node10",
    "verbatimModuleSyntax": false,
    "outDir": "dist/cjs"
  }
}
```

关于 CJS 这份配置：
- **TypeScript 版本要确认**：TS 6 起 `moduleResolution: node10` 已被废弃。如果你用的是 TS 6 及以上，改成 `"moduleResolution": "bundler"`，我记得 TS 6 起这个组合允许和 `module: commonjs` 一起用。以 `tsc -p tsconfig.cjs.json` 不报错为准。
- 如果 base 里开着 `verbatimModuleSyntax`，CJS 这份必须关掉，否则 `import` 语法会直接报错。

### 3. `package.json`

```json
{
  "type": "module",
  "main": "./dist/cjs/index.js",
  "module": "./dist/esm/index.js",
  "types": "./dist/cjs/index.d.ts",
  "exports": {
    ".": {
      "import": {
        "types": "./dist/esm/index.d.ts",
        "default": "./dist/esm/index.js"
      },
      "require": {
        "types": "./dist/cjs/index.d.ts",
        "default": "./dist/cjs/index.js"
      }
    },
    "./package.json": "./package.json"
  },
  "files": ["dist"],
  "sideEffects": false,
  "scripts": {
    "clean": "node -e \"fs.rmSync('dist',{recursive:true,force:true})\"",
    "build": "npm run clean && tsc -p tsconfig.esm.json && tsc -p tsconfig.cjs.json && node -e \"fs.writeFileSync('dist/cjs/package.json', JSON.stringify({type:'commonjs'}))\"",
    "typecheck": "tsc --noEmit",
    "check:pkg": "publint && attw --pack .",
    "prepublishOnly": "npm run build && npm run check:pkg"
  },
  "devDependencies": {
    "@arethetypeswrong/cli": "^0.18.0",
    "publint": "^0.3.0"
  }
}
```

几个容易出错的地方：
- **`dist/cjs/package.json` 写 `{"type":"commonjs"}` 必须有。** 根目录是 `type: module`，少了这个文件，Node 会把 `dist/cjs/*.js` 当成 ESM 加载，TS 也会把 `dist/cjs/*.d.ts` 当成 ESM 类型。
- `exports` 里 `types` 必须放在每个条件的第一位。
- 顶层的 `main` 和 `types` 留着，给还在用 `moduleResolution: node10` 的老 TS 用户。
- 根目录加 `"type": "module"` 后，仓库里其他 `.js` 文件（比如 `eslint.config.js`、`jest.config.js` 这类配置）也会被当成 ESM。里面用了 `require` 的，要改名为 `.cjs`。
- 两份 `.d.ts` 结构相同，`files` 里列 `dist` 就会全部发出去，不需要再配 `typesVersions`。如果以后加子路径导出，比如 `./utils`，在 `exports` 里照同样结构再加一项。

**双包风险（dual-package hazard）**：如果用户同一个进程里既 `import` 又 `require` 了这个包，就会加载两份实例。`instanceof` 判断、模块级缓存或单例会分裂成两份。库里如果有这类状态，要么把它放到无状态的设计里，要么考虑只发 ESM：Node 20.19+ / 22.12+ 已经支持 `require(esm)`，但老 Node 和老 TS 的配置会因此失去支持，这是需要你来定的取舍。

**3. 打成 tarball，在一个干净目录里装上真实调用一遍**

把 `your-lib` 换成包名，`someFn` 换成实际导出的函数。

```bash
set -euo pipefail
PKG_DIR=$PWD
TARBALL=$(npm pack --silent)
TMP=$(mktemp -d); cd "$TMP"
npm init -y >/dev/null
npm i "$PKG_DIR/$TARBALL" typescript @types/node >/dev/null

# 运行时
cat > esm.mjs <<'EOF'
import { someFn } from 'your-lib';
import assert from 'node:assert';
assert.equal(typeof someFn, 'function'); console.log('esm runtime ok');
EOF
cat > cjs.cjs <<'EOF'
const { someFn } = require('your-lib');
const assert = require('node:assert');
assert.equal(typeof someFn, 'function'); console.log('cjs runtime ok');
EOF
node esm.mjs && node cjs.cjs

# 类型：ESM 和 CJS 两边，各用 nodenext 和 bundler 解析
echo "import { someFn } from 'your-lib'; const f: typeof someFn = someFn; export {};" > a.mts
echo "import { someFn } from 'your-lib'; const f: typeof someFn = someFn; export {};" > b.cts
npx tsc --noEmit --strict --module nodenext --moduleResolution nodenext a.mts b.cts
npx tsc --noEmit --strict --module esnext --moduleResolution bundler a.mts

# 确认每边解析到的是自己那份 .d.ts
npx tsc --noEmit --module nodenext --moduleResolution nodenext --traceResolution a.mts b.cts \
  | grep "successfully resolved to" | grep your-lib
```
最后一条命令的输出里，`a.mts` 应该解析到 `dist/esm/index.d.ts`，`b.cts` 应该解析到 `dist/cjs/index.d.ts`。

**4. 有测试的话**，再跑一遍原来的测试，确认补 `.js` 扩展名之后测试工具还能正常解析。Jest 可能需要配置 `moduleNameMapper`，把 `.js` 映射回 `.ts`；Vitest 不需要额外配置。
