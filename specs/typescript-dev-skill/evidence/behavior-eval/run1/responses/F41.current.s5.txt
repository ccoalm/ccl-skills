## 现在的问题

1. **ESM 产物在 Node 里跑不起来。** `moduleResolution: bundler` 允许写 `import './utils'` 这种不带扩展名的路径，tsc 会原样输出。Node 的 ESM 必须写全路径，所以 Node 用户 import 时会直接报错。
2. **没有 CJS 产物。** `require()` 拿到的是 ESM 文件。Node 22.12 之前直接报 `ERR_REQUIRE_ESM`。
3. **两种用户共用一份 `.d.ts`。** TS 会把同一份类型同时当成 ESM 和 CJS，arethetypeswrong（attw，检查 npm 包类型的工具）会报 “Masquerading as ESM/CJS”。
4. **没有 `exports` 字段。** 用户可以深层引入 `dist/` 里的任意文件，Node 也无法按 `import` / `require` 选不同的入口。

## 改动

### 1. `tsconfig.base.json`（公共配置）

```json
{
  "compilerOptions": {
    "target": "es2020",
    "lib": ["es2020"],
    "strict": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "rootDir": "src",
    "skipLibCheck": true,
    "isolatedModules": true
  },
  "include": ["src"]
}
```

不要开 `verbatimModuleSyntax`，它和 CJS 输出冲突。

### 2. `tsconfig.esm.json`

```json
{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "outDir": "dist/esm"
  }
}
```

### 3. `tsconfig.cjs.json`

```json
{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "module": "commonjs",
    "moduleResolution": "node10",
    "outDir": "dist/cjs"
  }
}
```

- **TS 5.x：** 按上面写即可。
- **TS 6.x：** `node10` 已被标记为废弃。可以加 `"ignoreDeprecations": "6.0"`，也可以把 `moduleResolution` 改成 `bundler`（我记得 6.0 起 `bundler` 能和 `module: commonjs` 搭配，用前用你的 tsc 版本确认一下）。

原来的 `tsconfig.json` 可以改成继承 `tsconfig.esm.json`，编辑器和 `tsc --noEmit` 就会按 Node 的 ESM 规则检查。

### 4. 源码里的相对 import 补上 `.js`

```ts
// 之前
import { x } from './utils'
export * from './types'
// 之后
import { x } from './utils.js'            // 写 .js，TS 会找到 utils.ts
export * from './types.js'
import { y } from './helpers/index.js'    // 目录引入要写到 index.js
```

`nodenext` 会把每一处漏写的地方报成类型错误，照着改就行。

另外建议**公共 API 只用具名导出**。`export default` 编译成 CJS 后，用户要写 `require('pkg').default` 才能拿到。

### 5. `package.json`

```json
{
  "name": "your-lib",
  "type": "module",
  "main": "./dist/cjs/index.js",
  "module": "./dist/esm/index.js",
  "types": "./dist/cjs/index.d.ts",
  "exports": {
    ".": {
      "import": {
        "types": "./dist/esm/index.d.ts",
        "default": "./dist/esm/index.js"
      },
      "require": {
        "types": "./dist/cjs/index.d.ts",
        "default": "./dist/cjs/index.js"
      }
    },
    "./package.json": "./package.json"
  },
  "files": ["dist"],
  "sideEffects": false,
  "scripts": {
    "clean": "node -e \"require('fs').rmSync('dist',{recursive:true,force:true})\"",
    "build": "npm run clean && tsc -p tsconfig.esm.json && tsc -p tsconfig.cjs.json && node -e \"require('fs').writeFileSync('dist/cjs/package.json', JSON.stringify({type:'commonjs'}))\"",
    "check:pkg": "publint && attw --pack .",
    "prepublishOnly": "npm run build && npm run check:pkg"
  },
  "devDependencies": {
    "@arethetypeswrong/cli": "^0.18.0",
    "publint": "^0.3.0"
  }
}
```

为什么这样写：

- **`types` 在每个条件里都要排第一。** 这样 TS 才会按 import 或 require 选对类型文件。
- **`dist/cjs/package.json` 里写 `{"type":"commonjs"}` 是关键。** 有了它，Node 会把 `dist/cjs/*.js` 当成 CJS，TS 也会把 `dist/cjs/*.d.ts` 当成 CJS 的类型。
- **顶层的 `main` / `types` 指向 CJS。** 这是给不认识 `exports` 的老工具和 `moduleResolution: node10` 的 TS 用户留的入口。
- **根目录设了 `"type": "module"`。** 仓库里其他用 `require` 写的 `.js` 配置文件（eslint、jest 等）要改名成 `.cjs`。

### 已知的取舍

- **同一份代码会有两个副本。** 如果同一个应用里既有 import 又有 require，库会被加载两次，模块里的状态、`instanceof`、单例都会各有一份。如果库是纯函数就不用管；如果有共享状态，就把状态放进 CJS 那份，ESM 那份只做一层包装去引用它。
- **想继续用不带扩展名的 import，就换打包工具。** 可以改用 tsdown 或 tsup 这类工具，同时输出 esm 和 cjs 并开启类型生成。但它们输出的文件名（`.cjs`、`.d.cts` 等）随版本变化，`exports` 要按实际产物来写，下面的验证照样要做。

最终证据要从打包出来的 tarball 安装后实测，不要用本地路径：

```bash
npm pack                                # 生成 your-lib-x.y.z.tgz
TMP=$(mktemp -d) && cp your-lib-*.tgz "$TMP" && cd "$TMP"
npm init -y >/dev/null && npm i ./your-lib-*.tgz typescript@<你的版本> @types/node

# 运行时：import 和 require 两条路都要通
echo "import { foo } from 'your-lib'; console.log('esm', typeof foo)"      > t.mjs
echo "const { foo } = require('your-lib'); console.log('cjs', typeof foo)" > t.cjs
node t.mjs && node t.cjs                 # 两行都应输出 function / object

# 类型：ESM、CJS、bundler 三种用户
echo "import { foo } from 'your-lib'; foo satisfies unknown"           > a.mts
echo "import { foo } = require('your-lib'); foo satisfies unknown"     > b.cts
npx tsc --noEmit --strict --module nodenext --moduleResolution nodenext a.mts b.cts
echo "import { foo } from 'your-lib'; foo satisfies unknown"           > c.ts
npx tsc --noEmit --strict --module esnext --moduleResolution bundler c.ts
```

把 `foo` 换成你库里真实导出的名字。如果想确认类型检查确实在起作用，可以在 `a.mts` 里故意写错参数类型，`tsc` 应该报错。
