## 做法：外部来的数据一律先当 `unknown`，在入口校验一次

`JSON.parse` 的返回值、`localStorage` 读出的内容、`catch` 拿到的变量，在运行时都可能是任何东西。`as User` 只让编译器不再报错，运行时什么也不检查。改法是：这些值先当成 `unknown`，在入口处用运行时校验转成确定的类型。校验失败时返回带类型的失败结果，不再用 `as` 断言。

### 1. 公共工具：`src/boundary/parse.ts`

```ts
import { z } from 'zod';
import { errorMessage } from './errors';

export type ParseFailure =
  | { kind: 'invalid_json'; message: string }
  | { kind: 'invalid_shape'; issues: ReadonlyArray<{ path: string; message: string }> };

export type ParseResult<T> = { ok: true; value: T } | { ok: false; error: ParseFailure };

/** JSON.parse 的返回值是 any，这里改成 unknown，异常改成失败结果 */
export function parseJson(text: string): ParseResult<unknown> {
  try {
    const value: unknown = JSON.parse(text);
    return { ok: true, value };
  } catch (e) {
    return { ok: false, error: { kind: 'invalid_json', message: errorMessage(e) } };
  }
}

export function parseWith<T>(schema: z.ZodType<T>, input: unknown): ParseResult<T> {
  const r = schema.safeParse(input);
  if (r.success) return { ok: true, value: r.data };
  return {
    ok: false,
    error: {
      kind: 'invalid_shape',
      // path 里可能有 symbol，直接 join 会抛错，所以先 map(String)
      issues: r.error.issues.map((i) => ({ path: i.path.map(String).join('.'), message: i.message })),
    },
  };
}
```

### 2. User：`src/user.ts`

```ts
import { z } from 'zod';
import { parseJson, parseWith, type ParseResult } from './boundary/parse';

// 只保留 schema 这一份定义，类型从 schema 推出来，避免两处定义不一致
export const UserSchema = z.strictObject({
  id: z.string().min(1),
  name: z.string().min(1),
  email: z.string().email(),
  age: z.number().int().nonnegative().optional(),
});
export type User = z.infer<typeof UserSchema>;

export function parseUser(body: string): ParseResult<User> {
  const json = parseJson(body);
  return json.ok ? parseWith(UserSchema, json.value) : json;
}
```

调用处：

```ts
const r = parseUser(body);
if (!r.ok) return reply.status(400).send({ error: r.error.kind, issues: r.error.kind === 'invalid_shape' ? r.error.issues : [] });
const user = r.value; // User，已经过运行时校验
```

安全上要注意两点：

- **只验了格式，不代表可信。** 请求体完全由调用方控制。user id、角色、租户这类决定权限的值，必须从登录态或服务端数据里取，不能从 body 里取。
- **多余字段直接拒绝。** `strictObject` 会拒掉 schema 里没有的字段，例如 `isAdmin`、`__proto__`。如果直接 `as User` 再展开写库，这些字段会被混进去。

### 3. 配置：`src/config.ts`

```ts
import { z } from 'zod';
import { parseJson, parseWith } from './boundary/parse';

export const ConfigSchema = z.object({   // 非 strict：旧版本写入的多余字段会被去掉，不会报错
  theme: z.enum(['light', 'dark']),
  pageSize: z.number().int().min(10).max(100),
  features: z.array(z.string()),
});
export type Config = z.infer<typeof ConfigSchema>;

export const defaultConfig = (): Config => ({ theme: 'light', pageSize: 20, features: [] }); // 每次返回新对象，避免多处共享同一个对象被改

export type StorageLike = Pick<Storage, 'getItem'>;
export type ConfigLoad =
  | { source: 'stored'; config: Config }
  | { source: 'default'; config: Config; reason: 'unavailable' | 'missing' | 'invalid_json' | 'invalid_shape' };

const KEY = 'cfg';

// 传入一个取 storage 的函数：在 Safari 无痕模式或禁用 cookie 时，访问 window.localStorage 本身就会抛错
export function loadConfig(getStorage: () => StorageLike = () => globalThis.localStorage): ConfigLoad {
  let raw: string | null;
  try {
    raw = getStorage().getItem(KEY);
  } catch {
    return { source: 'default', config: defaultConfig(), reason: 'unavailable' };
  }
  if (raw === null) return { source: 'default', config: defaultConfig(), reason: 'missing' };
  const json = parseJson(raw);
  if (!json.ok) return { source: 'default', config: defaultConfig(), reason: 'invalid_json' };
  const cfg = parseWith(ConfigSchema, json.value);
  return cfg.ok
    ? { source: 'stored', config: cfg.value }
    : { source: 'default', config: defaultConfig(), reason: 'invalid_shape' };
}
```

配置损坏时，这里选择整份退回默认值，并返回原因，不去删用户的存储数据。如果你希望只修好有问题的字段，可以给各字段加 `.catch(默认值)`。

### 4. catch：`src/boundary/errors.ts`

```ts
export function errorMessage(e: unknown): string {
  if (e instanceof Error) return e.message;
  if (typeof e === 'string') return e;
  // 兼容 iframe/worker 等其他运行环境里抛出的 Error，以及形如 { message } 的对象
  if (typeof e === 'object' && e !== null && 'message' in e && typeof e.message === 'string') return e.message;
  try {
    return JSON.stringify(e) ?? String(e);
  } catch {
    try { return String(e); } catch { return 'Unknown error'; }
  }
}

export function toError(e: unknown): Error {
  return e instanceof Error ? e : new Error(errorMessage(e), { cause: e }); // cause 需要 lib es2022 及以上
}
```

用法：`catch (e) { log(errorMessage(e)) }`，Promise 的写法是 `.catch((e: unknown) => …)`。注意 Promise `.catch` 回调的参数类型永远是 `any`，下面的 lint 规则能管住它。

### 5. 让编译器和 lint 防止旧写法再出现

- **tsconfig**：`"strict": true`。它包含 `useUnknownInCatchVariables`，开了以后 `err.message` 会直接编译报错。
- **typescript-eslint（需要带类型信息的 lint）**：
  - `no-unsafe-type-assertion`：拦截 `JSON.parse(x) as User` 这种从 `any` 断言的写法。
  - `no-unsafe-assignment`、`no-unsafe-member-access`、`no-unsafe-argument`、`no-unsafe-return`。
  - `use-unknown-in-catch-callback-variable`。
- **可选**：用 `@total-typescript/ts-reset` 把 `JSON.parse` 和 `Response.json()` 的返回类型全局改成 `unknown`。
- **找出现有写法**：
