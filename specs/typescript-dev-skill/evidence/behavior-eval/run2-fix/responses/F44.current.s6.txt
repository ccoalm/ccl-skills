## 一、为什么现在要整仓重检

通常是三种原因之一：
1. 只有一个 `tsconfig` 覆盖整个仓库，或者每个包各自跑 `tsc --noEmit` 但互相 import 源码，结果每个包都把依赖重新检查一遍。
2. 没开 `composite`，也没用 `tsc -b`，所以没有增量信息（`.tsbuildinfo`）。
3. 构建信息没在 CI 里缓存。

用 `tsc -b` 加项目引用之后：只有过期的项目会重建；如果一个包改了内部实现，但导出的 `.d.ts` 没变，依赖它的包会显示 up to date，直接跳过。

## 二、tsconfig 结构

```
tsconfig.base.json          # 共享选项，只此一份
tsconfig.json               # solution：files: []，引用所有叶子项目
packages/core/tsconfig.json
packages/core/tsconfig.test.json
packages/utils/tsconfig.json  …（其余同构）
```

**`tsconfig.base.json`**：6.0 改过默认值的选项全部显式写出来，不要依赖默认值。
```jsonc
{
  "compilerOptions": {
    "strict": true,
    "target": "es2022",              // 按最老的目标运行时定，不跟开发机走
    "lib": ["es2022"],               // 浏览器包在自己的配置里加 "dom"
    "module": "nodenext",            // Node 直接加载或要发布的包用这个；纯打包器的包在包内改成 esnext + bundler
    "moduleResolution": "nodenext",
    "types": [],                     // 6.0 起默认就是 []，各包自己列 node、测试框架等
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "noUncheckedSideEffectImports": true,
    "composite": true,               // 隐含 declaration；要求所有源文件都被 include 覆盖
    "declarationMap": true,
    "sourceMap": true,
    "skipLibCheck": true             // 如果有手写的 .d.ts，另起一个 skipLibCheck:false 的检查
  }
}
```
已经开着的 `noUncheckedIndexedAccess` 等选项照原样保留。不要在升级的同时收紧或放宽严格度。

**`packages/api/tsconfig.json`**（依赖 core 和 utils）：
```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "src",                // 6.0 起默认是 tsconfig 所在目录，显式写上才能保证 dist 布局不变
    "outDir": "dist",
    "tsBuildInfoFile": "dist/.tsbuildinfo",
    "types": ["node"]
  },
  "include": ["src"],
  "references": [{ "path": "../core" }, { "path": "../utils" }]
}
```

**`packages/api/tsconfig.test.json`**：测试和脚本也要进门禁。
```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": ".", "outDir": ".tsbuild/test",
    "emitDeclarationOnly": true,
    "types": ["node", "vitest/globals"]
  },
  "include": ["test", "scripts"],
  "references": [{ "path": "./tsconfig.json" }]
}
```

**根目录 `tsconfig.json`**（solution 配置）：
```jsonc
{
  "files": [],
  "references": [
    { "path": "packages/core" }, { "path": "packages/core/tsconfig.test.json" },
    { "path": "packages/utils" }, …
  ]
}
```

另外要定三件事：
- **包之间怎么互相消费**：两种方式选一种，全仓统一。
  - 构建优先：`exports` 指向 `dist`，`types` 写在每个条件对象的第一位。
  - 源码优先：自定义一个 export 条件（比如 `"@acme/source": "./src/index.ts"`），然后在 `customConditions`、打包器和测试运行器里都配上。

  两种混用的话，编辑器、CI 和运行时看到的类型会不一致。
- **路径别名**：不要靠 `paths` 跨包引用，而要用 `workspace:*` 依赖加 `exports`。包内别名用 `package.json#imports`（`#internal/*`）。`baseUrl` 在 6.0 已被弃用。
- **引用必须和包依赖方向一致**。如果出现循环引用，那是包边界的设计问题，不是配置问题。

**日常命令：**
```bash
tsc -b                          # 根目录增量构建，只重建过期的项目
tsc -b packages/api             # 只构建 api 和它的上游
pnpm --filter "...[origin/main]" run typecheck   # CI 里只跑受影响的包
```
CI 要缓存所有 `**/dist/.tsbuildinfo`、`.tsbuild/` 和 `dist`，缓存 key 用 lockfile 加 tsconfig 的哈希。

## 三、升级步骤：5.x → 6.0 → 7.0

TS 7.0 是用 Go 重写的原生编译器，**没有编程 API**。6.0 的弃用项到 7.0 都会变成硬错误，所以不能从 5.x 直接跳到 7。我凭知识判断 7.0 已经发布，但没有联网核实。开工前先跑 `npm view typescript dist-tags`，再读一下 6.0 和 7.0 的官方 release notes。

**第 0 步：盘点和基线**（还在 5.x 上）
```bash
pnpm -r exec tsc -v ; pnpm why -r typescript
```
- 列出所有调用编译器 API 的工具：typescript-eslint、`vue-tsc`、ts-jest、api-extractor、tsup/rollup-dts、ts-node、typedoc、编辑器插件。
- 在 `pnpm-workspace.yaml` 里用 `catalog:` 把 `typescript` 锁成一个版本，各包写 `"typescript": "catalog:"`。
- 记录基线：错误数（必须是 0）、`tsc -b` 冷启动和热启动的耗时，再把所有 `dist/**/*.d.ts` 复制一份到 `/tmp/dts-before`。

**第 1 步：在 5.x 上落地第二节的结构**（单独提交）
- 把 `moduleResolution: node/node10` 改成 `nodenext` 或 `bundler`，去掉 `baseUrl`。
- 把 6.0 改了默认值的选项都显式写出：`strict`、`module`、`target`、`types`、`rootDir`、`noUncheckedSideEffectImports`。
- 验证：`.d.ts` 和基线没有差异，测试全绿。

**第 2 步：升到 6.0**（单独提交）
- 把 catalog 改成 `^6`，执行 `pnpm install`，然后 `tsc -b`。
- 每个新报错要么修好，要么用 `// @ts-expect-error <原因>` 压住；不要加 `@ts-ignore`，也不要放宽 `strict`。
- `ignoreDeprecations: "6.0"` 只能当临时过渡，进 7.0 之前必须删掉。
- 先查 typescript-eslint 官方支持的 TS 版本范围，再升级它。

**第 3 步：升到 7.0**（单独提交，前提是 6.0 上零错误、零 `ignoreDeprecations`）
- `tsc`（包括 `-b` 构建模式）换成 7.0。先确认你用到的 `--build` 和增量功能 7.0 都支持。
- 需要编译器 API 的工具，按官方文档改用 `@typescript/typescript6`，它提供 6.0 的 API 和 `tsc6` 命令。用 pnpm 的 `overrides` 或 `packageExtensions` 把这些工具的 `typescript` peer 指过去。具体写法以官方说明为准，这里不编造。这个两版本并存的安排要写进仓库文档。
- 某个工具暂时不兼容的话，就让它留在 6.0 API 上，**不要因此回退整个仓库**。

## 四、验证（每一步都要跑完）

```bash

diff -r /tmp/dts-before <新的 d.ts>      # 对外类型没有意外变化
```

**增量效果要实际证明，光看配置不算数：**
1. 再跑一次 `tsc -b --verbose`，应该全部是 "up to date"。
2. 只改 `core` 的内部实现，再跑一次：只有 core 重建，依赖它的包都跳过。
3. 改 `core` 的导出类型：core 和下游重建，不相关的包跳过。
4. 对比冷启动和热启动的耗时。
