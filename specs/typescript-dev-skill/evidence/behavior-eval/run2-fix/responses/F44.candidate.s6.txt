## 一、tsconfig 结构

```
tsconfig.base.json        # 共享选项，只此一份
tsconfig.json             # solution：files: []，引用所有叶子项目
packages/a/tsconfig.json        # src，composite
packages/a/tsconfig.test.json   # 测试，引用 ./tsconfig.json
...（b–e 同构）
```

**`tsconfig.base.json`**：显式写出 6.0 会改默认值的那几项，避免升级时行为悄悄变化。下面的取值只是示意，实际照抄你现在的配置。

```jsonc
{
  "compilerOptions": {
    "composite": true,
    "declaration": true,
    "declarationMap": true,
    "strict": true,
    "target": "es2022",
    "lib": ["es2022"],
    "module": "nodenext",            // 包由 Node 直接加载或会发布时用；纯打包场景用 esnext + bundler
    "moduleResolution": "nodenext",
    "types": [],                     // 6.0 默认就是 []，每个项目自己声明用到的全局类型
    "noUncheckedSideEffectImports": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "skipLibCheck": true             // 只为跳过第三方 .d.ts；手写的 .d.ts 要另外用 false 检查
  }
}
```

**`packages/b/tsconfig.json`**（假设 b 依赖 a）

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": { "rootDir": "src", "outDir": "dist", "types": ["node"] },
  "include": ["src"],
  "references": [{ "path": "../a" }]
}
```

**`packages/b/tsconfig.test.json`**：测试代码也要被类型检查，但不能输出到 `dist`。

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": ".", "emitDeclarationOnly": true,
    "outDir": "../../.tsbuild/b-test",          // 这个目录加进 .gitignore
    "types": ["node", "vitest/globals"]
  },
  "include": ["test"],
  "references": [{ "path": "./tsconfig.json" }]
}
```

**根目录 `tsconfig.json`**

```jsonc
{ "files": [], "references": [
  { "path": "packages/a" }, { "path": "packages/a/tsconfig.test.json" },
  { "path": "packages/b" }, { "path": "packages/b/tsconfig.test.json" }
  // …c/d/e 同样写上
]}
```

**包之间怎么引用（建议先构建再引用）**：`exports` 指向构建产物，并把 `types` 条件放在第一位：

```jsonc
"exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } },
"dependencies": { "@scope/a": "workspace:*" }
```

另一种做法是用 `customConditions` 直接引用源码，但打包工具和测试运行器也要认同一个 condition。两种做法只能选一种，混用会导致编辑器、CI 和运行时看到的类型不一致。另外，`references` 的依赖方向必须和包之间的架构依赖一致，出现循环引用说明设计有问题，不能靠改配置解决。

**加一个一致性门禁**：防止 `references` 和依赖声明对不上。根目录 `tsconfig.json` 应引用全部项目，这一点也要在 CI 里一并核对。

```js
// scripts/check-refs.mjs（在 CI 里运行）
import { readFileSync, readdirSync } from 'node:fs';
const pkgs = readdirSync('packages');
const nameToDir = Object.fromEntries(pkgs.map(d => [JSON.parse(readFileSync(`packages/${d}/package.json`)).name, d]));
let bad = 0;
for (const d of pkgs) {
  const pj = JSON.parse(readFileSync(`packages/${d}/package.json`));
  const deps = Object.keys({ ...pj.dependencies, ...pj.devDependencies, ...pj.peerDependencies }).filter(n => n in nameToDir).map(n => nameToDir[n]).sort();
  const tc = JSON.parse(readFileSync(`packages/${d}/tsconfig.json`)); // 带注释的 tsconfig 需要换成 jsonc 解析器
  const refs = (tc.references ?? []).map(r => r.path.replace('../', '')).sort();
  if (deps.join() !== refs.join()) { console.error(`${d}: deps=${deps} refs=${refs}`); bad = 1; }
}
process.exit(bad);
```

**日常命令**

- `tsc -b`：全仓检查，只重建过期项目。
- `tsc -b packages/b`：检查 b 和它的上游。
- 改了 a 之后要检查下游：根目录跑 `tsc -b` 就够了，未受影响的项目会直接跳过。
- CI 里缓存 `**/*.tsbuildinfo`、`dist` 和 `.tsbuild`。

**第 0 步：盘点**

- 记录 5.x 的基线：`tsc -b --extendedDiagnostics` 的错误清单和耗时，另外备份一份现有的 `dist/**/*.d.ts`。

**第 1 步：在 5.x 上改 references（单独一个 PR）**

- 按第一节调整结构。
- 原来的 `moduleResolution: node` 改成 `nodenext` 或 `bundler`。
- `baseUrl` 改成在每个 `paths` 条目里写全前缀，或者直接改用 `package.json#imports`。
- 验收标准：错误集合和基线一致，运行时测试通过。

**第 2 步：升到 6.0**

- 按 6.0 release notes 检查改了默认值的选项：`strict`、`module`、`target`、`types`、`rootDir`、`noUncheckedSideEffectImports`。第一步已经都显式写出来了，所以这里不应该有行为漂移。
- 新出现的源码错误优先修掉。暂时修不了的，用 `// @ts-expect-error <原因>` 压住，不要用 `@ts-ignore`。
- 弃用项报错（TS5101、TS5107）出现在 tsconfig 上，只能用 `"ignoreDeprecations": "6.0"` 临时压住，而且这一步结束前必须删掉。

**第 3 步：确认可以进入 7.0**

- 在 6.0 上编译完全干净，没有 `ignoreDeprecations`。
- 每个依赖 API 的工具都确认过兼容情况。例如 typescript-eslint 的类型检查规则依赖编译器 API，7.0 不提供，只能继续走 6.0 API。TypeScript 团队提供了 `@typescript/typescript6` 包（内含 `tsc6` 和 6.0 API），可以和 7.0 并存。具体的别名写法和包名要按官方 release notes 来，不要自己猜。
- 这种两个版本并存的情况要写进仓库文档，说明是刻意为之。

**第 4 步：升到 7.0**

- 安装 7.0，用 `tsc -b` 跑一遍，确认 build 模式和 references 的行为和 6.0 一致。
- 之后的后续 PR：逐个删掉 `@ts-expect-error`，并删掉不再需要的 6.0 并存配置。
