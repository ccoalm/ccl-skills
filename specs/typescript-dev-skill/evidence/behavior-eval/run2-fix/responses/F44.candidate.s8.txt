## 0. 先摸清现状（每次改动都整仓重查，通常就是这里的原因）

```bash
pnpm why typescript -r        # 应该只有一个 typescript 版本
npx tsc -v
grep -rn '"paths"\|"baseUrl"\|"references"\|"composite"' --include='tsconfig*.json' .
```

整仓重查最常见的三个原因：
- 用 `paths` 把别的包直接指向它的 `src/`。这样每个包都会把下游源码重新编译一遍。
- 只有一个根 `tsconfig`，`include` 覆盖了 `packages/**`。
- 用了 `tsc --noEmit -p`，没用 `tsc -b`。

还要列出所有调用编译器 API 的工具：typescript-eslint、vue-tsc、ts-jest、tsup 或 rollup 的 dts 插件、api-extractor、ts-node 等。升级时它们是主要风险。

## 1. tsconfig 结构（project references）

```
tsconfig.base.json          # 共享选项，只写一份
tsconfig.json               # solution：files: []，引用所有项目
packages/shared/tsconfig.json
packages/shared/tsconfig.test.json
packages/core/tsconfig.json  → references: shared
packages/api/tsconfig.json   → references: core, shared
...
```

依赖方向要和架构上的分层一致，不能有循环。如果出现循环引用，要改设计，不能靠配置绕过去。

**tsconfig.base.json**：把 6.0 改了默认值的选项都显式写出来。

```jsonc
{
  "compilerOptions": {
    "strict": true,                 // 现在是 false 的话先显式写 false，开 strict 另做一次迁移
    "target": "es2022",             // 按要支持的最老运行时来定
    "lib": ["es2022"],
    "module": "nodenext",           // Node 直接加载或要发布的包用这个；前端打包的包在包内覆盖
    "moduleResolution": "nodenext",
    "types": [],                    // 6.0 默认就是 []，每个包要自己列出 node、测试框架的全局类型
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "composite": true,              // 会隐含 declaration 和 incremental
    "declarationMap": true,         // 编辑器里跳转定义能直接到源码
    "sourceMap": true,
    "skipLibCheck": true
  }
}
```

**packages/core/tsconfig.json**：`rootDir` 和 `outDir` 必须在每个包里写。base 里的相对路径是相对 base 文件本身解析的。

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": { "rootDir": "src", "outDir": "dist", "types": ["node"] },
  "include": ["src"],
  "exclude": ["src/**/*.test.ts"],
  "references": [{ "path": "../shared" }]
}
```

**packages/core/tsconfig.test.json**：测试也要纳入类型检查，不能只查 `src`。

```jsonc
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": { "rootDir": ".", "outDir": ".tsbuild/test", "emitDeclarationOnly": true,
                       "types": ["node", "vitest/globals"] },
  "include": ["src/**/*.test.ts", "test"],
  "references": [{ "path": "./tsconfig.json" }]
}
```

**根目录 tsconfig.json**：

```jsonc
{ "files": [], "references": [
  { "path": "packages/shared" }, { "path": "packages/shared/tsconfig.test.json" },
  { "path": "packages/core" },   { "path": "packages/core/tsconfig.test.json" }
  // ...其余包同样写
]}
```

**包之间怎么互相引用**：
- `package.json` 里写 `"@scope/shared": "workspace:*"`。
- `exports` 指向编译产物，`types` 放在条件对象的第一个，否则 TypeScript 读不到：`{".": {"types": "./dist/index.d.ts", "default": "./dist/index.js"}}`。
- 删掉指向兄弟包 `src` 的 `paths`。
- 我推荐"先构建再引用"，也就是引用对方的 `dist`。如果改成直接引用源码（用 `customConditions`），打包工具和测试运行器也得认同一个条件。两种方式不能混用，混用的话编辑器、CI 和运行时看到的类型会不一样。
- 由打包工具加载的前端包，在包内覆盖成 `"module": "esnext", "moduleResolution": "bundler"`，并加上 `"lib": [..., "dom"]`。

**脚本**：
- 全量检查：`"typecheck": "tsc -b"`
- 监听：`"typecheck:watch": "tsc -b -w"`
- 只查一个包：`tsc -b packages/core`。它只会检查 core 和 core 依赖的上游包。

改好之后：
- 改了一个包，只有它自己，以及依赖它、而且它的 `.d.ts` 确实变了的下游包会重查。
- 只改实现、不改导出类型时，下游会被跳过。

## 2. 升级步骤：5.x → 6.0 → 7.0，不要跳过 6.0

先用 `pnpm view typescript dist-tags` 确认最新版本。我没有在线核实过。下面的行为来自 TypeScript 6.0 和 7.0 的官方发布公告：7.0 是用 Go 写的原生编译器，会把 6.0 里废弃的选项直接变成报错，而且不提供编译器 API。

1. **先做结构改造，再单独升级。** 第 1 步的 references 改造在 5.x 上做完、验证通过，作为一个独立 PR。升级是另一个 PR，也不要夹带无关的类型重构。
2. **升到 6.0。** 只在根目录的 devDependencies 里装 `typescript@6`，或者用 pnpm catalog 统一版本，保证整个仓库只有一个版本。然后跑 `tsc -b`。
3. **处理 6.0 的报错：**
   - 6.0 改默认值的选项（`strict`、`module`、`target`、`types`、`rootDir`、`noUncheckedSideEffectImports`）已经在 base 里显式写了，行为不会悄悄变化。
   - 去掉 `baseUrl`，把前缀写进每一条 `paths`；最好改用 `package.json#imports`。
   - `moduleResolution: node`/`node10` 按包的运行环境改成 `nodenext` 或 `bundler`。
   - 源码里的新报错要么修掉，要么加 `// @ts-expect-error <原因>`。
   - 废弃选项的报错（TS5101、TS5107）出现在 tsconfig 上，只能用 `"ignoreDeprecations": "6.0"` 临时压掉。这个设置必须在升 7.0 之前删除。
4. **在 6.0 上跑干净，作为一个稳定的落脚点。** 要求零报错，并且没有 `ignoreDeprecations`。如果 typescript-eslint 等工具还不支持 7.0，就先停在 6.0，这是完全可以接受的。
5. **升到 7.0：**
   - 类型检查的关卡改用 7.0 的 `tsc`。
   - 需要编译器 API 的工具（比如 typescript-eslint）要单独接到 `@typescript/typescript6` 提供的 6.0 API 上，具体接法以官方公告为准。在 pnpm 里通常要用 `overrides` 或 `packageExtensions` 让这些工具解析到 6.0 的 API。
   - 两个版本同时存在要是有意为之，并在 README 或 AGENTS.md 里写明。
   - 每个工具都要检查一遍再切换，不能只改版本号。
6. **清理：** 删掉第 3 步临时加的 `@ts-expect-error`，或者把它们修掉。
