# Conditional execution-card reference loading

Ordinary documentation work loads the complete tighten-doc entry, including detailed rules that apply only to execution/domain cards. Move those details to a required conditional reference so the entry carries less task-specific input.

## Scope

- Keep the entry section and require the reference before generating, modifying or reviewing an execution/domain card.
- Relocate the card skeleton and four card-specific editing rules verbatim.
- Keep the global batch-strip/retitle guard, applicability exclusions and the premise-rejection flow in the entry.
- Leave routing, permissions, reviews and task verification unchanged.

## Acceptance

- Every relocated paragraph matches the baseline text.
- Every entry byte outside the replaced block is unchanged.
- The reference pointer resolves, and entry size decreases.
- The preservation map names the old and new governing chain for every relocated obligation.
- Repository validation, independent review and challenge cover the exact candidate.

## Validation

Run the byte-preservation comparison against origin/main, the normal repository lane, the heavy regression lane and public sanitization. Check internal and incoming pointers. Review the conditional loading predicate and preserved batch-edit, scope and premise guards. A negative control must reject hiding the global batch-edit guard behind the card-only reference condition.

This change proves only the smaller entry and the stated preservation properties. It does not establish better task completion, elapsed time or overall delivery quality.
