# 042 — 技能语料优化

Status: **执行中**。本轮不自判通过。

## 1. 目标与判据

**产品目标**：技能集保持有用，且不被自己的规则拖垮。

039 量出的病：`skills/` 增删比 12.9:1，两个流程包占全仓 40.5%，29 轮里 22 轮的交付物是流程或工具自身。**从 039 钉点到本轮开轮，`skills/` 是 +1489 / −53（28:1）——收缩 program 跑了三轮，窗口内增长比开轮诊断还快一倍。**

**本轮判据（可证伪）**：每一批产出**至少一处对语料的实际改动**（合并、删除、移位），且每处改动附一条能红的验证。产不出改动就如实报「该杠杆在本仓无收益」——那也是结论。

**明确不做**：不再给「一条规则该不该退役」造裁定装置。三轮的教训是那条路在盘问存量，不在测量效果。

## 2. 证据基础（外部一手源，已核）

三条机制，各有各的解法。**不是**「只有最显著的一条规则起作用」——那条已在 `skill-extraction-workflow` 就地撤回，两家官方指南都无此说法，且它推出的「追加不增加合规」被 OpenAI 直接否定。

| # | 机制 | 一手源 | 解法 |
| --- | --- | --- | --- |
| 1 | **冲突**：矛盾指令按位置解决，靠后者胜；行为不对时**第一步**就是查矛盾 | OpenAI GPT-4.1 / GPT-5.1 Prompting Guide | 找出并消除矛盾 |
| 2 | **体量**：每个 token 消耗有限的 attention budget；context rot 在所有模型上都存在，只是程度不同 | Anthropic, *Effective context engineering for AI agents* | 取 high-signal 的最小集，放在 right altitude——脆的硬编码 if-else 与空泛指导都是被点名的失效模式 |
| 3 | **位置**：首尾被读、中间丢失；长上下文里指令首尾各放一次最好 | OpenAI GPT-4.1 Prompting Guide | 关键规则放到触发点；埋在深层引用中段的规则结构上就不会触发 |

联合满足随约束数下降是独立于上述三条的事实：多约束基准上最好的模型「全部满足」不到一半（RECAST，Gemini-2.5-Pro 平均 HSR 39.75%）。它支撑的是「必须同时成立的要求不能靠共存散文承载」，仓库已有该条。

## 3. 三个杠杆与优先级

**杠杆 1 — 矛盾检测（本轮主线）**
两家官方都把它列为调试第一步；本仓 30+ 技能、186 条台账行、三轮累积纠正，**一次语义矛盾检查都没跑过**（`eval-routing` 查的是 trigger 碰撞，不是语义矛盾）。

它同时解掉 039 找了一轮没找到的退役判据：**「两条规则相互矛盾」是两条规则之间的关系——正面可判定，无全称否定，不需要 firing-path 词汇表，也不需要终态本体论。** 矛盾一旦坐实，处置只有合并或删其一。

**杠杆 2 — 体量。** 119KB 的常驻入口直接违反「smallest possible set of high-signal tokens」。`right altitude` 给出砍什么的判据。现有 `check-size-budget.sh` 只拦增长、不驱动缩减，这块是空的。

**杠杆 3 — 位置。** 已半采纳（firing-path proof 的 reachable surface），补齐成本低，排最后。

**双臂探针（`eval/body-compliance-eval.rb --arm`）降为验证仪器**：用来确认某次合并或删除之后行为没退化，不用来逐条盘问规则。

## 4. 分批

### 批 1 — 矛盾检测可行性切片（当前）

- **范围**：`skill-extraction-workflow`（119KB，规则最多、纠正最多）的 `## Core Rules` 全部分组，逐组内扫 + 跨组扫已知复现主题。
- **方法**：按组切片喂给独立通道，要求产出**候选矛盾对**：两处原文跨度 + 冲突点 + 按位置规则谁会胜出。起草方不自判，逐对裁定「真矛盾 / 作用域不同的表面冲突」。
- **验收**：产出 ≥1 对**经裁定的真矛盾**，并落地其处置（合并或删其一）。零真矛盾也是结论，如实报，并据此下调杠杆 1 的优先级。
- **停止线**：候选对里超过一半是「作用域不同」的误报 → 方法本身不合格，先修方法再继续，不硬凑。

### 批 2 — 体量（批 1 之后）
以 `right altitude` 为判据在最大入口上找「脆的硬编码 if-else 式规定」，按批 1 的同一形态处置。范围与规模在批 1 收尾时定，不预设。

### 批 3 — 位置（最后）
把埋在深层引用中段、但被声明为承重的规则挪到触发点。

## 6. 撤回的范围与理由

判据终态集合重设、`休眠` 的 `delete` 裁决、v4 决策表——**整体撤回**。

两条理由，一条内生一条外来：

1. 独立评审 R1-2 指出并经核验：041 登记的四条缺陷里，#1 是 v1/v2 已抛弃的形态、#4 是 041 自选的方法、#2 的登记说法本轮已自行证否——**没有一条被证明是 v3 `休眠` 的活缺陷**，`delete` 的证据基础不成立。
2. 更根本：判据重设优化的是**代理量**。「台账行有没有 firing point」是作者写入时记的来路声明，不是效果的证据；机械化它得到的数与产品关心的东西不相关。

原判据文本与四条 P1 的逐条处置保留在 `dispositions.md`，作为该形态为何被撤回的记录。
