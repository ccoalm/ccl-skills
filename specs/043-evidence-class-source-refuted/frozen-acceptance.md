# 043 冻结判据 —— 先于任何一次闸改动

**本文件在 `impact-chain-gate.rb` 被触碰之前提交，顺序由 git 历史可核。**

## 为什么要先冻

本轮的起因是 042 被 `impact_chain_behavior_evidence_missing` 挡住。如果由"想让 042 过"的一方来定这一轮的成败，那这就是一次**为放行特定改动而做的闸变更**——042 轮已经实测过：作者对自己改动的判断系统性偏向让它落地（marker 偏向新文本、阈值在不利结果后被调、隔离闸被用出同义反复）。

所以：**判据在动闸之前冻结，且用合成用例表述，不用 042 的 diff。042 能不能过是事后的观察结果，不是本轮的目标。**

## 问题

证据分类里没有「一条规则触发正常、但内容为假」这一类。

| 主张类型 | 恰当证据 | 现有分类 |
| --- | --- | --- |
| 行为/路由变更 | `RED-baseline`（施加突变、观察转红） | 有 |
| 义务不变的改写 | `semantic-control` | 有 |
| **一条陈述被一手源否证，须撤回** | **一手源否证 + 零损失义务保全** | **无** |

现状后果：一次事实更正只能硬套 `RED-baseline`（造不出来，因为删掉假陈述往往无可测行为差异）或误标 `semantic-control`（会被 owner 级 RED 底线拦下）。于是**假陈述留在技能里比删掉它更容易**。

## 拟加的类：`source-refuted`

**不是豁免，是换一种证据。** 声明该类的行必须同时满足：

1. `observed-failure: no` —— 这条闸问的是规则有没有失灵；被撤回的陈述**触发正常**，它只是假的。
2. 证据列含**至少一个外部一手源引用**（URL），即否证该陈述的出处。
3. 证据列含一个**零损失义务对照**的可解析指针（文件路径 + 锚），且该目标非空。
4. 该 owner 包在本轮的**规范面净变化 ≤ 0 字节**。撤回一句假陈述会让包缩小；这条挡住"借事实更正之名夹带新规则"。

第 4 条是**机械下限，不是证明**：净删除仍可能在别处夹带，那由 dual-track 的零损失审查兜。本轮不假装机械检查能替代它。

## 冻结的验收用例（合成，全部确定性、不调模型）

| # | 用例 | 无新类时 | 有新类时 | 这条在防什么 |
| --- | --- | --- | --- | --- |
| **A** | 撤回一句陈述的 diff + 合规 `source-refuted` 行（源 URL、零损失指针、净字节 < 0） | **红** | **绿** | 类确实解决了那个问题 |
| **B** | **真的行为变更**（新增一条规范规则）披 `source-refuted` 标签 | 红 | **仍红** | 类不能变成万能豁免 |
| **C** | `source-refuted` 行**缺源 URL** | 红 | **仍红** | 证据要求是实的 |
| **D** | `source-refuted` 行**缺零损失指针**或指针目标为空 | 红 | **仍红** | 义务保全要求是实的 |
| **E** | `source-refuted` 行标了 `observed-failure: yes` | 红 | **仍红** | 分类语义不得自选 |
| **F** | 既有的 `RED-baseline` / `semantic-control` / 两个 `not-required` 类的现有行为 | 绿/红按现状 | **完全不变** | 不得回归 |

**通过条件 = 六条全中。** 任何一条不符即本轮未完成，不得以"主要目标达成"结案。

## 明确不作为判据的东西

- **042 的 diff 能否通过**。它不在测试集里；本轮跑完之后如实观察并记录，但它不是成败依据。
- 净字节数、改了多少行、跑了几轮。

## 停止线

- 若为让用例 A 变绿而需要放宽 B–F 中任何一条，**停止并交裁决**：那说明这个类的形状不对，不是门槛该松。
- 若实现后发现第 4 条（净变化 ≤ 0）会误伤正当的事实更正（例如撤回时必须补一句说明它为何被撤回，导致净增），**停止并交裁决**，不得自行改判据——这正是 042 轮"阈值在不利结果后被调"的形态。

## 独立评审两条 P1 之后的收紧

dual-track 指出四道门槛逐条都廉价可满足，该类当时**就是一条通用豁免路径**：

| 发现 | 攻击形态 | 处置 |
| --- | --- | --- |
| REVIEW-1 | 同 owner 一条合规撤回 + 一条真行为变更的 `semantic-control` 行；`any?` 顶起底线，行为变更搭便车 | 底线放行改为**整包性质**：该 owner 的全部非 no-behavior 行都须是该类 |
| CHALLENGE-1 | 删无关文字凑净负、加一条新规范规则、引任意 URL、指针写 `README.md#不存在的锚`（原实现只检文件存在非空） | ① 第四道门槛由「净字节 ≤ 0」换成**本轮不得新增任何规范规则行**（复用闸判锚点的同一谓词）；② 零损失指针的**锚点必须解析得到** |

连带后果（如实记）：撤回因此必须是**纯删除**，说明文字进 reference——原用例 A 的"改写式撤回"被新门槛正确拒绝，fixture 已按新形态改为纯删除；纯删除无可锚定的新增行，故该类与两个 `not-required` 类一致**免 firing-path**。

## 第二轮 dual-track 的两条 P1（同一发现，两个通道各自到达）

两轮都指出第四道门槛仍是**代理**：「不得新增规范规则行」看不见脚本改动、非列表格式的行为指令、以及以 `Always` 开头的规则（那个谓词故意排除 always）。零删除也能过。

处置：把该门槛换成**结构化的纯删除判据**——每个变更路径都是该 owner 下的常规 `.md`、状态都是修改（无新增/删除/改名/复制/改权限）、全 diff 新增行数为 0 且删除行数 > 0。不再依赖任何措辞启发式。

新增回归 I（脚本改动零删除）、J（`Always` 规则零删除）。至此十条，**原六条期望值自始未变**。

**这是本轮第三次同一形状**：谓词是代理不是不变量。而"纯删除"本来就有精确定义，前两版却都用启发式去近似它。

# 裁决：拿掉自动放行（收敛式删除）

冻结判据的核心期望是"合规撤回应转绿"。**七轮独立评审后该期望被用户裁定撤回。**

停止线原文写着：若发现该类的形状不对，停下交裁决、不得自行改判据。这条在第七轮触发——不是某一道门槛没写对，是**保护"自动清掉 RED 底线"这个能力的门槛被连续七次击穿**：

| 版本 | 门槛 | 被什么击穿 |
| --- | --- | --- |
| 1 | 净字节 ≤ 0 | 无关删除抵消新增规则 |
| 2 | 不得新增规范规则行 | 脚本改动、`Always` 规则、零删除 |
| 3 | `--name-status` 全为 M | `chmod` 记 0/0 |
| 4 | 文件存在且非空 | `../..` 穿越、逃逸符号链接、无界读 |
| 5 | `body.include?(anchor)` | `README.md#a` |
| 6 | 以上全部 | 指针形式合规、与被删内容无关 |
| 7 | 逐字交代被删内容 | 未经评审 |

两条独立通道**两次**给出同一建议：在指针能被绑到被撤回的义务之前，不要让它顶起底线。按本仓「同类跨轮复现是设计信号不是补丁信号」，删掉的是**那个能力**，不是再补第八道门槛。

**剩余缺口本质不可机械验证**：指针可以指向真实标题、逐字抄录被删文本，而"这个一手源确实否证了那条陈述"只有人能判。

## 裁决后的形态

- 七道门槛保留——它们让标签诚实、强制产出零损失义务对照、并把诊断指向正确补法。
- **该类不再顶起 RED 底线。** 撤回仍需一条 `RED-baseline` 行，或由具名风险 owner 经既有人工通道放行。
- 用例 A 的期望由绿改红，其余十五条期望值未变。

## 对 042 的后果

042 仍被挡着，由人裁决——回到开 043 之前的位置，但现在有七轮证据支撑，不是猜测。
