# 会议室预约 技术设计

## 领域模型与不变量

1. 同一会议室无重叠占用：同一会议室内，待确认和已确认的预约在时间上不得重叠，两个请求同时到达时也必须成立。保证方式：创建预约时在事务内锁住该会议室行，查询重叠后再插入；并发测试 concurrent_overlapping_bookings_one_wins 断言只有一个成功。
2. 状态迁移受限：预约状态只能从待确认到已确认、已取消或已失效，以及从已确认到已取消；已取消和已失效是终态，不能再变为已确认或重新生效。保证方式：迁移表写在领域层，状态更新使用带原状态条件的 UPDATE，影响行数为 0 即拒绝；单测 illegal_transitions_are_rejected 逐条覆盖。
3. 待确认超时释放：待确认的预约 10 分钟内未确认就不再占用时间段，过期之后到达的确认必须被拒绝。保证方式：确认时校验 expires_at 大于当前时间，重叠查询排除已过期的待确认记录；单测 confirm_after_expiry_is_rejected。
4. 提醒至多一次：提醒触发器重复触发时，一个预约的提醒也至多送达一次。保证方式：reminders 表以 booking_id 为唯一键，插入成功才发送。
5. 停用会议室不可预约：会议室处于停用状态时不能创建新的预约。保证方式：在第 1 条的同一把行锁内校验会议室状态；单测 booking_rejected_when_room_disabled。

## 分层与依赖方向

handler 调 service，service 调 domain；dal 实现 domain 里定义的仓储接口。依赖只朝里指：domain 包不 import gorm 或 HTTP 框架。

## 运行时

- 调用提醒服务的每个请求都带截止时间：context.Context 从入口传到提醒客户端，超时 2 秒。
- 数据库访问全部放在 dal 仓储之后；handler 不自己创建数据库或提醒客户端，依赖在启动时注入。
