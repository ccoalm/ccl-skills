# 订单部分退款 技术设计

## 业务规则

- 同一订单，处理中和已成功的退款金额之和不得超过实付金额，并发申请时也必须成立。
- 客户端重试和渠道重复回调都不允许产生或入账第二笔退款，一次申请至多对应一笔退款。
- 退款进入成功或失败之后不再变化，晚到或乱序的回调必须被忽略。
- 订单已关闭时必须拒绝创建退款。

以上规则的具体实现方式留到开发阶段确定。

## 分层与依赖方向

handler 调 service，service 调 domain；dal 实现 domain 里定义的仓储接口。依赖只朝里指：domain 包不 import gorm、HTTP 框架或渠道 SDK。

## 运行时

- 调用支付渠道的每个请求都带截止时间：入口的 context.Context 一路传到渠道客户端，超时 3 秒。
- 数据库访问全部放在 dal 仓储之后；handler 不自己创建数据库或渠道客户端，依赖在启动时注入。
- 账务通知走 outbox 表加后台投递，账务不可用时重试。
